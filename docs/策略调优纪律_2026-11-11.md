# 策略调优纪律（2026-11-11，v1）

本文件规定「改哪个参数、怎么判有效、什么算噪声」。配套工具 `tools/tune_advice.py`，
配套基线快照 `docs/策略参数基线_2026-11-11.json`。

本轮只搭评测架子并冻结基线：**不改任何权重取值、不引入新因子、不扩数据区间、
不动 `data/`、不改 `run_backtest.py`**。权重调整要等两份基线报告（推荐链路胜率
检验、beta/alpha 三层分解）出来之后再做。

## 1. 冻结口径（v1，不允许每次评测改动）

| 项 | 值 |
|---|---|
| 主评测段（OOS） | 2022-01-01 ~ 2026-10-31 |
| 参数选择段（IS） | 2015-01-05 ~ 2021-12-31，只允许在这里看结果做选择 |
| 主持有期 | **60 个交易日**；5 / 20 日仅作对照 |
| 调仓 | 每 `hold` 个交易日一期，非重叠，逐期复利 |
| 成交 | T 日收盘打分 → T+1 开盘等权买入 Top-15 → T+1+hold 开盘卖出；候选不足 15 只时剩余留现金 |
| 不可成交 | 涨停/停牌跳过且不顺延，计入 `skipped_untradable` |
| 成本 | **0.724%/期往返**（佣金 5bp×2 + 印花税 5bp + 过户费 0.2bp×2 + 市值分档滑点），按本期实际换手比例摊销：满仓全额换手 = 0.724%，半仓 ≈ 0.362%，无持仓期不计 |
| 打分 | 各档 zscore 加权（config 权重×方向），缺失按剩余权重归一，不填 0 |
| 选股门槛 | `score_percentile ≥ 档位 buy_percentile`、`amount_ma20 ≥ 档位 min_amount`、`volatility_20 ≤ max_volatility`、`atr_pct ≤ max_atr_pct`、`raw_close ≥ min_price`、`soft_pass` 为真 |
| 股票池 | 全市场分层抽样 800 只（seed 20261111，按成交额十分位等比例），剔除上市不满 250 日；池源 `list_local_stock_codes` 已排除状态表登记的 236 只停更/退市标的，v1 存在幸存者偏差，对基线与候选同等生效 |
| 风险过滤 | v1 不含 ST/事件过滤，对基线与候选同等生效，不引入相对偏差，绝对数值偏乐观 |

口径写在 `tools/tune_advice.py::PROTOCOL`，每次运行会完整打印并写入结果 JSON。
**改口径 = 改结论含义**，必须同时升 `PROTOCOL['version']`、重跑基线、在
`reports/strategy_tuning/experiments.csv` 留一行，否则任何对比都不可用。

walk-forward 的定义：参数在一轮内固定（不在 OOS 内重新拟合）；每期只用 T 日及以前
的行情打分，T+1 开盘执行，期与期不重叠。因此 OOS 段每一期都是样本外前推，
不存在「用未来数据选股」；但**参数选择过程**本身仍可能泄露未来信息，见第 4 节。

指标定义：净年化（扣成本复利）、期胜率（净收益 > 0 的期占比）、年化单边换手
（`Σ(上期持仓数+本期持仓数)/(2×TopK) ÷ 年数`，按实际成交比例，不满仓不计满额换手）、
最大回撤（逐日收盘净值）。

## 2. 一次只动少量参数

- 单次试验最多改 **1 个参数组、≤3 个数值**；改 4 个以上就分多次跑，否则无法归因。
- 不同时改「因子权重 + 门禁阈值 + 冷却天数」，这三类互相影响，混在一起改等于重新设计。
- 每次改动必须能用 `--set` 精确表达，记账表里能还原出「从什么值到什么值」。
- 参数微调（如 `0.90 → 0.91`）与结构性改动（新增/删除因子）分开记，后者的试验次数
  单独再算一轮，不能沿用旧累计次数。

## 3. 试验次数会抬高显著性门槛

每次评测都追加一行到 `reports/strategy_tuning/experiments.csv`，行号即累计尝试次数 N。

- 显著性门槛按 Bonferroni 校正：`α* = 0.05 / N`；N=10 时单个试验要求 p<0.005。
- 期间收益 t 值 `t = mean(Δ期净收益) / (std(Δ期净收益)/√n)` 必须超过
  `t_{1-α*/2, n-1}` 才算显著；n 为 OOS 期数（60 日口径约 19 期，20 日约 58 期，5 日约 230 期）。
- **试得越多，同样的 t 值越不可信**：N=50 时 t=2.0 已不显著，不得拿「t≈2」当证据。
- 累计次数只增不减；作废的试验也要留行并标注 `label`，不允许删行来「重置」门槛。
- 工具已把 `累计尝试次数` 与校正后 α 打印在结果里，报告里必须照抄这两个数。

## 4. 新参数必须在时间上真正没见过的段上复现

- 参数只能在 IS 段（2015-01-05~2021-12-31）上选择；选择过程看过的任何 OOS 结果，
  都要在记账表里写明，并把这部分 OOS 降级为「已污染」，不得再当样本外证据。
- 结论必须在 OOS 段（2022-01-01~2026-10-31）单独成立，且方向与 IS 同号。
- 还要在 OOS 内前后两个不重叠子段（2022-01~2024-06 / 2024-07~2026-10）都同号；
  只在其中一段成立，判定为「时段依赖」，不算复现。
- 不允许用「全样本最优」替代样本外结论；全样本最优只能当对照组，必须标注含未来信息。

## 5. 目标函数只能是扣成本净收益或胜率

- 唯一合法的目标函数：**扣成本后的净年化收益**、**扣成本后的期胜率**。
- 禁止用 IC、IR、RankIC、分层单调性、多空价差选参数：这些指标不含成本、不含
  涨跌停/停牌约束，与最终能否赚钱不是同一个量。它们只能用来解释「为什么」。
- 禁止用未扣成本收益（毛收益）选参数；毛收益只允许出现在成本敏感性分析里。
- 目标函数一经选定，同一轮调优内不得换成「更宽松的那个」来让结果变好看。

## 6. 什么情况下判定「这组参数只是噪声」

满足任意一条即判噪声，不得进入配置：

1. **不显著**：OOS 期净收益的 t 值低于第 3 节校正后的临界值。
2. **不可复现**：IS 与 OOS 方向相反，或 OOS 前后两个子段方向不一致。
3. **幅度小于口径噪声带**：Δ净年化 < 2 个期间标准误，或 Δ期胜率 < 3pp（19 期口径下
   1 期翻转 ≈ 5.3pp，3pp 已接近 1 期的量级）。
4. **只在成本假设下成立**：把成本上调 1.5 倍（1.086%/期）后 Δ 由正转负。
5. **靠换手堆出来的**：Δ净年化 > 0 但同时 Δ年化换手 > 30%，且毛收益改善小于成本增加。
6. **对 ±1 微调敏感**：相邻取值（如 0.90→0.91、0.89）使 Δ 符号翻转，说明是拟合噪声。
7. **样本不足**：OOS 完整期数 < 15（60 日口径不足约 4 年），直接判「样本不足」，不判有效。

噪声判定的记录方式：在记账表 `label` 里写 `noise: <触发的条款>`，参数不落到
`src/advice/config.py`。

## 7. 一次完整的调优流程

```powershell
# 0. 冻结/刷新基线快照（只在 config.py 有意变更后做）
.venv\Scripts\python.exe tools\tune_advice.py baseline

# 1. 基线自评（写入第 1 行记账）
.venv\Scripts\python.exe tools\tune_advice.py evaluate --label baseline_v1 --segment oos

# 2. 候选参数：IS 段选择，只改少量参数
.venv\Scripts\python.exe tools\tune_advice.py evaluate --segment is `
  --label "is: long.buy_percentile 0.88->0.90" `
  --set tiers.long.buy_percentile=0.90

# 3. 样本外复现（同一条命令换 oos）
.venv\Scripts\python.exe tools\tune_advice.py evaluate --segment oos `
  --label "oos: long.buy_percentile 0.88->0.90" `
  --set tiers.long.buy_percentile=0.90

# 4. 查累计试验次数与校正门槛
.venv\Scripts\python.exe tools\tune_advice.py ledger
```

## 8. 明确不做的事

- 不改 `src/advice/config.py` 的任何权重取值；本文件只规范流程，不改参数。
- 不引入新因子、不扩数据区间、不动 `data/`、不改 `run_backtest.py`。
- 不把 `docs/策略参数基线_2026-11-11.json` 当配置真源：它是时点快照，真源是
  `src/advice/config.py`；禁止反向以快照覆盖 `config.py`。
- 不在基线报告（推荐链路胜率检验、beta/alpha 三层分解）出来前调权重。
