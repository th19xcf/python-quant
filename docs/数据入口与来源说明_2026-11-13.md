### 1.2 固化后的入口

新增 `tools/build_implied_suspension.py`，把当时口径逐条搬到 `tools/` 下：

  --apply --backup-dir _backup/meta/suspension_20261113

判定口径（与原脚本一致，代码见 `tools/build_implied_suspension.py` 的 `scan_asset` / `build_frame`）：

| 列 | 规则 |
|---|---|
| 命中条件 | `volume IS NULL` **或** `amount IS NULL` |

| `ohlc_flat` | 四价（open/high/low/close）全等；任一为空按 `False`（与 pandas `nan == nan → False` 同语义） |

| `source` | 固定串 `volume_isnull|amount_isnull|ohlc_flat`，记录判据本身，不是行级数据来源 |
| `detected_at` | 扫描日期；运行时字段，重跑必变（DG-34），复现旧版本须显式 `--detected-at` |

## 2. G-114：`st_status` / `industry` 的来源与日期口径

### 2.1 采集入口

| 族 | 入口 | 输入 | 落点 |
|---|---|---|---|
| `st_status` | `src/data/risk_flags.py::build_snapshot`（CLI：`python -m src.data.risk_flags refresh [--as-of]`） | 本地 `meta/names.json`（通达信名称快照）派生 `status`；本地无名称时才用远程 `stock_basic` 兜底，`status='D'` 一律判 `unknown`；名称码表为空且无兜底时**拒绝落盘**（fail-closed，`:109-116`） | `meta/st_status/st_status_<YYYYMMDD>.parquet` + 同目录 `manifest.json`（`build_snapshot` 末尾调 `write_manifest`） |
| `industry` | `src/data/industry.py::build_snapshot`（CLI：`python -m src.data.industry refresh [--as-of] [--cache-dir]`） | 通达信本地 cfg：`tdxhy.cfg` 分类 + `tdxzs.cfg` / `tdxzs3.cfg` 名称；缓存目录由 `resolve_tdx_cache_dir(config.data.tdx_data_path)` 决定 | `meta/industry/industry_<YYYYMMDD>.parquet` + 同目录 `manifest.json` |

两者都是**手工/流程触发的 refresh**，没有常驻调度；文件名日期取 `build_snapshot` 的 `as_of`（缺省 = 运行当日），写入走 `write_parquet_atomic`。

### 2.2 抓取时刻与「是否当日盘后截面」

表内**没有** `fetched_at` 列，抓取时刻只能看文件 mtime。2026-11-13 实测（`Get-ChildItem` 取 mtime）：

| 日期 | 星期 | `st_status` 文件 mtime | `industry` 文件 mtime | `st_status` 行数 | `industry` 行数 |
|---|---|---|---|---|---|
| 2026-11-03 | 二 | 16:54:12 | 16:54:20 | 5,654 | 5,654 |
| 2026-11-04 | 三 | 17:58:06 | 17:58:08 | 5,655 | 5,655 |
| 2026-11-05 | 四 | 16:31:32 | 16:31:34 | 5,812 | 5,812 |
| 2026-11-06 | 五 | 16:31:40 | 16:31:46 | 5,812 | 5,812 |
| 2026-11-09 | 一 | 16:31:17 | 16:31:18 | 5,818 | 5,818 |
| 2026-11-10 | 二 | 16:31:23 | 16:31:24 | 5,818 | 5,818 |
| 2026-11-12 | 四 | 16:32:24 | 16:32:27 | 5,832 | 5,832 |

- 7 份全部落在 **16:31~17:58**，均在 A 股收盘（15:00）之后，因此是「**当日盘后截面**」；两族同一日期的时间差 ≤ 8 秒，说明同日是同一次 refresh 连续跑出来的。
- 但截面内容是**当日运行时点的本地输入派生**，不是交易所官方截面：`st_status` 的 `status` 由名称前缀派生（`status_from_name`），`industry` 由当日本地 TDX cfg 派生；两者都不含「当日盘后公告/分类调整」的即时修正。

### 2.3 为什么恰好这 7 个日期（11-07 / 11-08 / 11-11）

| 日期 | 星期 | 有无快照 | 判定与依据 |
|---|---|---|---|
| 2026-11-07 | 六 | 无 | **非交易日**，不生成属正常（`as_of` 只在 refresh 运行当日写盘，周末不跑） |
| 2026-11-08 | 日 | 无 | 同上 |
| 2026-11-11 | 三 | 无 | **是交易日但当日未运行 refresh**：`quotes/stock/sz/000001.SZ.parquet` 实测存在 `2026-11-11` 的 bar，说明源端有该日行情、交易日历上该日是交易日；两族历史表内均无 `as_of=2026-11-11` 这一层，即「入口没跑」，不是「源端没有数据」（DG-27） |

结论：7 个日期 = 11-03/04/05/06/09/10/12 七个有 refresh 运行的交易日；缺 11-11 是运行缺口，缺 11-07/11-08 是周末。

### 2.4 不可补生成（为什么不能事后补 11-11）

`build_snapshot` 只按「运行当日」生成一层，upsert 进 `*_history.parquet`（同一 `as_of` 覆盖、不与既有行重复），输入是**当天**的 `names.json` / TDX cfg。若用今天的输入 + `--as-of 2026-11-11` 补一层，`as_of` 写成 11-11、内容却是 11-13 的名称与分类，属伪造 PIT 截面，**明确不做**（与 DG-16「推不出就留空」同源）。

### 2.5 PIT 使用边界

- 历史 ST 判定只认 `meta/st/st_intervals.parquet` 区间表；`st_status` 族只作当日横截面核对。
- 历史行业归属只认 `meta/industry_pit/`（`industry_pit.parquet` / `industry_change_pit.parquet`）；`industry` 族只作当日截面。
- 跨期引用任何一天的快照前，先按 `as_of` 列确认该层存在；不存在即「无当日截面」，不得用「不晚于该日的最新一份」冒充当日值（选择函数本身允许回落，但结论必须标注实际 `as_of`）。

### 2.6 残留

- 两族 `manifest.json` 缺「抓取时刻（mtime 口径）」「缺失日期与原因」两个字段；该文件在 `data/local_store/**` 下，本批不动。
- `src/data/quality/clean_set.py:1085` 仍把 ST 截面钉在 `as_of=2026-11-03` 那一层（已在权威清单登记为缺陷 G-148，不在本条范围）。

## 3. G-115：`events` 三项说明

### 3.1 全量重建入口：**当前没有独立入口**

三个写入口全部是追加语义（`src/data/events.py`、`tools/backfill_events.py`、`tools/update_events.py`），
没有任何脚本负责「从零/从全量源重建整表」。现状与合法路径：

| 路径 | 语义 | 是否可用于重建 |
|---|---|---|
| `tools/backfill_events.py --import-only --commit` | 按月分片合并后 **append**，并推进 `coverage.end` | 否，只追增量 |
| `tools/update_events.py` | 按自然日抓取 + 同日多轮收敛后 **append**，不动覆盖声明 | 否，只追增量 |
| `python -m src.data.events import --path <全量文件>` | `import_file(mode='replace')`：**整表替换** | **可以**，但需要一份「全量源文件」，仓库内无脚本负责把历史分片合并成全量件 |
| `python -m src.data.events append --path <文件>` | `import_file(mode='append')` | 否 |

`replace` 模式带三项守恒断言（`src/data/events.py:662` 调 `_assert_replace_conservation`，`:309-346`）：
行数守恒、改动行数逐行计数、各列 null 计数不得凭空增加；存量被替换掉的行数与改动行数都会以 `warning` 打印。
因此「想重建」的合法做法是：**先产出全量源文件 → `import`（replace）**，而不是删表重跑（删 `data/` 触红线）。
本批按边界**不新建** `tools/rebuild_events.py`；该入口的落地条件与验收见 §5。

### 3.2 去重键

| 层级 | 键 / 规则 | 代码 |
|---|---|---|
| 行唯一键 | `event_id = f"{art_code}-{stock_code}"` | `src/data/events.py:212` |
| 同标的同类型时间窗 | 同一 `(ts_code, event_type)` 内，`publish_time` 相距 **≤ 30 自然日**（`DEDUP_DAYS = 30`）的只保留**最早**一条；排序键带 `event_id` 兜底，保证同一批次在不同进程选出同一代表行 | `:76`、`:256-278` |
| `append` 与既有行的关系 | 既有行**一条不删、一个字段不改**；新批次先剔除与既有行重复的 `event_id`，再在批次内做 30 日去重，**不与既有行做 30 日比较**——所以补历史数据不会因新出现的更早公告把既有行挤掉 | `:283-310`、`:582-585` |
| `replace` 与既有行的关系 | 整表替换，逐类记账（保留未改 / 保留改值 / 被替换掉），三类之和必须等于存量行数 | `:309-346` |

推论：同一天同标的多份同类型公告（不同 `art_code`）只有一条进表；**因此 `(ts_code, event_type, ann_date)` 不唯一**，不能当主键用。

### 3.3 覆盖登记职责（`coverage.json`）

`coverage.json` 的写入是 `import_file` 的副作用：每次落盘后调 `_write_coverage(root, merged, complete, coverage_start, coverage_end)`（`src/data/events.py:688`、定义 `:491`）。
**推进 `start` / `end` 的责任在调用方**，不在 `import_file`：

| 入口 | 对 `coverage.start` / `end` 的动作 |
|---|---|
| `tools/backfill_events.py` | **推进** `end` 到本次补到的日期（`:19`、`:100`、`:296`） |
| `tools/update_events.py` | **原样传递**既有值，绝不推进；跑完只打印「是否需要人工推进 `coverage.end`」及其依据（`:18-19`） |
| `python -m src.data.events import/append` | 由 `--coverage-start` / `--coverage-end` 决定；不传则保持/按实现取默认（`:883-886`、`:860-866`） |

因此「行集已变、覆盖声明未变」是**合法但需人工收口**的状态：例如 2026-11-11 的 10 行已入库，而 `coverage.end` 停在 2026-11-10（`covered_range = 2015-01-01~2026-11-10`）。
这也是 G-072「业绩预告只有 2025 年」无法判定「源端没有 / 入口没跑」的根因：覆盖声明只由补数路径推进，日更不写，`covers()` 对声明外日期一律返回 `unknown`。

使用规则：**覆盖边界只认 `coverage.json` 的 `start`/`end`**，不得从数据 min/max 反推；在声明区间外必须返回 `unknown`，不得判「无事件」（DG-27）。
