# 数据治理方法论备忘

> 本文件记录两条**可复用、可校验**的方法论，每条都以本仓库的实测数字为实证，供后续审计与收口时直接引用。
> 只登记方法论与实证锚点，不改任何数据、不替代 `.trae/rules/` 的判定层；两节末尾各给一句「建议并入位置」，供用户侧决定是否落规则。

---

## 1. 旁路改写必须回写索引

**判定句**：任何脚本直接改盘后，必须回写对应索引 / 清单字段（`file_size`、`bytes`、`rows`、`sha256`、mtime 之外的全部内容指标），否则索引与磁盘实际文件之间会出现**无痕迹漂移**——这种漂移用 mtime 类检查永远看不出来。

**实证（`meta/daily_index.parquet`）**：

| 项 | 数值 |
|---|---|
| `file_size` 陈旧行数 | **252 行** |
| 陈旧幅度 | **−2,685 B ~ +611 B** |
| 总差额 | **+39,335 B** |
| 成因 | **不是** `manifest_refresh` 能力缺口，**也不是**写入口漏回写，而是**旁路改写**（`copy2` 保留 mtime、只有 ctime 变化）之后未回写索引 |
| 为何 mtime 检查无效 | `copy2` 逐字节复制时保留原 mtime，磁盘侧 mtime 与索引记录仍"看着一致"，只有 ctime 变化，而全仓 mtime 类校验不读 ctime |
| 反向对位证据 | **242 只 fund** 的索引登记值**恰等于** `logs/data_changelog.csv` 中同一秒记录的 `bytes`，可逐条对位复算 |
| 影响面 | 仅 `tools/lineage/build_inventory.py:105` 的 bytes 汇总（下游无价格 / 行数类误用） |

**为什么必须回写**：索引的用途是「不发盘也能判断文件是否变化」。一旦旁路改写不回写，索引记录的是**上一位写者的版本**，之后任何基于索引的判断（去重、增量、审计差异）都会把当前文件当成"未变"，缺陷因此不可被检出。

**执行口径**：① 旁路改写（`shutil.copy2` / 手工替换 / 外部脚本落盘）完成后，同一轮内必须重算并回写该文件的 `bytes` / `size` / `rows` / `sha256`；② 若无法在同一轮回写，必须在改动回执里写明「索引已过期，待回写」并列入待办；③ 审计时用「索引值 vs 磁盘实际」双向求差，禁止只用 mtime 判定是否一致。

> **建议并入 `.trae/rules/data_governance.md`**：「五、完成与留证」新增一条（建议编号 DG-33，紧随 DG-32 之后），判定句写「旁路改写必须在同一轮回写索引 / 清单字段；审计不得只用 mtime 判一致」。

## 2. 含运行时字段的表，SHA 不能证内容等价

**判定句**：含 `fetched_at` 之类运行时钟字段的正式表，**字节级 SHA256 只能证明「本次落盘的是这个文件」，不能证明内容未变**。判内容等价必须按主键 join 逐值对拍，并**单独报空值计数**——只有「**既有非空值被改动数」为 0** 才可判等价。

**已知适用表**：

| 表 | 运行时字段 |
|---|---|
| `meta/st/st_price_inferred.parquet` | `fetched_at` |
| `factors/stock_turnover.parquet` | `fetched_at` |

**为什么 SHA 不够**：这两张表每次重建都会写入新的 `fetched_at`，因此两次运行产生的**字节必然不同**。此时 SHA 不等**不能**推出内容有变；反过来，SHA 相等只说明"是同一个文件的同一份字节"，而一旦为了比内容去对齐 `fetched_at`（例如把它置空或回填），SHA 又会失真。两种形态都不能拿来当"内容等价"的证据。

**正确判据**：以业务主键（如 `(ts_code, date)`）做 join，逐列比对，同时给出三项数字——① 共同行数；② 各列最大绝对差与差异行数；③ **改动前后各自的空值计数**，以及「既有非空值被改动数」（必须为 **0**）。三项齐备才可判等价；缺空值计数这一项，则「空值从 0 变成 N」这类破坏不会被断言捕获（与 DG-31 的反例同源）。

**附：修复归因用「旧代码 + 当前输入」重算控制表**

当要判断「某次修复到底改了什么」时，用**旧代码 + 当前输入**重算一张控制表，再与正式产物比对：

- **控制表与正式产物除目标列外全列相等** → 差异被锁定在这一个修复点上，**修复作用域成立**，可据此判「改动只来自该修复」；
- **两者不等** → 说明还有别的因素在起作用（输入已变、口径另改、或另有缺陷），此时必须再加第三张表（**旧码 + 旧数据**）做三表对照，逐列定位差异来源；
- **禁止**把三表之间的全部差异整体记在某一次修复头上——那会把其他来源的漂移伪装成修复的副作用或反之，导致结论不可复核。

> **建议并入 `.trae/rules/data_governance.md`**：「五、完成与留证」新增一条（建议编号 DG-34，与 DG-30 同属「对拍对象选择」主题，建议紧接 DG-30 之后、DG-31 之前），判定句写「含运行时字段的正式表不得以 SHA 相等判内容等价；须按主键 join 逐值对拍并单独报空值计数」。
