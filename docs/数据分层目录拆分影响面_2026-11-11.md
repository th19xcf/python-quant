  搬迁时这些行决定 `derived/` 前缀挂在哪一层，因此单独统计、不计入 raw/derived。

## 3. 搬迁改动量与风险

### 3.1 改动量：真正要动的是 129 条，不是 476 条

目标形态是「raw 留在原位、derived 进 `data/local_store/derived/`」，因此 raw 侧 248 条引用**不需要改**，
只有挂到派生语义上的引用需要改写：

| 项 | 数量 | 说明 |
|---|---|---|
| 必须改的引用 | **129** | `derived` 层引用；其中 读 38 / 写 18 / 路径构造 73 |
| 必须改的文件 | **47** | 含 derived 引用的文件 |
| 其中同时含 raw 与 derived 的文件 | **37** | 不能按文件整替换前缀，必须逐处判断 |
| 路径基准（「根」）引用 | 83（读 9 / 写 5 / 路径构造 69） | 涉及 61 文件（src 14 / tools 47）；决定 `derived/` 挂在哪一层 |
| 入口/开关 | 14 | `local_store_path` / `LOCAL_STORE` / `DEFAULT_STORE_PATH` |

三个「一处改、全局生效」的杠杆点，改这三处可覆盖大部分引用：

1. `src/data/local_store/paths.py` 的 `DEFAULT_STORE_PATH` 与 `resolve_store_root`——所有走配置的入口都以它为基准；
2. `src/data/local_store/store.py` 里的路径属性（`meta_path`、`state_path`、`quote_path`、`factor_path`、`dividend_path` 等），它们才是 69 条「根 + 段」拼接的落地处；
3. `src/data/services/breadth_service.py:93-102` 这类「自己拿 store_root 再拼 `meta/`」的旁路（不走 `store.py`，漏改不会被杠杆点覆盖）。

需要单独决策的结构性难点：

- **`factors/` 目录会被一刀切成两半**：`stock_dividend` / `fund_dividend` / `fund_share_change` 是 raw，
  `stock_adj_factor` / `fund_adj_factor` / `stock_turnover` / `meta.json` / `covered_codes.txt` 是 derived。
  `LocalFactorStore` 目前用同一个 `self.root` 拼这两类路径（`store.py:527-532`），拆开后必须持有两个根。
- **raw 文件长在派生目录下**：`meta/factors/stock_shares.parquet`（raw）在 `meta/factors/`（派生）里，

- **`meta/state.json` 与 `meta/state/` 同名不同层**：`state.json` 是列存构建状态（derived），

## 4. 漏改检测办法（可执行）

四道闸门，任一道不过即判定「还有一处读老路径」。

### 4.1 静态闸门：老前缀零命中（白名单之外）

搬迁后执行，期望输出 **0 行**（`paths.py` 常量与迁移映射表进白名单）：

```powershell
rg -n --glob '*.py' "'meta'\s*/\s*'|'factors'\s*/\s*'|'quotes'\s*/\s*'|local_store/(meta|factors|quotes)" src tools
```

更严的一版是 AST 级：所有路径表达式里，`quotes` / `meta` / `factors` 之后必须紧跟 `raw/` 或 `derived/`，
不允许直接挂在根上。可写成一条测试（伪代码）：

```python
import ast, pathlib
BAD = ('quotes', 'meta', 'factors')
for path in list(pathlib.Path('src').rglob('*.py')) + list(pathlib.Path('tools').rglob('*.py')):
    tree = ast.parse(path.read_text(encoding='utf-8'))
    for node in ast.walk(tree):
        if isinstance(node, ast.Constant) and isinstance(node.value, str):
            first = node.value.split('/')[0]
            if first in BAD and node.value.count('/') == 0:
                ...  # 记录「裸目录名」，逐条人工确认是否经过 raw/derived 根
```

### 4.2 反向验证闸门：把新目录跑通、老目录留着不动

这是最有力的一条，且**完全不动 `data/`**：

1. 在 `_staging/<任务>_<日期>/` 下按新布局放一份派生数据（复制，不移动）；
2. 把配置 `DATA__LOCAL_STORE_PATH` 指向这份 staging 目录（或让 `resolve_store_root` 读它）；
3. 跑一条真实读路径，例如 `tools/research/build_multifactor_signals.py --no-write` 与
   `pytest tests/ -k local_store`；
4. 断言产物与搬迁前**逐值一致**。

若代码里还有 `Path('data/local_store')` 之类的硬编码，它会继续读老目录——产物仍会「对」，
因此第 4 步必须同时统计「到底读了哪个目录」：在 staging 目录放一个只有新目录才有的哨兵值（如某标的的分红多一行），
产物里出现哨兵值才算真正走了新路径。

### 4.3 逐值对拍闸门（DG-20）

搬迁是 `mv` 不是重算，SHA256 必须**逐个文件不变**：

```powershell
# 搬迁前
Get-ChildItem -Recurse data\local_store -Filter *.parquet |
  Get-FileHash -Algorithm SHA256 | Select-Object Path,Hash | Sort-Object Path |
  Export-Csv _staging\derived_split_20261111\before_sha.csv -NoTypeInformation
# 搬迁后（只对目录变化的那批文件）
Get-ChildItem -Recurse data\local_store -Filter *.parquet |
  Get-FileHash -Algorithm SHA256 | Select-Object Path,Hash | Sort-Object Path |
  Export-Csv _staging\derived_split_20261111\after_sha.csv -NoTypeInformation
```

补三项守恒：文件数、总行数（逐表 `pl.read_parquet(p).height` 之和）、抽样标的的首末日期。
任一项不等即回滚。

### 4.4 缺口计数闸门（专抓 3.2 那 12 处静默失败）

搬迁前后各跑一次同样的取数/质检流程，统计并比对：

| 计数 | 采集方式 | 期望 |
|---|---|---|
| `read_file` / `read_daily` 返回 `None` 的次数 | 迁移期在函数内加计数（或 patch 后统计） | 搬迁后为 0 |
| `data_manager` 本地未命中、回落数据库的次数 | `logger.debug` 那条分支计数 | 与搬迁前完全相同，不得增加 |
| 质检 `skipped` 标的数 | `checker` 汇总里的 `skipped_price_rules` / `codes_skipped` | 与搬迁前完全相同 |
| 回测分红事件数、`dividend_cash_total` | 固定标的固定区间跑一次 | 逐值相同（如 601258.SH 2019-12-30 事件仍在） |

「搬迁后本地未命中次数 = 0」是比任何静态扫描都可靠的判据：静默失败的特征就是命中数悄悄下降，
而这条计数会把它变成显式数字。

### 4.5 收口顺序建议

1. 先落基线：4.1 扫描结果 + 4.3 的 SHA/行数快照存进 `_staging/derived_split_20261111/`；
2. 改杠杆点（`paths.py` + `store.py` 路径属性 + `LocalFactorStore` 双根），不动调用方；
3. 用 4.2 的 staging 反向验证，确认没有硬编码老路径；
4. 动 `data/`：按 DG-11 先把现有目录整体移到 `_backup/`，再落新布局（此步属红线操作，需用户点名确认路径）；
5. 跑 4.3 / 4.4 全量对拍，四项证据齐全才算完成；不通过则按 DG-13 从 `_backup/` 回滚。
