## 1. 结论

| 决策点 | 取值 | 依据位置 |
|---|---|---|
| 步骤顺序 | 去极值 → 缺失保留 mask → 标准化 → 行业+lnMV 中性化 | 本文件 §2 |
| 去极值 | `med ± 3 × 1.4826 × MAD`（`winsor_k=3`） | §5.2 |
| 标准化 | `zscore`（`standardize='zscore'`） | §5.1 |
| 中性化 | 行业饱和哑变量 + lnMV 的联合 OLS 残差（FWL 等价实现） | §3 |
| 缺失 | 一律保留 null，**任何一步都不填 0**，另给 `{col}__valid` 掩码 | §2.3 |

`zscore` 而非 `rank_gauss` 的三条硬理由：|ICIR| 在 h=5/20/60 上**全部显著更好**
（配对 t，p<0.001），而 rank_gauss 的 |RankIC| 优势在样本内**一次都没达到显著**；
zscore 残差尺度更稳（跨日 CV 0.0348 vs 0.0372）；与现行 ±3σ 约定一致。
反面证据见 §5.1 末段——若主判据改为 OOS RankIC，应切 `rank_gauss`。

## 2. 管线定义

### 2.1 四步与可单独调用

```python
from src.alpha.cross_section.preprocess import (
    winsorize_mad, mark_missing, standardize, neutralize_industry_mv, run_pipeline)

out, d1 = winsorize_mad(df, ['momentum_1m'])                      # -> momentum_1m_win
out, d2 = mark_missing(out, ['momentum_1m'])                      # -> momentum_1m__valid
out, d3 = standardize(out, ['momentum_1m_win'], method='zscore')  # -> momentum_1m_win_std
out, d4 = neutralize_industry_mv(out, ['momentum_1m_win_std'])    # -> ..._win_std_neu

res = run_pipeline(df, ['momentum_1m'])   # 一次串完，返回 PipelineResult
res.columns                               # {'momentum_1m': 'momentum_1m_win_std_neu'}
res.summary()                             # 四步诊断的可 JSON 汇总
```

列名即阶段：走完全链的列形如 `momentum_1m_win_std_neu`，从列名可直接看出经过哪几步；
中间列全部保留，便于只重跑某一步。输入行序、行数不变，只新增列（单测
`test_pipeline_keeps_rows_order_and_adds_columns` 守住）。

### 2.2 每步参数与守卫

| 步骤 | 关键参数 | 守卫行为 |
|---|---|---|
| `winsorize_mad` | `k=3`、`scale=1.4826`、`min_obs=30` | `MAD ≈ 0` 或当期样本 < `min_obs` 时**不截断**（诊断记 `applied=0`），避免整列塌到中位数 |
| `mark_missing` | `non_finite_to_null=True` | 只标记、只把 `±inf` 转 null，**不产生任何 0 值**；非数值列不 cast |
| `standardize` | `method='zscore'`、`min_obs=30` | 常数截面（std≈0 / 全同秩）**置 null 而不是 0**，避免「无区分度」被当成「中位」 |
| `neutralize_industry_mv` | `min_obs=30`、`min_group_size=5` | 行业内有效样本 < 5 的组整体剔除（单样本组会让残差恒 0，等于把该股当作完美拟合） |

### 2.3 缺失语义：mask 与「被剔除」必须可区分

`mark_missing` 基于**原始**因子列产出 `{col}__valid`。因此最终残差为 null 时有三种可区分情形：

| 情形 | `__valid` | 最终残差 |
|---|---|---|
| 原始就缺失 | `False` | null |
| 原始有值但市值/行业缺失、或行业组过小 | `True` | null |
| 正常 | `True` | 数值 |

单测 `test_pipeline_mask_separates_missing_from_dropped` 与真实面板冒烟（§6.2）都验证了这一点：
两类 null 可以被分别计数，不会像「填 0」那样把「没有数据」伪装成「中位/极端值」。

### 2.4 诊断输出

`neutralize_industry_mv` 逐日逐因子给出：

- 参与回归样本数 `n_obs`；
- 四类未入回归数 `n_dropped_null_factor / n_dropped_null_mv / n_dropped_null_industry /
  n_dropped_small_group`——**互斥**，按此优先级依次判定，因此与 `n_obs` 相加恰等于当期行数，可直接对账；
- `beta`、`r2`、`resid_std`；
- `corr_resid_ln_mv`（残差对原始 lnMV 的相关）、`corr_resid_ln_mv_within`
  （残差对**行业内去均值后** lnMV 的相关，应≈0，用于自证 FWL 实现正确）；
- `max_abs_ind_dummy_leak`（各行业组残差均值 / 残差标准差的最大绝对值，应≈0，用于自证哑变量已被吸收）。

`winsorize_mad` 给 `n_obs / n_clipped / clipped_ratio / applied`；`standardize` 给
`n_obs / mean_out / std_out / short`；`mark_missing` 给 `n_obs / n_missing / n_non_finite`。

## 3. 为什么必须是「联合 OLS」而不是「两步投影」

现役两套写法都**不是** `[行业哑变量 + lnMV]` 的联合 OLS 残差：

| 实现 | 做法 | 与联合 OLS 的关系 |
|---|---|---|
| `src/alpha/cross_section/cross_sectional.py:145-161` | 先按 `(date, industry)` 去均值，再对**日期中心化**的 lnMV 回归 | 第二步的暴露忽略了行业均值差异，只吸收了暴露的**截面**变异，漏掉**行业内**变异 |
| `tools/research/build_multifactor_signals.py:73-76` | `f.mean().over("ind_code")`——行业均值**跨全表**，未按 `date` 分组 | 用跨期行业均值去均值，等于混入历史信息，且组内去均值不成立 |
| 本模块 `_neutralize_parts` | 按 `(date, industry)` 同时对 `y` 与 `x` 去均值，再对去均值 `x` 做一元回归 | FWL 定理保证与联合 OLS 残差**逐值相等** |

实测差异（`_staging/preprocess_chain_20261111/old_vs_new.json`，2 个调仓日 × 3 因子，
同一份 `_win_std` 输入，n≈3,300/日）：

| 对比 | Spearman 区间 | 最大绝对差 |
|---|---|---|
| 本模块 vs `cross_sectional.neutralize` | 0.9833 ~ 0.9999 | **1.081** |
| 本模块 vs `build_multifactor_signals._neutralize` | 0.9910 ~ 0.9999 | 0.313 |

秩相关看似很高，但**最大绝对差 1.08 个标准差**——在标准化残差量纲上足以改变个股排序段位，
也足以让同一份数据在两个入口得出不同的组合。这正是「必须收成一份」的直接证据。

> 单测 `test_neutralize_matches_explicit_dummy_ols` 用 `np.linalg.lstsq` 显式构造
> `[1, 各行业哑变量, lnMV]` 设计矩阵做对拍，逐值相等（`abs=1e-9`），不是「口径接近」。

## 4. A/B 设计

**数据（只读）**

| 项 | 来源 |
|---|---|
| 因子面板 | `_staging/factor_candidates_20261111/base_rebal.parquet`（周频，575 个调仓日，49 因子） |
| 行业 | `data/local_store/meta/industry_pit/industry_pit_sw.parquet`（PIT：`in_date`/`out_date`） |
| 市值 | `data/local_store/meta/financials/valuation_daily.parquet` 的 `total_mv` → `ln_mv`（`join_asof` backward） |
| 停牌/ST | `meta/name_history.parquet` 剔除名称含 `ST|退` 的标的 |

**过滤**：`cum_count >= 250`、`volume > 0`、剔除次日开盘涨跌停（688 为 19.5%，300/301 在
2020-08-24 后 19.5% 否则 9.5%，其余 9.5%）、单日截面 ≥ 100 只、行业组 ≥ 5 只。

**指标**（先在因子层算完再取 `mean|·|`，避免把不同因子的量级混在一起）

- `RankIC_t = Spearman(resid_t, fwd_ret_h)`；`IC_t` 为 Pearson；
- `ICIR_f = mean(RankIC_f) / std(RankIC_f)`（不年化）；`mono5_f` = 每日 5 分组收益对组号的
  Spearman 再跨日平均；
- OOS 切点 `2021-12-31`；双门槛 = `|ICIR| ≥ 0.3 且 |RankIC| ≥ 0.01 / 0.02`。

**样本量**：h=5 用全部 575 日；h=20 等距抽样 143 日；h=60 用 47 日（fwd_60 需 60 个交易日，
末端不足自然截断）。三档 horizon 的目的是确认结论不依赖单一持有期。

**组合**：6 组 = {`q1_99`, `mad3`, `mad5`} × {`zscore`, `rank_gauss`}；中性化在全部组合中固定为
`[行业哑变量 + lnMV]` 联合 OLS。

**为什么选 zscore**

1. 项目主判据是 |ICIR|。三个 horizon 上 zscore 全部胜出且**极显著**（t=4.30~5.46，p<0.001），
   不是「差不多」。
2. rank_gauss 的 |RankIC| 优势从未达到显著（p=0.089~0.164），且优势幅度 0.4%~1.1%
   远小于 |ICIR| 的 3.3%~3.9% 劣势。
3. 单调性两者全程打平（p=0.356/0.796/0.967），不构成区分依据。
4. 稳定性：两种残差的秩相关均值 0.986（最低 0.929），说明它们只是对同一信息的不同加权；
   但残差标准差的跨日变异系数 zscore **0.0348** 低于 rank_gauss 0.0372（rank_gauss 更低
   的因子只有 22/49），zscore 的截面量纲更稳，更利于后续等权/加权合成时权重可比。
5. 现行打分链路（`scoring._z_expr`、`factor_eval.build_composite`）都是「z 后截断 ±3」，
   沿用 zscore 不引入口径断裂。

**反面证据（如实列出，不隐藏）**

- OOS |RankIC| 与 OOS 双门槛过线数三条 horizon 上都是 rank_gauss 更好（h=20：34/49 vs 31/49；
  OOS RankIC 0.03628 vs 0.03538）。样本内 zscore 赢、样本外 rank_gauss 赢，是本组最真实的分歧。
- 若后续把主判据从 |ICIR| 改为 **OOS RankIC**，应切 `rank_gauss`；切换只需
  `standardize_method='rank_gauss'` 一个参数，管线其余部分不变。
- `rank_gauss` 还有一个附加优点：它使去极值 k 在行为上几乎不敏感（见 §5.2），可免调参；
  代价是丢弃了幅度信息。

### 5.2 去极值：MAD k=3 vs k=5 vs 1%/99%

**被削掉的样本比例**（三个 horizon 上高度稳定，下表取 h=5 / h=60）：

| 方式 | 边界 | 被削比例（h=5） | 被削比例（h=60） | 正态理论值 |
|---|---|---|---|---|
| `q1_99` | 1% / 99% 分位 | 1.9929% | 1.9913% | 2.00% |
| `mad3` | `med ± 3×1.4826×MAD` | **6.0089%** | **6.0134%** | 0.27% |
| `mad5` | `med ± 5×1.4826×MAD` | 2.5740% | 2.5680% | 0.00006% |

真实因子面板是厚尾分布：`±3σ` 在正态下只削 0.27%，在实盘面板上削 **6.01%**；
`±5σ` 在正态下几乎不削，实盘仍削 2.57%。换句话说 **k=5 的实际强度接近 1%/99% 分位，
k=3 才是真正的「强截尾」**——这组数字是把「3 倍还是 5 倍」的争论落到实处的关键。

**配对 t（固定 zscore）**

| 指标 | h | q1_99 | mad3 | mad5 | q1_99 vs mad3 | mad3 vs mad5 |
|---|---|---|---|---|---|---|
| \|RankIC\| | 5 | 0.02517 | **0.02632** | 0.02594 | t=−2.93, p=0.005（mad3 好 34/49） | t=3.23, p=0.002（mad5 仅好 12/49） |
| \|RankIC\| | 20 | 0.03603 | **0.03762** | 0.03697 | t=−3.16, p=0.003（33/49） | t=3.49, p=0.001（12/49） |
| \|RankIC\| | 60 | 0.04457 | **0.04691** | 0.04605 | t=−3.24, p=0.002（33/49） | t=3.54, p=0.001（13/49） |
| \|ICIR\| | 5 | 0.30961 | 0.31429 | **0.31960** | t=−0.60, p=0.551 | t=−2.63, p=0.011（mad5 好 33/49） |
| \|ICIR\| | 20 | 0.46040 | 0.46934 | **0.47594** | t=−0.74, p=0.461 | t=−1.82, p=0.076 |
| \|ICIR\| | 60 | 0.65306 | 0.67355 | **0.68180** | t=−1.07, p=0.292 | t=−1.42, p=0.161 |
| \|mono\| | 5 | 0.10145 | 0.09751 | **0.10134** | t=1.47, p=0.149 | t=−2.55, p=0.014（31/49） |
| \|mono\| | 20 | 0.15973 | 0.15360 | **0.16121** | t=1.44, p=0.157 | t=−2.91, p=0.006（31/49） |
| \|mono\| | 60 | 0.22514 | 0.22588 | 0.22584 | t=−0.15, p=0.883 | t=0.01, p=0.990 |

读法：

- **|RankIC| 明确支持 k=3**：k=3 对 1%/99% 与 k=5 都显著更好（p≤0.005），且是三个 horizon 一致。
- **|ICIR| 略微支持 k=5**，但只在 h=5 显著（p=0.011），h=20/60 不显著（p=0.076/0.161）。
- **|mono| 支持 k=5**，h=5/h=20 显著，h=60 完全打平。
- 三项加权：k=3 在一个主指标（RankIC）上稳定显著胜出，k=5 在 ICIR/mono 上胜但强度弱、
  且随 horizon 衰减——**取 k=3**。

**`rank_gauss` 下 k 几乎无影响**（同一标准化方式内部比较）：
h=20 时 `q1_99 / mad3 / mad5` 的 |RankIC| 为 0.03805 / 0.03804 / 0.03804（p>0.8），
|mono| 为 0.1541 / 0.1527 / 0.1531。即：**rank-gauss 把去极值变成无关步骤**（秩不变），
这也是 §5.1 中「若切 rank_gauss 可免调 k」的依据。

### 5.3 现役口径 vs 新默认（直接对拍）

A = 现役：1%/99% 分位 + z-score + `clip(±3)`；B = 新默认：MAD k=3 + z-score（不再二次截断）。
同一批 143 个调仓日、h=20、49 因子（`_staging/preprocess_chain_20261111/status_quo_vs_new.json`）：

| 口径 | mean\|RankIC\| | mean\|ICIR\| | mean\|mono\| | 双门槛(0.02) |
|---|---|---|---|---|
| A 现役 | 0.03654 | 0.4700 | 0.1584 | 35/49 |
| B 新默认 | **0.03762** | 0.4693 | 0.1536 | **36/49** |
| 差 | **+2.96%**（t=−3.07, p=0.0035，B 好 36/49） | −0.15%（p=0.92，打平） | −3.0%（p=0.119，打平） | +1 个 |

换成新默认不会牺牲 ICIR/mono，换来的是**显著的 RankIC 提升**与多 1 个因子过双门槛。
「z 之后再 clip(±3)」这一层被证明是多余的：MAD k=3 已经做了等效截尾，二次截断只会损失信息。

## 12. §7 替换清单落地（`tools` 侧）与四处自行决定

本轮只改 `tools/research/build_multifactor_signals.py`、`tools/single_window_diag.py`
与 `tests/test_single_window_diag.py`；`src/alpha/cross_section/preprocess.py` 与
`cross_sectional.py` 未动（后者仅确认 `neutralize` 的 `deprecated` 注解在位）。

### 12.1 删除 `build_multifactor_signals` 的 `_neutralize` / `_zscore`

- **改了什么**：删两个私有实现，预处理改走 `run_pipeline`；IC 改在残差列
  `z_{c}` 上计算；原始因子列保留，覆盖率按原始可用性披露。
- **为什么**：与 `preprocess` 重复实现，且 `_neutralize` 的 `over("ind_code")`
  缺 `date` 分组，等价于用跨期行业均值去均值；顺序（先中性化后标准化）与管线相反。
- **单点回退**：`git checkout -- tools/research/build_multifactor_signals.py`。无数据副作用。

### 12.2 `_spearman_ic` 增加 `alias` 形参

- **改了什么**：签名变为 `(df, col, alias)`，列名不再由入参列名拼接。
- **为什么**：IC 改在 `z_{c}` 上算后，列名仍需 `ic_{c}` 供 ICIR 权重循环读取。
- **单点回退**：调用改回 `_spearman_ic(df, c)`，内部恢复 `f"ic_{col}"`。

### 12.3 `tests/test_single_window_diag.py` 截面 12 → 40 只

- **改了什么**：只改 fixture 行数，断言未动。
- **为什么**：`winsorize_mad` / `standardize` 的 `min_obs=30` 守卫会把 12 只的截面
  整列置 null，用例会以「null 参与均值」失败。
- **单点回退**：`range(40)` 改回 `range(12)`（会重新失败）。

### 12.4 `_day_data` 的 null → 0（回归入参）

- **改了什么**：`np.nan_to_num(z, nan=0.0)`，仅在喂 numpy 回归前。
- **为什么**：`build_style_panel` 已不再 `otherwise(0.0)` / `fill_null(0.0)`，
  但 NaN 进入 `lstsq` 会让整段归因变 NaN；0 即截面均值，与 `_lookup_arrays`
  「缺失记 0」同口径。
- **量化**（`_staging/preprocess_replace_20261111/ab_missing_zero.json`，h=20 面板
  2,303,889 行 / 575 周）：被 0 纳入的样本 **84,000 行（3.65%）**，涉及 **3,241 只**，
  575 周全部存在；改为剔除后风格 β 的 |Δ| 均值 ≤ **0.0050**（`style_size` 最大），
  单周最大 **0.1504**（`style_size`）；572 个有效周中 **81 周** max|Δβ|>0.01、
  **7 周** >0.05。
- **结论**：小量但非零，当前保留 0 填充；若收紧应改为剔除并在归因里披露剔除行数。
- **单点回退**：删掉该 `nan_to_num` 一行。
