## 九、设计缺陷与改造建议

### 9.1 可复用的正确入口（命令 + 参数）

`build` 子命令**有**增量与干跑模式，日常刷新不应跑默认全量：

```powershell
# 日常增量：只重建源 .day 末行日期比本地新的标的
.\.venv\Scripts\python.exe -m src.data.local_store build --incremental --target-date 2026-11-11

# 只刷新某一类
.\.venv\Scripts\python.exe -m src.data.local_store build --incremental --data-type fund

# 先看影响面再决定
.\.venv\Scripts\python.exe -m src.data.local_store build --incremental --dry-run

# 崩溃后用备用命令补 meta（不重算行情）
.\.venv\Scripts\python.exe -m src.data.local_store rescan-meta

# 因子副本治理（只读校验 → 同步 → 复验 → 门禁）
.\.venv\Scripts\python.exe -m src.data.local_store factor-governance
```

可用参数：`--all`（需显式指定；全量前会先复制快照到 `_backup/quotes_<日期>/`）/ `--incremental` / `--codes` / `--since` / `--data-type` / `--target-date` / `--max-date` / `--dry-run` / `--force-intraday` / `--skip-anomaly-lists` / `--skip-derive-turnover` / `--skip-factor-verify` / `--allow-missing-factors`。**不带任何模式参数时默认增量**（2026-11-11 晚改造，见 §11.2）。

**所以"只有全量、就地覆盖、无快照这一种模式"的说法不成立**——有 `--incremental` 与 `--dry-run`。真正的问题是默认值与失败恢复设计。

### 9.2 三个实际缺陷

| # | 缺陷 | 具体表现 | 后果 |
|---|---|---|---|
| D1 | **`--all` 是默认值** | 不带参数直接跑 `build` 就触发 9k 文件全量重写 | 一次误敲即全量覆盖；本次即如此 |
| D2 | **`flush_meta` 的 dtype 与磁盘不一致** | `flush_meta` 把 datetime 的 `built_at` 追加到字符串列的 `daily_index.parquet`，`store.py:493` 稳定抛 `ComputeError` | 每次全量构建都会在最后一步失败；失败后 `_align_written_factor_copies`(473)、`write_state`(478)、`verify_incremental_target`(495) **全部被跳过**，本次 633 只基金因子副本退化即由此而来 |
| D3 | **就地覆盖、无 staging 与快照** | 9,091 个正式文件直接 `os.replace`，未走 `_staging/`，未按 DG-11 把旧目录移入 `_backup/` | 单文件原子但整批非事务；中途崩溃无回滚点，`state.json` 仍停留在 11-10，与实际不符 |

补充：崩溃后 `meta/state.json` 未被更新（现仍为 `2026-11-10T16:22:57`、`last_build=incremental`、9,770 文件），任何读 `state.json` 判断"上次构建"的工具都会得到错误时间。

### 9.3 最小改造（2026-11-11 晚已落地，见 §11）

按性价比排序，三条都不改变既有 CLI 的显式用法：

1. **修 D2（必修，改动最小）**：`flush_meta` 落盘前把 `built_at` 统一 `cast` 成磁盘列同一 dtype 再 `vstack`；或在 `write_parquet_atomic` 前显式给定 schema。同时把 `_align_written_factor_copies` 与 `write_state` 调到 `flush_meta` **之前**，让"数据写完"与"记账写完"这两件事不互相阻塞——即便 meta 写失败，因子对齐与 state 也已落地。
2. **改 D1（防误触）**：把 `--incremental` 设为默认，`--all` 需显式给出；`--all` 时要求额外的 `--yes` 或打印待改文件数并要求确认。
3. **补 D3（对齐 DG-11）**：`--all` 前先把 `quotes/` 整体移入 `_backup/quotes_<日期>/`（移动而非删除，留 SHA256 对照），或在 `_staging/` 构建后整目录切换。另在构建开始时写 `_staging/<task>_<date>/progress.json`（DG-7），使中断可发现、可续跑。
