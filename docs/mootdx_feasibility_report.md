# mootdx 接入可行性验证报告

> 验证时间：2026-11-03 13:15–13:40（Asia/Shanghai）
> 验证对象：mootdx 0.11.7（PyPI 最新版）
> 环境：`e:\code\python\quant`，Python 3.14.9，venv `.venv`
> 性质：只读验证 + 实测采集；**未改动项目代码、未提交 git、未写入 pyproject.toml**

---

## 0. 一句话结论

**不能作为数据源接入：通达信公开服务器的 K 线/盘口/逐笔命令在 2026-09 之后已全面返回空，142 个节点实测 0 个能取日线；唯一还可用的"历史分时"接口只给"分钟收盘价 + 成交量"，没有 OHLC 与成交额，既补不了日线缺口也无法满足 `stock_minute` 的字段契约。结论为「不值得接」，只出报告、不写代码。**

## 3. 数据拉取实测

### 3.1 日线全历史对拍：**无法完成（K 线通道已失效）**

| 测试项 | 结果 |
|---|---|
| `get_security_bars(9, 1, '600000', 0, 800)` 日线 | **None**（响应体 = 16 字节头 + 2 字节 `ret_count=0`） |
| 周线 / 1 分 / 5 分 / 15 分 / 30 分 / 60 分 | 同样全部空 |
| `get_index_bars`（000001.SH 日线） | 空 |
| `get_security_quotes`（实时盘口） | 空（20 字节，计数 0） |
| `get_transaction_data`（逐笔） | 空（18 字节） |
| 仍正常工作的接口 | `get_security_count`(24573)、`get_security_list`(1000 行/次)、`get_xdxr_info`(88 条)、`get_finance_info`(37 字段)、`get_history_minute_time_data`(240 行)、`get_minute_time_data`(今日分时) |

交叉验证：用独立实现 `pytdx 1.72`（隔离安装，不污染 venv）访问同一节点，`get_security_bars` 同样返回 None。**说明不是 tdxpy 解析 bug，而是服务端主动返回空。** 与公开资料一致：通达信公开服务器自 2026-09 起对 K 线 / 盘口 / 逐笔命令返回空，财务与 F10 照常。

因此 **"600000.SH 日线全历史逐行对拍 OHLC / 成交量 / 成交额" 一项无数据可对拍**；替代验证见 3.2（用分时聚合回推当日收盘与成交量，与本地 `.day` 对拍）。

本地基准：`H:\zxzq\vipdoc\sh\lday\sh600000.day`，6408 行，**最后一根 2026-10-19（文件 mtime 2026/10/19 15:53）**，即本地日线本身已落后 2 周。

### 3.2 分钟线（唯一可用通道）

| 测试项 | 结果 |
|---|---|
| 600000.SH 近 5 个交易日 1 分钟 | **1200 行（5×240）/ 49.2ms** |
| 单日单票 1 分钟 | 240 行 / **8.5~9.8ms** |
| 5 分钟线（近 20 日） | **不可用**（K 线通道死，且分时接口无 OHLC，无法聚合出 5 分钟 K 线） |
| 字段清单 | `price`（分钟收盘价）、`vol`（成交量，手）；mootdx 额外加一列 `volume`（与 `vol` 同值） |
| 是否含成交额 | **否**，无 `amount` |
| volume 单位 | **「手」**（与项目契约一致，无需换算） |
| 回溯深度 | **2001-01-02 起可回溯**（2000-01-04 及更早返回 0 行），单日固定 240 行 |
| 非交易日 | 返回 0 行（2026-10-31 周六、2026-01-02 均为空） |
| 今日盘中 | 2026-11-03 实时分时 145~148 行（13:24 时点） |

**单位/口径实证（对拍本地 `.day`）**：

| 日期 | Σ分钟 vol | 本地日线 volume | 末分钟 price | 本地日线 close |
|---|---|---|---|---|
| 2026-10-19 | 540,747 | 540,747.0 | 9.78 | 9.78 |
| 2026-10-16 | 922,942 | 922,942.0 | 9.73 | 9.73 |
| 2026-10-15 | 685,743 | 685,743.0 | 9.64 | 9.64 |
| 2010-01-04 | 661,913 | 661,913.38 | 21.19 | 21.19 |
| 2005-01-04 | 38,089 | 38,089.39 | 6.87 | **6.88** |
| 2001-01-02 | 12,490 | 12,490.0 | 20.92 | 20.92 |

- 分钟 `vol` 求和 == 日线 `volume`（差 < 1 手，仅小数舍入）→ **单位就是「手」**，无需 /100。
- 末分钟 `price` == 日线 `close`（6 个样本 5 个精确一致，2005-01-04 差 0.01 为价格精度差异）→ `price` 是**原始不复权收盘价**。
- 因为没有 OHLC/amount，**无法重建日线 OHLC 与成交额，也无法写入 `stock_minute`（该表要求 open/high/low/close/vol/amount）**；用 close 冒充 open/high/low 会违反项目「禁止伪造价格」硬约束。

### 3.4 复权

- mootdx **不提供 qfq/hfq**：`bars()` 无复权参数、返回体无复权字段，全部为原始价；
- 只提供 `xdxr()` 除权除息事件（88 条，字段 fenhong/peigujia/songzhuangu/peigu 等），理论上可自算因子，但项目已有本地 `stock_adj_factor` 快照，重复造轮子无收益；
- 结论：**mootdx 只能当原始价源（且 K 线已死）**，复权必须继续走本地因子表。

## 5. 吞吐与外推

| 场景 | 实测 |
|---|---|
| 单票 1 个交易日 1 分钟 | 8.5~9.8ms / 240 行 |
| 单票 5 个交易日 | 49.2ms / 1200 行 |
| 20 只 × 5 日（100 次请求） | **0.85s**，即 8.5ms/请求 |

**以下为外推（非实测）**：
- 全市场 6,924 只 × 1 个交易日 = 6,924 次请求 ≈ **59s**（单连接串行）；
- 全市场 × 20 个交易日 ≈ **20 分钟**；
- 全市场 × 5 年（约 1,200 交易日）≈ 830 万次请求 ≈ **19.6 小时**，落盘约 **20 亿行**（240×6924×1200）。

结论：只有"补最近若干天"的吞吐是可行的；长历史分钟全量补库不可行，且这 20 亿行还只是 close+vol，价值密度极低。

## 6. 接入设计要点（在"远程只做离线补数"约束下）

结论本身是「不值得接」，以下仅为"若坚持接入"的设计要点，供决策留档：

1. **Handler 位置**：`src/data/sources/mootdx/`（`client.py` 网络客户端、`handler.py` 继承 `DataSourceBase`、`schema.py` 字段映射）。`get_stock_data/get_index_data` **只读本地快照**（`data/local_store/minute/`），不联网；网络只出现在 `update_stock_minute()` 里，由 CLI 调用。
2. **开关**：新增独立开关 `data.mootdx_sync_enabled`（默认 `False`），**不复用 `allow_remote_sources`**。`DataService._init_builtin_datasources` 仅在该开关为真时注册 Handler；CLI 为 `scripts/sync_mootdx_minute.py --allow-network --codes ... --start ... --end ...`，一次性运行后退出。
3. **运行时不联网**：读路径保持「缓存 → 本地 Parquet 列存 → TDX `.day` → 禁止线上源」。mootdx 不进入 `DataFetcher` 运行时回退链，只在离线同步脚本里出现。
4. **单位与复权**：`vol` 已是「手」无需换算；`price` 为原始价，复权必须复用本地因子表，禁止把复权价落库。
5. **字段缺口**：只有 close+vol。若坚持写 `stock_minute`，open/high/low 只能取 close，属伪造价格、违反项目硬约束；唯一合规做法是新增 close-only 序列（如 `stock_minute_close`）或列可空 + `quality_flag='close_only'`，但会让分钟功能只能画"收盘价折线"，失去 K 线。
6. **回退**：节点池 3~5 个按延迟排序，单节点 3 次重试，全失败写 health 事件并返回明确错误（含节点清单）；同步失败不影响已有本地数据。
7. **增量**：以「代码 + 交易日」为水位，交易日集合取自本地日线 Parquet 的 `date`，只补缺口、幂等可重跑。

## 7. 替代方案（已实测）

| 方案 | 实测结果 |
|---|---|
| **腾讯 qfq 日线** `web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600000,day,,,800,qfq` | ✅ 801 行（2023-07-13 → **2026-11-03 含当日**），字段 date/open/close/high/low/volume，**自带前复权**，补本地日线 2 周缺口可行 |
| **腾讯分钟 K** `ifzq.gtimg.cn/appstock/app/kline/mkline?param=sh600000,m5,,320`（需 `Referer: https://gu.qq.com/`） | ✅ m1/m5/m15/m30/m60 各 320 根，**含 OHLC + 成交量**；但深度固定约 320 根（m1≈1.3 天、m5≈4 天、m30≈20 天） |
| AkShare `stock_zh_a_hist` | ❌ 临时装上 py-mini-racer 后调用东财接口被 `RemoteDisconnected` 断开；且本 venv 原本缺 `py_mini_racer`（akshare 在 Windows 声明的是 `mini-racer`，代码却 import `py_mini_racer`），`import akshare` 直接失败——这是**既有的环境缺陷**，与本次验证无关 |
| 通达信分时（mootdx） | ✅ 2001 年起长历史，但只有 close+vol |

**推荐**：
- **日线补库**：腾讯 qfq 日线（零新依赖、含复权、可拿到当日），按"显式 CLI 一次性同步 → 落本地列存"的方式接入，运行时仍只读本地；
- **分钟补库**：若只做近几天回看分析，腾讯 mkline（有 OHLC，但仅 320 根）；若必须 2001 年起的长历史，则只有通达信分时，且只能做"收盘价 + 成交量"研究，无法支撑 K 线渲染；
- **不建议**为了分钟线引入 mootdx：字段残缺 + 服务端已停供 K 线 + 库本身 2024 年后停更，维护风险高。

## 9. 最终回答

| 问题 | 结论 |
|---|---|
| 能不能接 | **不能接（作为数据源）**；仅"离线 1 分钟收盘+成交量"这一残缺口径有条件使用，但不值得为此引入依赖 |
| mootdx 版本与节点延迟 | 0.11.7；142 节点中 38 个可连（26.8%），TCP p50 29.6ms，协议层 p50 203.1ms，**0 个能取日 K** |
| 日线对拍偏差 | **无法对拍**（K 线接口全部返回空）；用分时聚合替代验证：收盘价 6/6 基本一致（1 处差 0.01），成交量合计差 < 1 手 |
| 分钟线回溯与 volume 单位 | 1 分钟可回溯至 **2001-01-02**，单日 240 行；volume 单位 = **手**；**无 OHLC、无成交额**；5 分钟线不可得；指数/ETF/北交所（market=2）均支持 |
| 200 次请求成功率 | **190/200 有数据、10 次为已退市标的空值、0 失败 0 超时**，p50 8.1ms、QPS≈105、未见限流 |
| 接入设计要点 | Handler 离线式（只读本地快照，网络仅在 CLI 同步）、独立开关 `data.mootdx_sync_enabled` 默认关、单位无需换算、字段缺口需 close-only 处理、节点池回退、按代码+交易日增量 |
| 替代方案 | **腾讯 qfq 日线**（实测可取到当日，含复权）补日线；**腾讯 mkline**（OHLC，仅 320 根）补近端分钟；AkShare 在本机不可达 |
