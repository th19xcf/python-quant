## 二、值得改但优先级次之

### P2-1 `src/data/quality` 与 `src/data/local_store.build` 双向依赖

- 证据：`src/data/quality/checker.py:144` 与 `src/data/quality/tradable_universe.py:453` 都从 `src.data.local_store.build` 延迟 import `discover_local_files`。
- 判定：全仓共 11 组循环依赖（见下节），**只有这一组是双向的**——quality 需要"文件发现"能力，而该能力落在 build（构建流程）里，属于放错位置。
- 收益：把 `discover_local_files` 提到 `local_store/paths.py` 或独立 `file_index` 模块后，双向依赖消失，quality 不再依赖构建入口。
- 代价：小。两处 import + 一处定义迁移，测试 `tests/test_data_quality.py` 需同步。建议在下次改这两处任一时顺带做，不必单独立项。

### P2-2 异常测试存在近重复 + 空断言

- `tests/test_exception_handling.py`：7 个测试、5 处 assert；`tests/test_exception_handling_optimized.py`：8 个测试、**1 处 assert**。两者 import 的是同一批 `src.utils.exception_handler` / `src.utils.exceptions`。
- 例：`test_exception_handling.py::test_global_exception_handler` 只调用 `setup_global_exception_handler()` 并打日志，无任何断言。
- 收益：不是"功能没测到"（真实逻辑另有用例），而是**空断言用例会抬高覆盖率棘轮的分母，让 68% 这个数字含水分**，与 `pyproject.toml:292-301` 里"不得靠空断言抬数字"的自述规则冲突。
- 代价：低。合并成一个文件、给每个函数补 `pytest.raises` / 返回值断言，或删除重复文件。
- 备注：本次全量扫出 48 个"字面无 assert"的测试函数，逐个人工抽查后绝大多数是合法正向用例（如 `tests/test_backtest_input_contract.py` 的 accepts 用例、`tests/test_fetch_margin_partial.py::test_complete_day_passes`），**不属于假绿**，不要按数量一刀切改。

## 三、不值得改（明确不建议投入）

1. **11 组循环依赖整体拆解**。AST 全图扫描结果（Tarjan SCC）：
   `data.local_store.build ↔ data.quality{,.checker,.tradable_universe}`、`data.risk_flags ↔ st_history ↔ st_name_history ↔ st_price_infer`、`tech_analysis.indicator_cache ↔ indicator_calculator ↔ indicator_manager`、`database.db_manager ↔ models.stock`、`data.atomic_write ↔ changelog`、`services.local_first_basic ↔ sync_fund`、`ui.chart_components.indicator_renderer ↔ ui.indicator_parameters`、`advice.config ↔ factor_sets`、`financials ↔ financials.collector`、`ui.main_window ↔ ui_manager`、`quant.learning.carry ↔ evaluator`。
   逐条核对后：**除 P2-1 那一组外，其余全部是函数体内延迟 import（带 `# noqa: PLC0415`），不存在顶层循环**，运行时无风险。为"图好看"去拆它们属于纯重构，改动面覆盖数据层与 UI，收益不可观测、回归风险实在。

2. **把 60 个直读 parquet 的文件统一收口到读取 API**。`LocalQuoteStore` 已有 `read_daily/read_daily_batch/factors/dividends`（`src/data/local_store/store.py:420-860`），但 `src/quant/analysis/*_local.py`、`src/data/quality/*`、`src/backtest/runner/compute.py:31-33` 等仍各自构造路径与列裁剪。统一抽象会掩盖各处的列裁剪差异、把 `scan_parquet` 的谓词下推变成对象调用，**很可能变慢**；且读取侧没有写入那样的落地风险。建议只在 P2-1 那样"能力放错位置"的具体点上局部收口。

3. **大文件拆分**（`tools/advice_stateful_backtest.py` 3,389 行、`tools/daily_update.py` 2,339 行、`src/backtest/engine/execution_core.py` 2,251 行、`src/data/managers/data_fetcher.py` 1,872 行）。这些是撮合内核/日更编排/多源取数，改动即触碰回测与数据口径。建议**只在该文件下次因业务原因被改时顺带拆**，不单独立项。

## 四、观察项（记录事实，非改单）

1. **依赖方向基本正确**：`src/core`、`src/data`、`src/backtest` 均未 import `src.ui`（0 命中）；`src/ui` 只依赖 `src.api` 协议与 `src.quant`。唯一反向是 `src/data/managers/data_manager.py:21` 从 `src/api.data_api` 取 `IDataProvider/IDataProcessor` 协议——这是接口层被实现层引用，符合六边形方向，不算违规。
2. **架构守卫有机制**：`tests/test_architecture_guard.py` 用 AST 扫描 + `FROZEN_WHITELIST`（仅 3 条，只减不增）冻结 UI→database/tech_analysis、advice→数据源实现两类越界，随 pytest 自动执行。这是本项目最有价值的一处治理设计。
3. **静默失败已被治理**：全仓 35 处 `except: pass/continue`，逐条看下来绝大多数是 `except ValueError: continue`（日期解析跳过脏行），关键的 `src/data/quality/clean_set.py:208,261` 都带"兜底理由"注释 + `logger.warning`。**没有发现无日志吞掉写盘/校验失败的情况**，无需整改。
4. **无硬编码绝对路径**：`src/` 内未出现盘符路径（命中项均为 HTTP URL）。路径集中在 `src/data/local_store/paths.py` 与各模块 `ROOT / 'data/local_store/...'` 常量。
5. **无 CI**：仓库无 `.github/`。`pyproject.toml:308` 自述"覆盖率闸门只有本地命令执行"，性能门禁 `-m perf` 默认被 `addopts` 排除（`pyproject.toml:164,166`）。质量门禁完全依赖本地纪律——这也是 P1-2 中"裸写差值不入退出码"值得留意但不强制的原因：本地已有一条致命级体检步骤兜底。
6. **性能**：日更最近一次全量 `714.7s / 17 步`（`daily_update_run.log` 尾部），步骤为子进程串行（`tools/daily_update.py:1458-1462`）。但取数受"单连接串行 + 节流"约束，并行化收益不确定，**不建议动**。同次日志里出现 `[changelog] 记账失败：PermissionError ... manifest.json`——属 Windows 文件占用导致的记账侧失败（数据已落盘），是可观测的健壮性小缺口，建议单独排查一次文件锁时序。
7. **重复实现**：`src/utils/dates.py`（46 处引用）与 `src/utils/date_utils.py`（2 处引用）功能重叠，后者可择机合并；ST 领域三模块（`st_history.py` 1,813 行 / `st_name_history.py` 951 行 / `st_price_infer.py` 955 行）职责分别是区间表、曾用名补充、价格推断，不算重复，但共享的路径构造与名称清洗值得抽公共函数。
