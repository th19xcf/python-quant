# 每日推荐筛选与判断清单

- **清单版本**：`2026-11-11.3`（与 `src/data/universe_filter.py:RULES_VERSION` 同一常量，每日输出会打印）
- **代码基准**：本文件按 2026-11-11 工作区实读整理；`src/advice/config.py` 的因子与权重正在由另一条任务调整，若两处不一致以代码为准，并按版本号回溯
- **每日入口**：`tools/daily_advice.py`
- **本文件随每日输出一起落盘**：清单 markdown / json 头部会打印规则版本号与本文件路径

> **每日出单 ≠ 每日调仓**。清单每个交易日重出，但持仓受最小持有期（中线 20 个交易日）、
> 卖出确认日（3 日）与单次单边换手上限（20%）约束，绝大多数标的在持有期内只显示「维持」。
> 只有「新进」「退出」对应需要处理的交易，且仍受换手上限压缩。

## 0. 一条命令 + 输出位置

```powershell
# 只读当日已有数据出清单
.venv\Scripts\python.exe tools\daily_advice.py

# 先增量更新行情再出清单（复用既有列存构建入口，不另写取数逻辑）
.venv\Scripts\python.exe tools\daily_advice.py --update
.venv\Scripts\python.exe tools\daily_advice.py --update --full-update --force   # 全量重建

# 指定信号日复算 / 自定义资金与输出目录
.venv\Scripts\python.exe tools\daily_advice.py --as-of 2026-11-09 --equity 1000000
.venv\Scripts\python.exe tools\daily_advice.py --out-root reports\advice\daily
```

输出（按信号日分目录，便于事后核对）：

| 文件 | 内容 |
|---|---|
| `reports/advice/daily/{YYYYMMDD}/daily_advice.md` | 可直接阅读的清单（数据状态、选池剔除、新进/维持/退出表） |
| `reports/advice/daily/{YYYYMMDD}/daily_advice.json` | 同内容结构化版本（含 `universe_filter` 全量剔除明细） |

退出码：`0` 正常 / `1` 数据更新失败 / `2` 未到收盘后 15:30 / `3` 数据 stale 被拦截 / `4` 数据不足无产出。

## 1. 数据状态（stale）与「数据没更新怎么办」

每日入口**必须先打印数据截止日与 stale 状态**，再出单：

- 判据来源：`src/data/quality/freshness.py::check_all` + 配置 `src/data/quality/freshness_config.json`，
  与 `tools/data_freshness_check.py` 同一套分级；
- 行情条目 `quotes_stock`：`freshness_field=meta/daily_index.parquet:end`（`data_type=stock`），
  `cadence=每交易日`，`warn_multiple=1`、`critical_multiple=3`；
- 落后 1 个交易日 → `warn`（可出单但必须显示）；≥3 个交易日 → `critical` → **拒绝出单**（退出码 3）；
- 终端与清单头部固定输出：`数据截止日: YYYY-MM-DD（A股日线行情，基准日 …）`、`数据状态: OK/WARN/CRITICAL，落后 N`；
- 显式放行：`--allow-stale`。放行后清单头部写入 `> [STALE] 数据未更新到基准日…不得当作当日信号使用`，
  退出码 0，但仍保留告警原文。

**数据没更新时的处理顺序**（不要直接拿旧数据出单）：

1. 看终端 `数据状态` 与环境里 `check_all` 给出的原因（配置缺失 / 覆盖不足 / 落后）；
2. 跑 `--update`（增量）或 `--update --full-update`（重建）；更新失败返回 1，先修取数；
3. 仍拿不到当日数据时，用 `--as-of <最新交易日>` 明确以旧日为信号日出单，或 `--allow-stale` 显式放行并标注；
4. 禁止把 stale 当作正常信号用于次日交易：清单里的「最早可执行日」按 T+1 计算，数据落后会让执行日已过期（`exec_status=expired`）。

### 2.1 指标打分层（全名单 / 方向 / 权重 / 缺失值）

打分 = 当日截面 1%/99% 去极值 → 标准化（z 截断 ±3）→ 按 `weight × direction` 加权 → 除以**非缺失因子权重和** → 截面百分位。

缺失值处置：**reweight，不填 0、不填均值、不插值**。该票在某因子的 z 为空时，该因子权重从分母剔除，用剩余因子重新归一；
历史不足 `lookback_days` 或停牌（`volume<=0`）先置空；全部因子缺失时 `score=null`，不参与候选（`src/advice/scoring.py:40-74`）。

默认产出档位为**中线 + 长线**（短线 `short` 在 `default_output_tiers` 中被排除，仅供历史回放，见 `src/advice/config.py:317-330`）。
`default_config(factor_set='extended')` 是默认入口（`src/advice/config.py:328`），因此上面的扩展因子集与 §2 的软筛选在默认运行里**是生效的**。
三档 legacy 因子与权重：

| 档位 | 因子（方向） | 权重 |
|---|---|---|
| 短线 short（仅观察） | momentum_1m(−)、volume_momentum_20(−)、ma20_gap(−)、rsi_14(−)、atr_pct(−) | 0.30 / 0.20 / 0.20 / 0.10 / 0.20 |
| 中线 mid（默认） | momentum_3m(−)、momentum_6m(−)、trend_slope_60(−)、sharpe_ratio_20(−)、volatility_20(−) | 0.30 / 0.15 / 0.20 / 0.15 / 0.20 |
| 长线 long | momentum_6m(−)、momentum_12m(−)、trend_slope_60(−)、sharpe_ratio_20(−)、max_drawdown_20(+) | 0.25 / 0.25 / 0.20 / 0.20 / 0.10 |

> `direction=-1` 表示**取值越低越看多**（反转/低波动风格），不是写错符号；`max_drawdown_20` 未标方向即 `+1`。
> 权重为空说明该档不启用；三档各自合计 1.00（`src/advice/config.py:207-279`）。

扩展因子集（`--tier` / extended 模式启用，20 日全样本门槛 + walk-forward 入选）：6 组 12 因子组内等权，
组间权重三档分别为 0.15/0.20/0.15/0.15/0.10/0.05（short）、0.15/0.15/0.15/0.10/0.10/0.05（mid）、

- reversal：`a101_020`

### 2.2 门禁层（IC）

- 触发条件：对当期打分做 20 日窗 RankIC 滚动监控，**连续 3 个窗口 RankIC<0** 且每窗有效配对 `MIN_PAIRS=30`（`src/advice/ic_monitor.py:29-32`）；
- 触发后行为：**只停本期新建仓（不产 BUY），不清空候选池、不影响已持仓的持有/卖出管理**（`ic_gate_decision` 返回 `block_new_buys=True`，`src/advice/ic_monitor.py:171-189`、`src/advice/pipeline.py:270-278`）；
- 样本不足不拦截（返回 `(False,'')`），信息写入门禁备注；
- 清单呈现：档位小结处打印 `门禁：IC监控(…)`，单条记录显示「IC门禁拦截新建仓；本条为持仓管理」。

### 2.3 风控层（行业上限 / HHI）

- 行业权重上限 **25%**、单票 **8%**、现金缓冲 **10%**（占总资金，`src/advice/config.py:84-105`）；
- 命中处置：**按比例压缩到上限**，不剔除标的（`src/advice/portfolio.py:79-126`）；行业口径为通达信二级桶，未知行业不受上限约束但会登记；
- 单票 ADV 参与率上限 **10%**（20 日均额），超限压缩下单量；
- **HHI 集中度在每日推荐链路未实现**：全项目仅 `src/risk/rules.py:492-505` 的 `MaxIndustryHHI`（默认 0.25，`src/risk/rules.py:37-40`）在回测风控规则里生效，`src/advice/` 没有任何调用。清单不声称每日推荐受 HHI 约束。

### 2.6 撮合层（涨跌停拒单）与选池的区别

- 位置：`src/backtest/engine/execution_core.py:1918 _check_order_executable`；
  涨跌停/一字板/停牌不可成交 → `execution_rules.is_tradable('not_tradable')`（`src/backtest/execution_rules.py:222`）
  → 订单转入 `expired_orders`：买单作废，卖单按 `blocked_sell_ttl_days` 重试（`execution_core.py:1950-1955`）；
- 涨跌幅口径：`ExecutionRules.resolve_limit_pct`（`execution_rules.py:130`）——主板 10%、创业板注册制改革后 20%、
  科创板 20%、北交所 30%；仅 10% 板块的 ST 收窄到 5%；
- 与选池的区别：选池是「**今天要不要把这只票放进候选**」（用 T 日及之前的数据做静态剔除），
  撮合是「**这笔单在 T+1 能不能成交**」（用 T+1 的开盘价/涨跌停判定）。同一只票可以在候选池里，但在 T+1 因涨停买不到而成为废单。
- 建议层（2026-11-11 按用户裁决改造）：`src/advice/eligibility.py::check_eligibility` 对买入侧 T 日涨停**不再拦截**，
  改为标记 `EligibilityResult.limit_up_risk=True` + `limit_up_basis`（哪个价触板 / 当日涨停价 / 幅度 / 一字板），
  条目照常进清单，`gate`（门禁状态）末尾追加「涨停风险（…，次日可能买不进）」，`risk_notes` 同步带出；
  口径分工是 **清单说策略想买什么，撮合层说实际能买什么**，两层不互相替代；
- 卖出侧跌停仍拦截：当日跌停说明次日按参考价卖出大概率失败（与买入侧不同，卖出不存在「等一天再看」的等价替代）。

### 2.7 可买只数时间序列（判断「空仓是市场状态还是规则冲突」）

- 落盘路径：`reports/advice/daily/available_counts.csv`（每日入口自动幂等追加，按 `(signal_date, tier)` 覆盖同一行）
- 写入位置：`tools/daily_advice.py::write_available_counts`；上游计数在 `src/advice/pipeline.py::_run_tier` 的 `funnel_*`
- 字段：`signal_date` 信号日、`tier` 档位、`universe_kept` 选池后只数、`panel_rows` 当日有行情只数、
  `soft_pass` 软筛选通过只数、`score_pass` 分数达买入分位只数、`all_gates_pass` 同时过分数/可交易/成本/风控/事件冷却只数、
  `new` 新进、`hold` 维持、`exit` 退出、`avoid` 观察、`ic_gate_blocked` 门禁是否拦截、`rules_version`、`generated_at`
- **唯一合法读法**：`score_pass` 高而 `all_gates_pass` 长期为 0 → 规则自相矛盾（门槛在打架）；
  两者都低 → 市场状态（例如全市场多头排列占比极低，2026-07-20 仅 7.4%）。
  单看「新进 0」不能下结论，必须看这两级计数。

| signal_date | tier | universe_kept | soft_pass | score_pass | all_gates_pass | new | hold | exit |
|---|---|---|---|---|---|---|---|---|
| 2026-11-09 | long | 4965 | 201 | 596 | 0 | 0 | 12 | 0 |
| 2026-11-09 | mid | 4965 | 201 | 497 | 3 | 0 | 15 | 0 |

  读法：`score_pass` 497 只达标、`all_gates_pass` 仅 3 只 → 主因是**软筛选**（201/4965 通过），
  不是分数门槛；3 只候选全部落在已持仓/未满确认期，故 `new=0`。

## 4. 为什么涨停不在选池里剔

- T 日涨停不代表 T+1 买不到：一字板确实买不到，但普通涨停次日往往能成交，若在选池阶段就剔除，等于**用 T 日的收盘状态预判 T+1 的可成交性**，会把大量可交易标的错误排除；
- 正确判定点在撮合层：用 T+1 的开盘价与涨跌停价比较，买不到就作废/顺延（见 §2.6）；
- 建议层也不再拦截（2026-11-11 改造）：`src/advice/eligibility.py::check_eligibility` 对 T 日涨停只打
  `limit_up_risk=True` 标记并给出判定依据，条目照常进清单——否则会出现「清单里没有、撮合层也没机会判定」的双重缺失，
  且清单与成交两侧口径不一致。

## 5. 清单字段含义

| 字段 | 含义 |
|---|---|
| 代码 / 名称 | `ts_code` 与本地名称快照；名称缺失时回退代码 |
| 得分 / 分位 | `score` 为档位内加权综合分（缺失因子已 reweight，非缺失权重归一）；`score_percentile` 为当日截面排名分位（0~1，越高越看多） |
| 建议动作 | `BUY`（新进）/ `HOLD`（维持）/ `SELL`（退出）/ `AVOID`（观察或不建议）；`(延后)` 表示被单次换手上限推迟 |
| 主要因子贡献 | 该档位权重最高的前 3 个因子的 `weight × direction × z`；负号表示该因子在当前取值下拉低得分 |
| 门禁状态 | 该条在 IC 门禁 / ST / 事件冷却 / 行业上限 / 流动性 / 换手上的实际结论（通过 / 拦截原因 / 延后到哪天） |
| 涨停风险（`limit_up_risk` / `limit_up_basis`） | T 日是否涨停。为真时条目**保留**在清单里，只提示「次日可能买不进」；`limit_up_basis` 给出依据（开盘价/收盘价 vs 当日涨停价、幅度、一字板）。能否成交由撮合层按 T+1 开盘价判定，清单不预判 |
| 建议持有期 | 档位 `min_hold_days`~`validity_days`（中线 20~60 个交易日），括号内为剩余有效天数 |
| 数据截止日 / 数据状态 | 见 §1；`stale` 时清单头部有 `[STALE]` 警示 |
| 选池规则版本 | `2026-11-11.1` + 本文件路径 |
