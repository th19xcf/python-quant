# 分红数据刷新指南

分红正式表两张：`data/local_store/factors/stock_dividend.parquet`（个股）与
`data/local_store/factors/fund_dividend.parquet`（基金）。刷新分两档：日频增量与
月度全量，二者互不替代。

## 一、日频增量（已在日更链路内）

日更第 7 步 `tools/refresh_dividend_daily.py`，非致命：只取除息日落在
「上次成功日 + 1 ～ 目标日」的增量。基金走 `ak.fund_fh_em` 年度批量，个股走
`ak.stock_fhps_em` 最近两个报告期；只追加/回填，不删行。实测约 20 秒。

```powershell
.venv\Scripts\python.exe tools/daily_update.py --apply --allow-remote
```

单跑本步（排障用）：

```powershell
.venv\Scripts\python.exe tools/refresh_dividend_daily.py --date 2026-11-18 --dry-run
.venv\Scripts\python.exe tools/refresh_dividend_daily.py --date 2026-11-18
```

## 二、月度全量（定时任务入口）

单一入口 `tools/refresh_dividend_monthly.py`，一条命令串行完成五个阶段。

完整命令（定时任务直接调用这一条）：

```powershell
.venv\Scripts\python.exe tools/refresh_dividend_monthly.py --apply --start-year 2016 --interval 2 --throttle 0.5
```

不带 `--apply` 即 dry-run，只打印阶段计划与预计耗时，不联网、不写盘：

```powershell
.venv\Scripts\python.exe tools/refresh_dividend_monthly.py
```

### 阶段与预计耗时

| 阶段 | 内容 | 预计耗时 |
|---|---|---|
| `stock_bulk` | `collect_stock_dividend.py` 按报告期（2016 年起约 43 期）全市场批量拉取，逐期缓存 | 约 8~15 分钟 |
| `fund_probe` | `probe_fund_dividend.py --all-funds` 基金逐只取证（1,696 只，每只 2 次请求，间隔 2s、只间隔 0.5s） | 约 90~150 分钟 |
| `fund_ingest` | `backfill_fund_dividend.py` 取证命中行入库 + 受影响基金因子重建 | 约 1 分钟 |
| `ledger` | `build_no_dividend_ledger.py --evidence` 重建无分红台账（仅在逐只取证完整时执行） | 约 1 分钟 |
| `stock_factors` | 仅对本次新增除息事件的个股重建复权因子并核对行情副本 | 约 1~10 分钟 |

全流程串行、不并发，总耗时约 **2~3 小时**，由基金逐只取证主导。
如需先试跑小批量：加 `--limit 50`（只影响本轮取证只数）。

### 断点续跑

- 阶段级断点：`work/分红月度全量_<日期>/state.json`，已完成阶段重跑时自动跳过。
- 基金逐只：`work/分红月度全量_<日期>/基金逐只取证/progress.csv`、`failed.csv`、
  命中行 `rows.csv`；中断后重跑同一条命令即从断点继续。
- 个股批量：`work/分红月度全量_<日期>/个股报告期批量/cache/` 逐报告期缓存 +
  `progress.json`，重跑不再重复请求已缓存报告期。
- 修复后重跑：直接重复执行上面的完整命令，不要删除工作目录（删了就得从零开始）。

### 限流与失败处理

- 基金逐只遇限流/封禁（`频率/429/403/too many` 等）时子工具返回 3，入口立即
  停手并保留断点，不推进后续阶段；等待一段时间后用同一命令续跑，**不要加压重试**。
- 个股批量单个报告期失败只记入 `failed.csv` 并继续其余报告期；报告期级失败可
  通过重跑（缓存命中已成功期）补齐。
- 取证阶段未跑完全量时 `ledger` 阶段自动跳过，保留旧台账，避免把已确认基金
  降级为「未确认」。
- 基金入库若发现取证代码与正式表部分重叠会拒绝覆盖并退出，需人工核对
  `rows.csv` 与正式表后处理。

### 写盘与回滚

- 基金：`backfill_fund_dividend.py` 走 staging 候选 → 逐值对拍 → `_backup/snapshots/`
  快照 → 原子替换 → 因子重建。
- 个股：`collect_stock_dividend.py` 合并后原子写，核验报告落在
  `work/分红月度全量_<日期>/个股报告期批量/verification.json`；因子重建在
  `stock_factors` 阶段完成。
- 回滚素材：`_backup/snapshots/` 下当日 `.bak.parquet` 与改前 CSV。
