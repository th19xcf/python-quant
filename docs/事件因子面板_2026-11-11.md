## 0. 结论摘要

1. `events.parquet` 共 185,653 行、6,061 只标的、2015-01-01~2026-11-11，`event_id` 唯一、无整行重复、无同日同类型多事件。
2. 表里**没有** `ann_date` 字段，唯一日期是 `publish_time`（公告披露时间）；14.7% 的行带真实时钟，其余为 00:00，**无法**用时钟区分盘中/盘后，统一按「T 日公告 → T+1 交易日可用」。
3. 点名的 8 类事件里，**4 类可用**（大股东增持、股权激励、并购重组、监管问询与立案）、**1 类部分可用**（业绩预告，仅 2025 年）、**3 类表内没有**（股份回购、定增与可转债发行、限售解禁）。没有硬凑。
4. 面板口径：τ=20/60 × 12 个事件类 × 3 种叠加规则；τ=20 主面板 8,003,705 行、τ=60 主面板 10,669,305 行，覆盖 5,721 只、2,880 个交易日（2015-01-05~2026-11-11）。
5. **`max` 与 `latest` 在单核单调衰减下数学恒等**（文件逐格一致，见 §5.2），三类叠加规则实际只有两种。
6. 推荐：多主体/可重复事件用 `sum`（增持、减持、股权激励、合同、分红），单一事项的进展类公告用 `max`（并购重组、监管处罚、立案问询、业绩预增/预减）。理由见 §5.4。
7. **业绩预告列在 2025 年之前是「无数据」不是「无事件」**，当 0 用会系统性压低事件强度（见 §3 W2）。
8. 四类缺口的补法（本地能否间接推 / 外部源与接口语义 / 补前如何标注）见 §9.1，建议并入《数据缺口登记》的条目见 §9.2（G-069 起）。

## 3. 使用警告（读面板前必须先看）

### W1 `max` 与 `latest` 是数学恒等，不是实现巧合

对同一事件类，衰减核 `w(d)=exp(-d/τ)` 只有 τ 一个参数、峰值为 1，且对 `d` **严格单调递减**。于是在任一交易日 `t`：

```
存在多事件 {a1 < a2 < ... < am}，各自权重 w(t-a_i+1) 随 a_i 增大而增大
⇒ max_i w(t-a_i+1) = w(t-a_max+1) = 「最近一条」的值
```

即 `max` 规则永远取到最近一条事件的权重，与 `latest` 逐格相等。实测两份文件 8,003,705 行逐格一致（§8）。**这不是 bug，也不是两条独立规则**；只有当开始给事件加**幅度权重**（金额、比例、股东数）或给不同子类设**不同 τ** 时，`max` 与 `latest` 才会分开。在那之前，讨论「三种叠加规则」实际只有两种（`sum` vs `max`）。

### W2 2025 年之前的业绩预告列是「无数据」，不是「无事件」

`ev_yoy_up` / `ev_yoy_down` 两列在 2015-01-01~2024-12-31 恒为 0，原因是**源表没有这段时间的业绩预告**（`coverage.json` 里 `em_yjyg` 通道只拉了 2025 一年），不是因为那些年没有预告——A 股每年 1 月都有大量年报预告。

- 把它当 0 用：2015–2024 年所有样本的「事件强度合计」会系统性偏低，任何以事件强度做横截面排序/加权的回测都会在这段区间得出**假的「事件稀疏期」**结论。
- 叠加一层语义损失：即使 2025 年，`ev_yoy_up` 也包含「扭亏」「续盈」，`ev_yoy_down` 也包含「首亏」「续亏」（来源后缀实测见 §9.1 G-072），方向反转信息已被抹平。
- 正确用法：① 只做 2025 年内的时间序列；② 做跨年面板时**整列剔除** `ev_yoy_up`/`ev_yoy_down`，或显式加 `is_available = trade_date >= 2025-01-01` 掩码并在因子定义里注明；③ 补齐源数据后再启用。
- 同理，`ev_equity_incentive` 在 §2.2 列出的 6 个月里为 0 也属「源缺失」，不要当「无激励事件」。

### W3 并购重组与监管处罚的「公告条数」不等于「事件强度」

- 并购重组 25,323 条 / 2,813 只，平均 9.0 条/只；同一重组事项会以「预案→反馈→过会→批复→实施」反复披露。
- 监管处罚剔除模板后仍有进展/补充类公告。
- 这两类若用 `sum`，强度会随披露频次膨胀（τ=20 下 `sum/max` 比值均值 1.28/1.19，p95 达 1.49/1.39）；本面板对它们默认用 `max`。

### W4 「不存在被处罚」类模板公告必须剔除

`监管处罚` 9,825 条里有 5,403 条（55.0%）是「关于最近五年不存在被证券监管部门和交易所采取监管措施或处罚情况的公告」这类再融资/IPO 问询回复里的**否定陈述**，若不清洗，会给大量正常公司凭空造出「监管处罚」脉冲。本面板在构建时已剔除（规则见 §4.4），但 `events.parquet` 原表**没有改**——任何人重新从原表建面板都必须重放这条清洗。

### W5 停牌日有脉冲、无行情

抽样 84,744 个 (date, code) 键中 2,503 个（3.0%）在该标的行情里没有对应 bar，全部落在该标的行情区间内部，即**停牌日**。脉冲在停牌日仍然存在（事件已发生），与收益面板 join 时这些行会自然消失，这是预期行为；不得把「join 后没有行」解释为「事件没发生」，也不要在 join 后把停牌日 fill 0 再回头当作事件强度下降。

### W6 面板末端截断

行情索引 `end` 到 2026-11-11，面板末日同此。之后发布的公告没有可用日，计数为 0；`_staging` 结果不可外推到 2026-11-11 之后。

## 4. 脉冲定义与参数

### 4.1 公式

```
w(d) = exp(-d / τ)
d    = 公告日之后第 d 个交易日（可用日 d = 1，即首日权重 exp(-1/τ)）
τ    = 20 或 60（交易日）
```

- τ=20：首日权重 0.9512，第 20 日 0.3679，第 60 日 0.0498。
- τ=60：首日权重 0.9835，第 60 日 0.3679，第 180 日 0.0498。
- `d` 从 1 起（严格按「公告日之后第 d 个交易日」），因此**峰值不是 1 而是 exp(-1/τ)**。若下游需要峰值为 1，把整列除以 exp(-1/τ) 即可，不改变横截面排序。

### 4.2 截断

`w < 1e-2` 截断，对应 `D = ceil(τ·ln100)`：

| τ | D（交易日） | 约合自然日 |
|---|---:|---:|
| 20 | 93 | 4.4 个月 |
| 60 | 277 | 13.2 个月 |

截断掉的尾部质量 ≤ 每事件峰值的 1%，但会累积：τ=60 时同一标的同类事件若 9 个月内再来 1 条，`sum` 的最大值可达 3.14（实测 `ev_dec` 峰值）。需要完整尾部时把 `FLOOR` 调小重跑，代价是面板行数线性增长。

### 4.3 两档 τ 的选择依据

- τ=20（≈1 个自然月）：对应「公告冲击的短期消化窗口」，与 A 股事件研究里常用的 20 日窗口一致；适合做短周期（月频）因子。
- τ=60（≈1 个季度）：对应「预期修正/资金行为的中期窗口」，覆盖一次定期报告间隔；适合季频因子。
- 两档都输出，不做二选一：τ 是超参数，应由下游因子检验决定（本轮不做）。

## 5. 叠加规则

### 5.1 三种规则

| 规则 | 含义 | 结果特征 |
|---|---|---|
| `max` | 同标的同类多条事件取当日最大权重 | 突出最近一次事件，不受披露频次影响 |
| `sum` | 权重直接相加 | 保留事件密度/多主体信息，可 >1 |
| `latest` | 只保留最近一条事件的脉冲 | **与 `max` 逐格相等**（§5.2） |

### 5.2 `max ≡ latest` 的验证

- 解析：见 W1。
- 数值：`pulse_tau20_max.parquet` 与 `pulse_tau20_latest.parquet` 行键完全一致、全部 12 列逐格相等；τ=60 同。验收项 `max_equals_latest=True`。

读法：

- 差异不是噪声而是**信息选择**：`sum` 把「一个月内两个股东增持」当更强的信号，`max` 把「同一重组发了 5 条进展」当同一个信号。

### 5.4 推荐规则（按类，写进主面板）

| 类 | 推荐 | 理由 |
|---|---|---|
| `ev_inc_big` / `ev_inc_insider` / `ev_inc_other` | `sum` | 多个股东分别增持是真实的强度叠加；表内 30 天去重已压掉重复公告，`sum` 峰值最高 1.81，未失控 |
| `ev_dec` | `sum` | 同上；减持主体多且常分笔披露，`sum` 保留密度 |
| `ev_equity_incentive` | `sum` | 一次激励可能同时有授予、调整、解锁多条，但都属于同一计划的不同阶段；`sum` 峰值 1.83，可接受 |
| `ev_contract` | `sum` | 多份合同是独立事件 |
| `ev_dividend` | `sum` | 中期+年度分红可叠加，`sum` 峰值 1.49 |
| `ev_merger` | `max` | 9.0 条/只的进展公告，`sum` 会把「披露勤快」当成「重组力度大」，τ=60 下比值 p95 达 2.75 |
| `ev_probe` / `ev_sanction` | `max` | 立案到处罚是同一事项的推进，`sum` 会重复计价；且惩罚性事件不宜线性累加 |
| `ev_yoy_up` / `ev_yoy_down` | `max` | 一年一（两）次、几乎不重叠，`sum` 与 `max` 差异 <17%，取 `max` 可与其它类保持「单事件峰值=1」的量纲 |

主面板 `pulse_tau20.parquet` / `pulse_tau60.parquet` 按此表逐类取规则；`ev_total` = 12 列之和（`ev_total` 最大 τ=20 为 4.12、τ=60 为 7.54，说明极端日会同时命中多类事件）。

若下游要做**等权事件组合**，建议改用 `*_max` 文件里的列自己拼，避免 `ev_total` 的类间量纲差异（`dec` 的 `sum` 峰值 1.94 与 `yoy_up` 的 `max` 峰值 0.95 不在同一尺度）。

## 9. 已知缺口与边界

### 9.1 三个缺失类 + 业绩预告：能不能本地推、外部怎么补、补前怎么标注

#### G-069 股份回购

**① 本地能否间接推：只能推「回购注销」，不能推「回购」**

- 本地股本变动表 `meta/factors/stock_shares.parquet`（`change_reason` 含「回购」）有 **11,018 行 / 2,816 只 / 1994-11-07~2026-11-05**，2015 年后 10,647 行；其中 10,860 行（98.6%）伴随 `total_share` 减少，即「回购股份注销完成」。
- 可信度：**低**。① 事件日是「注销生效日」，比回购预案公告晚 3–18 个月；② 大量回购进入库存股、不注销，完全不产生股本变动行（漏掉大部分回购）；③ 没有任何「回购金额/价格区间/进度」字段，无法定强度。
- 结论：可做「回购注销」代理列，**不能**替代「股份回购」事件。

**② 外部补：Tushare `repurchase`（doc_id=124）**

- 接口：`pro.repurchase(ann_date=..., start_date=..., end_date=...)`，日期格式 `YYYYMMDD`；不填参数单次默认返回 2,000 条。权限 2,000 积分，数据始于 2011 年、每日更新。
- 字段：`ts_code, ann_date, end_date, proc(进度), exp_date(过期日期), vol(回购数量), amount(回购金额), high_limit, low_limit`。
- **关键语义**：一个回购计划会以「股东大会通过 → 实施 → 完成」多次出现在同一 `ann_date` 下，`proc` 区分进度。做事件因子必须**按计划去重**（同 `ts_code` + 同 `exp_date` 只保留最早一条 `ann_date`），否则 `sum` 规则会把「披露次数」当「回购力度」——与 W3 的并购重组同型错误。
- 强度可用 `amount` 或 `vol/总股本` 加权，需自算分母。

**③ 补之前的事件因子标注**

- 面板里**不新增列**，在因子定义文档里写「股份回购：未覆盖（no coverage），不得解释为无回购」。
- 若临时需要，可新增 `ev_buyback_cancel_proxy`（来自股本变动，仅注销口径），并在列名与文档中保留 `proxy` 字样，禁止与真正的回购事件列混用。

#### G-070 定增与可转债发行

**① 本地能否间接推：定增可推「增发股份上市日」，可转债发行推不出**

- 定增：`stock_shares.change_reason` 含「增发」共 **7,921 行 / 3,629 只**，2015 年后 6,074 行；主因 `增发A股上市` 7,418 行。全部 7,921 行里 7,886 行（99.6%）伴随 `total_share` 正增，可据此算出新增股本。
  - 可信度：**中**。事件日 = 增发股份**上市日**，比发行公告晚约 1–4 周（发行结果公告 → 验资 → 上市），且「增发A股上市」不区分定向增发/公开增发（含 42 行新三板）。
- 可转债：`change_reason` 含「债转股」共 **18,820 行 / 966 只**，但这是**转股**（流通股本增加），不是发行；发行日、发行规模、票面利率均无本地来源。
  - 可信度：**不可用**（语义不同，不能替代）。
- 结论：定增可用股本变动做「上市日 + 新增股本」代理；可转债发行本地无解。

**② 外部补：Tushare 的实际情况**

- **Tushare Pro 没有独立的「定向增发」接口**（`tushare.pro/document/1?doc_id=108` 的股票接口清单里无此项，公司/股权类只有 `top10_holders`、`pledge_*`、`repurchase`、`share_float`、`stk_holdertrade` 等）。定增只能靠：① 公告文本（cninfo，本地 `events.parquet` 的 `title` 即来自该源，但没有独立类型，需按「发行结果暨股本变动公告」「非公开发行股票发行情况报告书」等标题重新分类）；② `stock_shares` 的增发上市日代理。
- 可转债发行：Tushare 债券接口 **`cb_issue`**（doc_id=186，2,000 积分），可取发行日、发行规模、利率、上市日等；`cb_basic` 提供条款与正股映射。
- 若走公告文本路线，必须先定义「同一事项的多份文件只算一条」的合并规则，否则重犯 W3。

**③ 补之前的事件因子标注**

- 定增：注明「仅 `ev_equity_issue_proxy`（上市日代理），缺发行预案日与发行规模，不得当定增公告日使用」。
- 可转债发行：标注「未覆盖」，不进面板；转股稀释是另一类事件（`债转股上市`），与「发行」不可混用。

#### G-071 限售解禁

**① 本地能否间接推：可以，且质量比回购/定增好**

- `stock_shares.change_reason` 含「限售/解禁」共 **24,323 行 / 5,676 只 / 1994-06-30~2026-11-05**，2015 年后 16,771 行；**24,045 行（98.9%）**伴随 `float_share` 正增，可用差分算出解禁股数。
- 主因：`首发限售股份上市` 10,594、`股权激励限售流通股上市` 6,214、`股改限售流通股上市` 4,585、`其他限售股上市` 1,271，其余为「战略配售上市 + 首发限售股份上市」等组合口径（354 行起）。
- **漏项提醒**：`网下配售股份上市` 有 9,496 行，语义上同属解禁，但字面不含「限售/解禁」，上面的正则没有覆盖；做代理时必须一并纳入，否则网下配售解禁会整段缺失。
- 可信度：**日期高 / 数量中 / 事件定义需裁剪**。
  - 日期：股本变动生效日即上市流通日，与真实解禁日一致。
  - 数量：`float_share` 差分可用，但同一行可能混入高管股份变动等其它原因（110 种 `change_reason` 组合），需按主因过滤。
  - 定义：其中 6,214 行是「股权激励限售股上市」，与本面板 `ev_equity_incentive` 是同一事项的不同阶段，**同时计入会双计**；`股改限售股上市` 主要发生在 2006–2014，2015 年后极少。
- 结论：可用「首发/战略配售/其他限售股上市」子集做代理，剔除股权激励与股改口径。

**② 外部补：Tushare `share_float`（doc_id=160）**

- 接口：`pro.share_float(ts_code=..., ann_date=..., float_date=..., start_date=..., end_date=...)`，`ts_code` 与 `ann_date` 至少填一个；单次最多 6,000 条；页面标注 120 积分起（接口清单页写 3,000，两处口径不一致，接入前需实测权限）。
- 字段：`ts_code, ann_date(公告日), float_date(解禁日), float_share(流通股份), float_ratio(占总股本%), holder_name, share_type`。
- **关键语义（与其它事件相反）**：`share_type` 含「定增股份 / 首发原始股 / 股权激励限售流通 / 首发战略配售股份 / 公开增发一般股份」等，说明解禁是**可提前预知**的事件——`ann_date` 是预案公告日，`float_date` 才是实际解禁日。用哪一天取决于因子假设：测「预期冲击」用 `ann_date`，测「解禁当日的供给冲击」用 `float_date`。本面板其余类都用公告日，接入时必须在文档里写明这一处例外。
- 强度用 `float_ratio`（已归一，不需自算股本）。

**③ 补之前的事件因子标注**

- 面板不新增列；因子定义里写「限售解禁：未覆盖」。
- 若临时用代理，列名 `ev_unlock_proxy`，并在文档注明「仅含上市流通日、已剔除股权激励与股改口径；不含解禁预案日，不可与 `ev_equity_incentive` 叠加使用」。

#### G-072 业绩预告只有 2025、业绩快报全缺

**① 本地能否间接推：不能**

- 2025 快照 4,543 行 / 3,096 只 / 2025-01-02~2025-12-31，按公告月分布：1 月 2,494、7 月 1,362、4 月 286、10 月 151，其余月份 13~58 条，符合「年报预告 + 一季报 + 中报 + 三季报」节奏，但只有一年。
- `title` 形如 `20241231 续盈`，是「报告期 + 类型」拼接，**不含公告标题**，因此无法从标题反推正文，也无法用标题匹配补全其它年份。
- 子类型被折叠：`title` 后缀实测为 预增 1,228 / 首亏 808 / 预减 703 / 略增 599 / 扭亏 570 / 略减 309 / 续亏 221 / 续盈 105；入库时只映射成两列（`业绩预增` = 预增+略增+扭亏+续盈 = 2,502，`业绩预减` = 预减+略减+首亏+续亏 = 2,041）。「首亏」与「预减」、「扭亏」与「预增」语义不等价，做因子时无法区分方向反转。
- 业绩快报（`express`）在本地**完全没有**（`events.parquet` 无对应类型，标题命中 0 条）。

**② 外部补：Tushare `forecast`（doc_id=45）+ `express`（doc_id=46）**

- `pro.forecast(ts_code=..., ann_date=..., start_date=..., end_date=..., period=...)`：输出 `ann_date`（公告日）、`end_date`（报告期）、`type`（预增/预减/扭亏/首亏/续亏/续盈/略增/略减）、`p_change_min`/`p_change_max`（预告净利变动幅度%）、`net_profit_min`/`net_profit_max`（万元）、`last_parent_net`、`first_ann_date`（首次公告日）、`summary`、`change_reason`。2,000 积分，单次 3,500 行。
- `pro.express(...)`：输出 `ann_date`、`end_date`、`revenue`、`operate_profit`、`total_profit`、`n_income`、`total_assets`、`diluted_eps`、`diluted_roe`、`bps`、`yoy_sales`/`yoy_op`/`yoy_dedu_np` 等同比率、`is_audit`、`perf_summary`。2,000 积分。
- **批量限制（影响补数方案）**：`forecast` 与 `express` 都只能按单只股票取历史，要按报告期批量拉全市场必须用 `forecast_vip` / `express_vip`（5,000 积分）。若按 5,000+ 只逐只调用，等于 5,000 次请求，必须按「同时最多 2 条、单连接串行 + 节流」执行，预计是小时级任务。
- **字段陷阱**：`express.yoy_net_profit` 是「去年同期修正后净利润」（金额），**不是**同比增速；同比增速用 `yoy_dedu_np`。
- **关键语义**：`ann_date` 是公告日（可 T+1 用），`end_date` 是报告期（不是事件日）；`type` 必须保留原始 8 类枚举，不能像本表一样只折叠成增/减——否则丢失「扭亏」「首亏」这类方向反转信息。`forecast` 另有 `first_ann_date`，可用于区分「首次预告」与「修正预告」，是重要的去重依据。

**③ 补之前的事件因子标注**

### 9.3 其它边界（不能用的地方）

1. **不能向前外推**：2015-01-01 之前无事件数据，任何"事件强度"在 2015 前无定义。
2. **不能把 0 当「无事件」的三处**：`ev_yoy_up`/`ev_yoy_down`（2025 前）、`ev_equity_incentive`（6 个缺月）、三类未覆盖事件（回购/定增/解禁）。
3. **不能当幅度用**：本面板所有类都是「单位幅度 × 衰减」，没有金额/比例加权；「一次增持 1 万元」与「一次增持 10 亿元」权重相同。要做幅度因子必须回到 `events.parquet` 结合公告正文或外部字段（当前表无金额列）。
4. **不能跨 τ 比较绝对值**：τ=60 的同一事件在首日权重 0.9835、τ=20 是 0.9512，且尾长不同；跨 τ 只能比排序与相关性。
5. **不能把 `ev_total` 当等权组合**：类间峰值差异大（`dec` 1.94 / `merger` 0.95），等权使用需先标准化。
6. **2026 年为不完整年度**：截至 2026-11-11，年度计数不可与整年比较。
