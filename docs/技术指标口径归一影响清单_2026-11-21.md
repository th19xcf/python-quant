# 技术指标口径归一：影响清单（第一阶段，2026-11-21）

> **本文件只做影响分析，未改动任何代码、数值或缓存。** 归一实现与重算待确认后执行。
> 前置登记见 `docs/技术指标双口径登记_2026-11-21.md`。

## 0. 结论摘要

- 两套实现的**公式源已经同一**（`src/tech_analysis/indicators/formulas.py`），分歧只在组装层：
  A 侧（`src/alpha`）用「窗口 shift(1) + ddof=0」，B 侧（factor_lib）用「当期窗口 + ddof=1」。
- 真正会变值的是 **6 类指标**：布林位置、ATR、均线/均线偏离、波动率、MA 交叉、MACD 量纲；
  RSI 与 KDJ 公式与窗口完全一致，**归一时数值不变**。
- 影响面分成两层：**生产建议链（A 侧）默认不受影响**（默认档位不启用 extended），
  **因子库研究报告（B 侧）需要重算**；纯估值/财务结论（EP+质量、中性化后超额）**不受影响**。
- 建议采用「**新旧列并存 → 小样本对比 → 一次性切换**」，回滚靠单提交 revert，不碰 `data/`。

## 5. 重算耗时与迁移策略

### 5.1 耗时

- 仓库内**无实测记录**：`docs/主机迁移本地数据清单.md:210,306` 明确写 `reports/factor_lib`
  可由 `python -m src.quant.factor_lib --size 80` 重算，但**耗时未实测**。
- 建议先以 `--size 80` 计时一次（单进程、串行），再按全市场（约 5,000 只）线性外推；
  不建议在清单阶段给出未经测量的数字。
- advice extended 档位的 replay 同样无实测基线，需单独计时。

### 5.2 迁移方案对比

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A 一次性切换 | 直接把 B 侧 spec 改成 A 侧语义，重算全部报告 | 改动小、一次到位 | 报告数字整体跳变，无法逐因子归因；出问题只能整批回滚 |
| **B 新旧列并存（推荐）** | 新增 `tech_*_v2` spec（A 口径），旧 spec 原样保留；先只入评估，对比 IC/分层后再切换 | 可逐因子对拍、结论可解释、回滚只需删 v2 | 因子表短暂扩容 11 行 |

**推荐 B**：归一的目的是消除口径分叉，不是省 11 行代码；并存一轮能用同一数据直接量化
「错位一期 + ddof」对 IC/换手的影响，避免把研究结论的变动误判为模型问题。

## 6. 建议切换顺序与回滚

1. **冻结**（已完成）：白名单守卫 `tests/test_tech_indicator_dual_track_guard.py`。
2. 新增 `tech_*_v2` spec，仅注册、不进 `enabled_extended_columns()`；`src/alpha` 不动。
3. `--size 80` 跑旧/新两套，产出逐因子对比表（IC、ICIR、单调性、分层收益、冗余聚类）。
4. 检查差异方向是否与「错位一期 + ddof」预期一致；不一致则停手排查。
5. 一次性把生产评估切到 v2，重算 `reports/factor_lib/*`（旧报告先整体复制到 `work/` 备份）。
6. 若启用 extended：重跑 advice replay + IC 门禁，对比 tier 命中率。
7. 更新登记文档与因子登记表（标注 v2 口径），旧 spec 保留一个版本后删除。

**回滚**：全程不改 `data/`；切换以单个提交完成，`git revert <hash>` 即回到旧口径；
`reports/factor_lib` 为可再生产物，回滚后重跑命令即可恢复，不涉及数据恢复。
