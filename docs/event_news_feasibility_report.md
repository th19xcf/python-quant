# 网络舆情与公告事件：可行性验证报告

> 范围：公告事件 + 宏观/主题新闻事件 → 板块映射。只做研究与最小试点，**不接入生产推荐流程**。
> 数据截止：行情 2026-11-02（股票日线多数至 2026-10-19），公告样本 2025-01-01 ~ 2025-12-31。
> 本文所有脚本与结果位于 `research/events/`，未修改 `src/` 下任何生产代码。

## 一句话结论

这件事值得做，但只能当「排雷」用、不能当「选股」用：并购重组、重大合同/中标、监管处罚这三类公告发布之后，股票大概率跑输大盘，适合用来把标的从推荐清单里剔掉；而「降息买券商地产、中东打仗买黄金、两会买基建」这类常识映射，绝大多数经不起检验，只有「美联储降息买银行」勉强成立；减持、增持、业绩预增预减这几类，换个算法结论就反过来，现在还不能信。

## 0. 先看结论：三类判断

| 判断对象 | 结论 | 依据强度 |
|---|---|---|
| 公告事件数据 | **可直连**，巨潮资讯可稳定抓取，无需凭证；但披露时间 96% 只有日期没有时分 | 强 |
| 分钟级新闻源 | **可直连**，东财快讯最优（秒级+原文链接），财联社/新浪需自己拼链接 | 强 |
| 研报数据 | **可直连**，但只有日期没有时分，不适合做事件时点 | 中 |
| 股吧/雪球舆情 | **不建议**，无稳定公开接口、噪声大、合规风险高 | 强 |
| 公告事件做「风险过滤」 | **值得做**：并购重组、重大合同/中标、监管处罚三类方向稳定 | 中（受模型口径影响） |
| 公告事件做「正向加分」 | **不值得做**：没找到稳定的正向超额 | 强 |
| 宏观事件→板块映射 | **基本不建议直接接入**：22 条映射里 13 条样本不足、6 条不成立、2 条显著反向、仅 1 条成立 | 中 |
| 接入选股打分体系 | **只接风险过滤项**，不进正向权重，不做黑箱模型 | — |

## 1. 数据源可行性

### 1.1 结构化公告（优先级最高）

| 数据源 | 接入方式 | 时间戳精度 | 原文链接 | 稳定性 | 结论 |
|---|---|---|---|---|---|
| 巨潮资讯 `hisAnnouncement/query` | POST 表单，公开页面接口 | `announcementTime` 毫秒时间戳，但历史记录约 96% 为 `00:00:00` 占位 | `adjunctUrl` 拼 PDF | 单次 pageSize 上限 30；连续约 1000 次请求后返回 403，需限速+退避 | **可直连（推荐主源）** |
| 东方财富 `np-anotice-stock/api/security/ann` | GET 公开接口 | `display_time` 毫秒、`eiTime` 秒，**历史部分为空**；`notice_date` 常比真实发布时间晚 1 个自然日 | 有 | 高频触发 567 拦截；`page_index` 上限约 100 页 | **可直连（备源，不建议当主源）** |
| 上交所/深交所官网披露 | 无正式公开 API，页面抓取需遵守使用条款 | 页面显示到分 | 有 | 反爬策略不透明 | **需授权/需评估合规** |

实测：2025 全年 8 个关键词抓取 26,115 条公告，耗时 292 秒，无凭证、可复现。

**关键限制**：公告披露时间在巨潮历史数据里绝大多数是 `00:00:00`，意味着**无法区分盘中发布与盘后发布**。本报告统一采用「发布日期之后的下一个交易日」为事件日 0，属于偏保守处理，代价是盘后公告的真实首日反应被推迟到 T+2，CAR0 被低估。若要精细化，只能换用东财的秒级时间戳（覆盖不全）或实时监听。

### 1.2 财经新闻与研报

| 数据源 | 接口 | 时间戳 | 原文链接 | 结论 |
|---|---|---|---|---|
| 东方财富快讯 | `ak.stock_info_global_em` | 秒级（`2026-11-03 14:43:35`） | 有 | **可直连，首选** |
| 财联社电报 | `ak.stock_info_global_cls`；原始 `v1/roll/get_roll_list` | AkShare 封装只给 `HH:MM:SS`（丢日期）；原始接口 `ctime` 到秒 | AkShare 无链接列；原始接口有 `id`/`shareurl`，可拼 `https://www.cls.cn/detail/{id}` | **可直连（需自己拼链接）** |
| 新浪财经 7x24 | `ak.stock_info_global_sina`；原始 `zhibo.sina.com.cn/api/zhibo/feed` | 秒级 | AkShare 无链接列；原始接口有 `docurl` | **可直连（需自己拼链接）** |
| 东财研报 | `ak.stock_research_report_em` | 只到天 | 有 PDF | **可直连，但只适合做预期修正，不能做事件时点** |

实测样本（2026-11-03 盘中）：财联社 20 条、东财快讯 200 条、新浪 20 条、研报 227 条，全部无需登录、无需 key。抽检可见「乌克兰能源公司遭袭后紧急停电」「世界黄金协会：三季度各国央行购金创新高」等，具备映射到板块的语义基础。

**为什么不跑长期爬虫**：新闻源都有频率限制与版权约束，本次仅做单次小样本探测，验证「有接口、有秒级时间、有链接」三件事，不做长期采集。

### 1.3 社媒舆情

| 数据源 | 结论 | 原因 |
|---|---|---|
| 东方财富股吧 | **不建议（本期不做）** | 无公开 API，反爬强；帖子重复、情绪噪声极高；转载与存储涉及用户生成内容合规问题 |

### 2.3 类型枚举（本期已实现）

公告：`业绩预增`、`业绩预减`、`增持`、`减持`、`股权激励`、`重大合同/中标`、`并购重组`、`监管处罚`、`分红送转`。

宏观：`美联储降息`、`中国降准降息`、`两会`、`地缘冲突`、`中美贸易摩擦`，另有 13 类在映射表中标注「待验证」。

**抽取方式**：本期全部用「关键词 + 标题正则」实现（见 `announcement_event_study.py` 的 `KEYWORD_TO_TYPE` / `TITLE_FILTERS`），未引入模型。好处是可解释、可回溯、零依赖；代价是召回依赖标题写法，后续可加模型做兜底，但必须保留原文链接。

## 3. 公告事件研究（试点）

### 3.1 方法与防未来函数

- 估计窗 `[-120, -20]`（101 个交易日，有效样本 ≥60）；事件窗 `[-5, +20]`。
- 主口径：市场模型（OLS 估计 `alpha`/`beta`），基准沪深 300（`000300.SH`）。
- 对照口径：市场调整模型（`beta=1`）。
- CAR 分点：0 / +1 / +5 / +20 日；日 0 的 AR 用「开盘→收盘」收益减基准同区间收益。
- 建仓价：**事件日 0 的开盘价**（T+1 开盘）。事件日 0 = 发布日期之后的下一个交易日，盘后/夜间发布自然落到 T+1；两会这类「开盘前已知」事件用显式 `trade_day`。
- 显著性：t 检验 + Bootstrap（1000 次，2.5%/97.5% 分位）。
- **按事件日期聚类**：同一天大量公告会让横截面收益高度相关，naive t 值严重夸大。因此同时给出「合并均值」和「日期加权均值」，**以日期聚类的 `t_date` 与 `ci_low_date/ci_high_date` 为准**。

### 3.4 模型口径敏感性（必须看）

同一批事件改用市场调整模型（`beta=1`）后，结论会翻转：

| 事件类型 | +20 日市场模型（主口径） | +20 日市场调整模型（对照） |
|---|---|---|
| 减持 | -1.13%（t_date -3.12） | **+2.45%**（t_date +8.00） |
| 并购重组 | -3.81%（t_date -5.63） | +0.40%（t_date +0.63） |
| 重大合同/中标 | -1.43%（t_date -3.64） | +1.23%（t_date +1.34） |
| 监管处罚 | -1.83%（t_date -1.88） | +1.78%（t_date +2.20） |
| 业绩预增 | +0.34%（t_date -1.38） | +4.95%（t_date +3.75） |

原因：样本期 2025 年是单边上涨行情，而这些事件股的平均 beta 在 1.09~1.29 之间。`beta=1` 的市场调整模型少减了约 `(beta-1)×市场涨幅`，20 日维度足以造成 1~3 个百分点的系统性高估，甚至把负超额翻成正超额。

**处理原则**：以市场模型为主口径；市场调整模型只作对照。两个模型方向一致且主口径显著的事件，才可采信。

| 业绩预减 | 20 日合并均值 +3.26%（naive t=9.48） | 日期加权后 -0.87%（t=-0.62）。1896 条事件只有 74 个发布日，同日公告高度相关，naive t 是假的；市场调整模型又给 +7.09%，纯 beta 放大 |

| 减持 | 20 日市场模型 -1.13% 显著 | 市场调整模型 +2.45% 显著，方向完全相反；不能用 |
| 增持 | 5 日 -0.50%（t=-2.18） | 幅度极小，20 日转为不显著，且与市场调整模型冲突；不建议 |
| 分红送转 | 1 日合并 +0.46%（naive t=8.09） | 日期加权 -0.06%；除权除息机制干扰，不构成可交易规律 |
| 股权激励 | 全窗口不显著 | 无规律 |

**样本不足 / 无法判断**

- 牛熊分段形同虚设：2025 年样本几乎全在牛市区间（减持 6504 牛 / 59 熊，并购重组 929 / 9，股权激励 935 / 0）。本报告的「牛熊分段」只能证明「熊市样本太少、不能下结论」，必须补 2018、2022 等年份才能做真正的分段对比。
- 事件窗外的漂移（-5 ~ -1 日）未纳入，故不能回答「公告前是否已抢跑」。
- 北交所、次新股、停牌股因估计窗不足被剔除，结论只覆盖主板/创业板/科创板中流动性正常的部分。

### 4.4 对用户关心的三个典型案例的回答

**① 中东冲突 → 黄金上涨？**
5 次冲突样本（2022 俄乌、2023 巴以、2024 伊朗以色列、2025 两次中东升级），黄金 ETF 5 日平均 CAR **-1.15%**，胜率 40%，方向相反但不显著。**结论：样本不足，且现有样本不支持「冲突→黄金」的即时映射**。可能原因是事件日之前避险已被抢跑、冲突多为已知冲突的延续；但这只是推测，不能当结论。军工 +1.51%（胜率 60%）方向对但不显著；油气 -1.39%，同样不显著。**这一类需要扩样本（把 2014、2019、2020 年的冲突补进来）才可能得出结论。**

**② 中国两会 → 哪些板块受影响？**
两会映射到消费、基建、科技、军工。消费 5 日 +0.16%（t=0.34）不成立；基建样本仅 4 个（ETF 上市晚）；科技 6 个、军工 9 个，均样本不足且方向为负。**结论：两会作为「事件」没有可交易的板块超额；会议内容（政府工作报告的具体提法）比会议时点更重要，这已经不是事件研究能回答的问题。**

**③ 美联储议息 / 降准降息 → 券商、地产、银行？**
- 美联储降息：银行 +2.38%（t=2.73，胜率 81.8%）**成立**；券商 -1.21% 不成立；地产 **-5.13%（t=-2.34，胜率仅 9.1%）显著反向**。
- 中国降准降息：券商 +0.51% 不成立；银行 -0.07% 不成立；地产 **-2.28%（t=-2.21，胜率 15.4%）显著反向**。

**结论：市场共识里「降息→券商地产」是伪规律，尤其是地产——11 次/13 次事件里只有 1~2 次跑赢，平均跌 2%~5%。唯一站得住的是「美联储降息→银行」，但它是弱先验（息差扩张），且 11 个样本里 9 个牛市、2 个熊市，稳健性有限。**

### 4.5 牛熊分段（宏观）

- 美联储降息→银行：牛市 9 次均值 +2.06%（t_bull 2.36），熊市 2 次 +3.82%（t 1.10）；方向在两个区间都为正，但熊市样本仅 2 个。
- 中国降准降息→地产：牛市 4 次 -1.07%（t=-0.80，不显著），熊市 9 次 -2.82%（t=-2.05）；负向漂移在熊市更明显。
- 地缘冲突→黄金：牛市 3 次 vs 熊市 2 次，分组样本过少，不具解释力。

**宏观结论**：只有「美联储降息→银行」勉强经得起检验；「降息→地产」是稳定的**反向**信号（可作风险提示，但不能做多）；其余要么不成立，要么样本不足。**不建议把宏观映射直接做成推荐清单的加分项。**

## 5. 结论与最小落地方案

### 5.1 是否值得接入

| 用法 | 判断 | 理由 |
|---|---|---|
| 正向加分（事件因子进 `FactorSpec`） | **不做** | 没找到稳健的正向超额；唯一正向的「美联储降息→银行」样本太少，且是板块级不是个股级 |
| 风险过滤（负面事件冷却期） | **做，最小化接入** | 并购重组、重大合同/中标、监管处罚三类方向稳定，且过滤误杀成本低 |
| 黑箱模型（舆情打分直接调权） | **不做** | 不可解释、不可回溯，且本期没有舆情数据 |

### 5.2 最小落地方案（不改生产流程，只加一个过滤钩子）

**第一步：事件入库表（SQLite/Parquet 均可，字段与 §2 一致）**

```sql
CREATE TABLE event_announcement (
  event_id           TEXT PRIMARY KEY,
  ts_code            TEXT NOT NULL,
  stock_code         TEXT NOT NULL,
  short_name         TEXT,
  event_type         TEXT NOT NULL,
  publish_time       TIMESTAMP NOT NULL,
  time_precision     TEXT NOT NULL,          -- minute / date
  is_after_close     BOOLEAN,
  source             TEXT NOT NULL,          -- cninfo / eastmoney
  source_url         TEXT,
  title              TEXT NOT NULL,
  polarity           TEXT NOT NULL,          -- positive / negative / neutral
  extract_method     TEXT NOT NULL,          -- keyword / regex / model
  confidence         REAL NOT NULL,
  dedup_key          TEXT NOT NULL,
  trade_eligible_date DATE NOT NULL,
  created_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE event_macro (
  event_id        TEXT PRIMARY KEY,
  publish_time    TIMESTAMP NOT NULL,
  event_type      TEXT NOT NULL,
  event_subtype   TEXT,
  region          TEXT,
  affected_sectors TEXT,                     -- JSON array
  affected_commodities TEXT,                 -- JSON array
  polarity        TEXT NOT NULL,
  keywords        TEXT,                      -- JSON array
  source          TEXT NOT NULL,
  source_url      TEXT NOT NULL,
  summary         TEXT,
  extract_method  TEXT NOT NULL,
  confidence      REAL NOT NULL,
  trade_day       DATE NOT NULL
);

CREATE TABLE event_sector_map (
  event_type      TEXT NOT NULL,
  sector_tag      TEXT NOT NULL,
  market_direction TEXT NOT NULL,            -- + / -
  strength        TEXT NOT NULL,             -- 强 / 中 / 弱
  etf_code        TEXT,
  source          TEXT NOT NULL,
  status          TEXT NOT NULL,             -- 已检验 / 待验证
  tested          TEXT NOT NULL,             -- yes / no
  rationale       TEXT,
  conclusion      TEXT,                      -- 成立 / 不成立 / 显著反向 / 样本不足 / 未检验
  PRIMARY KEY (event_type, sector_tag)
);

CREATE TABLE event_factor_daily (
  trade_date      DATE NOT NULL,
  ts_code         TEXT NOT NULL,
  event_type      TEXT NOT NULL,
  event_id        TEXT NOT NULL,
  days_since_event INTEGER NOT NULL,
  filter_flag     INTEGER NOT NULL,          -- 1 = 负面冷却期内，应剔除
  severity        REAL NOT NULL,
  PRIMARY KEY (trade_date, ts_code, event_type, event_id)
);
```

**第二步：每日增量**

| 时点 | 任务 | 说明 |
|---|---|---|
| 17:00 | 抓当日公告（cninfo，增量按日期） | 写入 `event_announcement`，`trade_eligible_date` = 下一交易日 |
| 每小时（盘中） | 抓东财快讯增量（按 URL 去重） | 只入库，不参与当日交易 |
| 17:30 | 生成 `event_factor_daily` | 对每只股票汇总「冷却期内负面事件」 |
| 08:30 | 补一次隔夜新闻 + 生成当日过滤名单 | 盘前可用 |

冷却期（只在方向稳定的三类上启用）：
- 并购重组：事件日 0 起 20 个交易日；
- 重大合同/中标：事件日 0 起 5 个交易日；
- 监管处罚：事件日 0 起 5 个交易日；
- 其余事件类型暂不启用（标记 `filter_flag=0`），只记录不生效。

**第三步：挂接点**

- 风险过滤：`src/advice/eligibility.py` 的 `check_eligibility()` 增加一段「当日存在冷却期内负面事件 → `blocked.append('事件冷却期')`」。只读 `event_factor_daily`，不改因子面板结构，失败时降级为不过滤。
- 正向因子：**本期不挂**。若后续验证出稳定正向事件，再在 `src/advice/config.py` 的 `FactorSpec` 增加一个 `event_score` 列，权重起步 0.05，并保留「无事件填 0」的语义。
- 宏观映射：只做展示/提示（如自选页提示「今日美联储降息，银行板块历史胜率 82%」），**不进打分**。

**第四步：验证门槛（接生产前必须满足）**

1. 事件样本跨至少 3 个年份、包含熊市区间；
2. 市场模型与市场调整模型方向一致；
3. 日期聚类 t 值 \|t\|≥1.96，且 Bootstrap 区间不跨 0；
4. 加入交易成本（双边 0.1%~0.2%）后仍显著；
5. 过滤后推荐清单的收益/回撤不劣于未过滤版本。

## 6. 数据缺口与限制

| 缺口 | 影响 | 处理 |
|---|---|---|
| 公告时间 96% 为 `00:00:00` | 无法区分盘中/盘后，CAR0 低估，T+1 偏保守 | 明确标注口径；后续接东财秒级或实时监听 |
| 2016~2019 年部分 ETF 未上市 | 两会、早期降息事件的板块样本缺失 | 在结论中标注「样本不足」，不插值 |
| 本地无申万行业指数 | 只能用行业 ETF 代理板块 | 已说明；后续补申万指数可提升粒度 |
| 无商品期货数据 | 无法检验「大宗暴涨→上游资源」的直接链条 | 该映射标为「待验证」 |
| 样本期仅 2025 年（公告）/ 2016~2025（宏观） | 牛熊分段几乎只有牛市 | 不把牛熊对比当结论；需补历史 |
| 单一数据源（公告以巨潮为主） | 可能有遗漏/标题口径差异 | 保留东财备源；后续做双源核对 |
| 未计交易成本与冲击成本 | 负向漂移幅度较小的事件可能不经济 | 落地前加成本回测 |

**声明**：本报告不使用任何抓取凭证、私有密钥或付费数据；所有数值来自 `research/events/data/` 下的 CSV/Parquet，可复现。
