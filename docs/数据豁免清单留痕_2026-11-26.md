# 质量豁免清单留痕（2026-11-26）

## 1. 来源与定位

`data/local_store/meta/anomalies/quality_exemptions.csv` 是巡检的「已知违规基线」，
由 `src/data/quality/exemptions.py` 读写，**不在 Git 跟踪范围内**（`data/local_store/`
整体被 `.gitignore` 排除）。因此本文档是该文件在本轮的**版本化镜像记录**：CSV 是
运行时事实源，本文档只留痕「本次登记了什么、依据是什么、怎么复现与校验」，不复制
全表（尚有 6,000+ 条更早的基线记录）。

台账本身被 `data/local_store/meta/anomalies/manifest.json` 的 `files` 条目覆盖
（`rows` / `bytes` / `sha256`），所以改这份 CSV 必须同步回写 manifest，否则日更
核对会报不一致。

### 判断依据：入库错误，不是单位缺失

按 `src/data/quality/rules.py` 的规则复算 2006-07-13 当日 26 行：

- `amount` 取值从 **7.0 元** 到 **18,025,600.0 元** 乱跳，`amount/(close×volume×100)`
  落在 **1e-6 ~ 8.87e-2**（正常应为 1 附近），没有任何**固定比例**关系。
- 若属「单位缺失」（如少乘 100 / 10,000），同日同批行应表现为**同一个常数倍**偏移；
  实际倍率千差万别，故判定为**入库错误**（成交额字段被写入无关数值），而非单位换算缺失。
- 反例（`000417.SZ`）：当日 `close=3.98`、`volume=56,764.46` 手，正常成交额应约
  `3.98×56,764.46×100 ≈ 2,259 万元`，但库里 `amount=20` 元，相差 6 个数量级；
  同批 `000049.SZ amount=1546`、`000514.SZ amount=67`、`000528.SZ amount=173` 也是同类残值。
- 源端坏值不可反推真实成交额，故**不修数据**，只登记豁免，使其不再被当作新增回归。

## 3. 复现方式

### 3.1 复算命中行（只读，不写盘）

```python
# 用规则本体复算，保证与巡检口径一致（逐标的调用，规则输出不含 ts_code）
import sys; sys.path.insert(0, '.')
from pathlib import Path
from datetime import date
import polars as pl
from src.data.quality.rules import RuleContext, rule_amount_dimension, rule_vwap_out_of_range

root = Path('data/local_store/quotes/stock')
ctx = RuleContext()
target = date(2006, 7, 13)
for path in sorted(root.rglob('*.parquet')):
    df = pl.read_parquet(path, columns=['date', 'high', 'low', 'close', 'volume', 'amount'])
    hit = df.filter(pl.col('date') == target)
    if hit.height and (rule_amount_dimension(hit, ctx).height
                       or rule_vwap_out_of_range(hit, ctx).height):
        print(path.stem)
```

### 3.2 重新生成 CSV

`quality_exemptions.csv` **不能用全量覆盖重建**：`python -m src.data.quality baseline
--confirm REBASELINE` 只会把当前 error 级违规写成新基线，会丢光历史条目。正确做法是
用 `read_exemptions` 读全量、追加本轮记录、再 `write_exemptions` 原子落盘（去重 + 排序）：

```python
from datetime import datetime
from src.data.quality.exemptions import (
    DEFAULT_EXEMPTION_PATH, ExemptionRecord, read_exemptions, write_exemptions)

old = read_exemptions(DEFAULT_EXEMPTION_PATH)
stamp = datetime.now().isoformat(timespec='seconds')
extra = [ExemptionRecord('amount_dimension', c, '2006-07-13', reason_amt, stamp) for c in amt_codes]
extra += [ExemptionRecord('vwap_out_of_range', c, '2006-07-13', reason_vwap, stamp) for c in vwap_codes]
print(write_exemptions(list(old) + extra, DEFAULT_EXEMPTION_PATH))  # 幂等：重复跑不增加条目
```

### 3.3 回写 manifest + 校验一致性

CSV 写入后，manifest 里的 `rows` / `bytes` / `sha256` 必须按磁盘实测回写（用既有通用实现，
不要手改 JSON）：

```python
from pathlib import Path
from src.data.manifest_refresh import refresh_manifest_files
```

校验（只读）：

```

```

仍核 bytes/sha256）/ **不一致 0 条** → `PASS`，即日更不会把本次登记报成「预期外改动」。

相关单测：`pytest tests -q -k "exempt or anomaly"` → 25 passed。

## 4. 与 `rules.py` 北交所标注的关系

`src/data/quality/rules.py::rule_vwap_out_of_range` 的 docstring 里加了一段「已知问题（不修）」：
北交所（`920` 开头）源端 `amount` 与 `volume` 口径不一致，按 `amount/(volume×100)` 算出的
均价会轻微越出 `[low, high]`，属**源端口径**问题，**不要改换算公式**去迁就。

两者边界不同，别混为一谈：

| 项 | 2006-07-13 那 26 行 | 北交所 1,254 行 |
| --- | --- | --- |
| 性质 | 入库错误（amount 被写入无关数值） | 源端 amount/volume 口径不一致 |
| 是否登记豁免 | 是，51 条全部登记 | **否**，只加代码注释 |
| 原因 | 单日离散坏值，规则无法自行区分「坏值」与「新回归」 | 全量持续偏差，属口径差异；登记豁免等于把该规则对北交所整体静音，会掩盖真正的新回归 |
| 规则命中 | `amount_dimension` 25 行 + `vwap_out_of_range` 26 行 | `vwap_out_of_range` 1,254 行（`amount_dimension` 0 行） |

实测支撑：北交所 359 只 / 286,327 行，`vwap_out_of_range` 命中 1,254 行，
`amount_dimension` 命中 **0** 行——说明偏差幅度远小于 10 倍量纲带，是口径差异而非坏值。
