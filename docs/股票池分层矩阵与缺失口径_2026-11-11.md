# 一、股票池分层矩阵 L0–L5

## 1.1 层定义与实现口径

所有层共用同一张 L0 网格，文件列固定为 `date / ts_code / in_layer`（`in_layer` 为布尔值），按 `(date, ts_code)` 升序。

| 层 | 判定规则 | 数据来源 | 关键参数 |
|---|---|---|---|
| **L0 全历史域** | `list_date <= t` 且（`delist_date > t` 或为空），**保留退市股** | `meta/stock_basic.parquet` 的 `list_date/delist_date` | 无 |
| **L1 剔除次新** | L0 ∩ 上市满 120 个交易日（交易日历逐日计数，不是自然日） | 交易日历（基准 `000001.SH`，`src/data/trading_calendar.py`） | `min_listed_trading_days=120` |
| **L2 可交易** | L1 ∩ 当日有 bar 且 `volume > 0`、`amount > 0` ∩ 不在停牌并集 | `quotes/stock/**/*.parquet` + `meta/suspension/suspension_daily.parquet` + `implied_suspension.parquet` | 无 |
| **L3 风险剔除** | L2 ∩ 非 ST/*ST（`meta/st/st_intervals.parquet` **区间版**）∩ 非退市整理期 | `st_intervals.parquet` + `stock_basic.delist_date` + `name_history.parquet` | 整理期=`delist_date` 前 30 个交易日；名称含「退」的历史段 |
| **L4 流动性** | L3 ∩ 前 20 个交易日成交额均值 ≥ 2,000 万元 | 本地个股日线 `amount` | `adv_window=20`；`min_amount=20,000,000` |
| **L5 池化** | L4 ∩ 现有准入规则：板块 `main/star/chinext`，剔除 B 股、老三板、北交所、旧码 | `src/data/universe_filter.py` 的 `UniverseFilterConfig` 默认值 | `include_bse=False`、`exclude_superseded=True` 等 6 项，逐条写入 manifest |

> **关于「按现有 `meta/pools` 的准入规则组合」**：`meta/pools/` 目前只有 ETF 权益池 `etf_equity_pool_20261104.csv`，没有股票池文件。股票准入规则实际在 `src/data/universe_filter.py`（`UniverseFilterConfig`）与 `src/advice/config.py` 的三档阈值里。L5 因此取 `UniverseFilterConfig` 默认值组合，并把 6 项开关原样写入 `manifest.json` 的 `parameters.pool_rules`，未臆造股票池规则，也未把 ETF 池误当股票池求交。

## 1.6 覆盖缺口、断言与复现

**已知覆盖缺口（未用占位值补齐）**：L0 域内 5,915 只中有 **84 只已退市老股在本地 `quotes/stock/` 没有行情文件**，因此从 L2 起无法进入。完整代码清单写入 `manifest.json` 的 `build_stats.codes_without_local_quotes_list`。这不影响 L0 的「保留退市股」地基（它们在 L0 里仍有历史区间），但任何需要价格的收益/因子研究都只能说「本地无数据」，不能当成「该股不存在」。

**抽样断言（实测）**：

- `000003.SZ`（PT 金田 A，已退市）：L0 最后一日 `2002-06-13`，与 `delist_date` 严格满足 `t < delist_date`；
- `000004.SZ` 在 `2022-05-06`（ST 区间首日）：L2=`True`、L3=`False`，证明 ST 区间在 L3 生效；
- `600519.SH` 在 `2012-05-29`（停牌日）：L2=`False`，证明停牌表生效；
- `600519.SH` 在 `2026-11-11`：L5=`True`；全市场最后一日 L5=4,930 只。

**守恒与嵌套校验**：六个文件的行数都等于网格 18,922,964；`in_layer=True` 计数与 manifest 一致；逐层 `anti join` 检查「深层是否有行不在浅层」结果均为 0；提升后 6 个 SHA256 与候选逐一相同。

# 二、缺失值口径审计（只读，未修改任何代码）

## 2.1 结论

1. **推荐打分链路本身是 null 安全的**：`attach_score` 用截面百分位 rank，缺失保留 null，并在有效因子集上重新归一权重（[scoring.py:16-26](file:///e:/code/python/quant/src/advice/scoring.py#L16-L26)、[scoring.py:60-74](file:///e:/code/python/quant/src/advice/scoring.py#L60-L74)）；`factor_panel` 明确传 `fill_missing=False` 并把 NaN 转 null（[factor_panel.py:53-54](file:///e:/code/python/quant/src/advice/factor_panel.py#L53-L54)、[factor_panel.py:95-98](file:///e:/code/python/quant/src/advice/factor_panel.py#L95-L98)）。这一步是正确的，不能退回「缺失填 0」。
2. **但 `technical.py` 完全忽略 `fill_missing`**，bollinger / MA / RSI 共 11 列无条件 `fill_null(0.0)`；`volume.py` 也仍有 6 处硬编码 0，即使传 `fill_missing=False` 也不会保留 null。这些列当前不在 `FACTOR_GROUPS` 的推荐打分列里（`FACTOR_GROUPS=price_momentum, volatility, volume, risk`，technical 未启用），所以**不进 advice 三档分**；但只要走因子评估、回测或任何省略 `fill_missing` 的调用，就会进入 rank。
3. **会对当前推荐打分产生影响的硬编码 0 主要是风险组的半方差/下行波动**：`risk.py` 把首行 null 收益写成 0（“无下行”），`downside_risk_20`、`sharpe_ratio_20` 等会被系统性低估风险，rank 口径下反而给出「风险最低」的高分。这是本次审计优先级最高的一处。
4. `SCORE_COLUMNS` 里列了 `rsi_14 / kdj_k / kdj_d`，但 `FACTOR_GROUPS` 未含 `technical`，这三列在面板里根本不存在，被 `score_cols` 静默过滤——这不是缺值填充，而是**接线缺口**，与本次审计相邻，单独列出。

## 2.5 rank / z-score 口径下的偏差机制

- **rank（advice 实际口径）**：`rank('average').over('date')` 只对非 null 排名。缺失保留 null → 该股票在该因子上不参与权重；填 0 → 0 变成一个真实观测，拿到名次。
  - 0 落在分布最低端（`bollinger_width`、`obv_ma`、`vwap`）：缺失股被排成「最差」，若方向为负则变成「最好」，两端都会出现虚假信号。
  - 0 落在分布中部（`volume_change`）：缺失股被当成中性股，看似无害，实际是**把「不知道」当成「没变化」**，并稀释真实因子的区分度。
  - 结构性 0（crossovers、signed volume）：制造大量并列值，`average` rank 把所有并列压到同一名次，尾部区分度下降；样本越年轻，并列越多。
- **z-score（研究/评估口径）**：填 0 会同时改变均值与标准差。缺失比例高时（新股 warm-up、停牌段），0 在直方图上形成尖峰，真实观测的 z 值被压缩；用 0 做中性值还会把「无数据」与「真实中性」混为一谈。
- **风险因子**：null 收益被写成 0，等价「当天没有下行」，`downside_risk`、半方差、Sharpe 都会系统性低估风险；rank 把这些股票排到低风险端，是最容易产生伪高分的路径。
