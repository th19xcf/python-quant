## 1. 缺陷与不变式

### 1.1 旧语义错在哪

旧 `merge_parts` 用 `unique(subset=key, keep='last')` 整行 last-wins。后果不是「值算错」，而是**后到分片里的空值把先前已采到的非空值抹成 null**，且 `source` 串随整行一起被替换。用现存两份产物对拍即可复现（实测，见 §2.3）：被拒的全量合并产物相对现正式表，`pe` 空值 713,026 → 4,464,788、`pb` 1,982,588 → 8,175,268、`dv_ratio` 4,247,822 → 8,175,268，**没有任何一行取到过不同的非数值**（`both_non_null_changed` 全为 0），全部损失都是「非空 → null」。

该产物已被拒收，落在 `_backup/derived_catchup_20261112/rejected_valuation_merged_full.parquet`（SHA256 `b4d34899…`）；正式表改按「仅追加」落地（`_staging/derived_catchup_20261112/fix_valuation_append_only.py`，append 11,158 行），现正式表因此仍是完好的。

### 1.2 重写必须满足的不变式

| # | 不变式 |
|---|---|
| I1 | 键集合不变（`('ts_code','trade_date')`），行数不变 = 17,969,137 |
| I2 | 每个数值列 = 该键在全部输入中「最后出现的非空值」；先前非空值不得被降为 null |
| I3 | `source` 的字段段跟随该字段取值的来源行；字段值为空则不产生段、原段保持；`key=none` 原样保留 |
| I4 | 输出排序 = 键升序，列序 = `SCHEMAS['valuation']` |

**原始 267 个采集分片已不在本地**（实测）：`_staging/financials_parts_*/valuation/` 为空 glob，`data/local_store/meta/financials/parts/` 不存在，`_staging/financials_progress_legacy_20261112/` 只有断点无分片。`_staging/valuation_history_20261111/parts/` 下 14 个 parquet 是 1990-12-19 ~ 2005-12-30 的历史重建分片（列集为 `close/tradestatus/pe_raw/pb_raw`，共 2,542,632 行），**不是**采集分片，不能当输入。

因此本方案的候选是**用新语义把现存两份产物重新合并一次的自洽重建**，不是重新采集后的重算。要「真按源分片重算」必须先重跑 `tools/collect_financials.py --only valuation`（DG-25 网络采集，单独立任务与限流），不在本方案内。

### 3.2 顺序与语义

- 输入顺序固定 `[A1(ord=0), A2(ord=1)]`：A1 是最早的完整表，A2 是「后到分片的合并结果」，恰好构成「后片有值则覆盖、后片为空则保留前值」的真实两档输入。
- 语义直接复用第一段落的 `store._merge_agg_exprs('valuation')`，**不另写第二份实现**（避免两套口径并行，DG-2）。组内排序用的分片下标列 `_ORDER_COLUMN='__merge_ord'` 只存在于合并过程，不落盘。

## 4. 段名映射表（DG-19 现有语法）

来源：`src/data/financials/store.py::_SOURCE_SEGMENT_FIELDS`（本次第一段落地的常量）。该语法先例为 DG-19 与 `docs/数据权威路径清单.md` 的 `source` 列（`pe=<来源>|pb=<来源>|dv=<来源>|mv=<来源>`）。

| 列名 | 段名 | 语料里是否出现 | 说明 |
|---|---|---|---|
| `close` | `close` | 否（0 行） | 段位保留，当前语料未使用 |
| `pe` | `pe` | 是（6,205,505 行） | — |
| `pe_static` | `pe_static` | 否 | 段位保留 |
| `pb` | `pb` | 是 | — |
| `ps` | `ps` | 否 | 段位保留 |
| `dv_ratio` | `dv` | 是 | **列名与段名不一致** |
| `total_mv` | `mv` | 是 | **列名与段名不一致** |
| `circ_mv` | `circ_mv` | 否 | 段位保留 |

**加字段的规矩**（将来照这张表走）：

1. 新增可追溯字段必须在 `_SOURCE_SEGMENT_FIELDS` 加一行 `(列名, 段名)`，并在本表登记；
2. 段名一经上线**不得改名**——历史串里已有旧段名，改名等于让旧行永久不可解析；要改名只能并列新旧两段一段时间；
3. 段名与列名不同时必须在本表显式写出（`dv_ratio→dv`、`total_mv→mv` 就是先例）；
4. 输出一律按本表顺序重组，不按输入串的物理顺序（否则同一语义会产出多种串，破坏对拍）。

## 5. 退化形态的处置代价与验收分档

### 5.1 三种形态与实测分布（正式表 17,969,137 行）

| 档 | 判定 | 实测行数 | 占比 |
|---|---|---|---|
| 完全可解析 | 有段，且四个 DG-19 段（`pe/pb/dv/mv`）齐全，每个非空字段都能取到非空段（含 `none` 声明） | 6,205,505 | 34.5% |
| 部分可解析 | 有段，但至少一个非空字段缺段 | 0 | 0% |
| 退化为整串 | 整串无 `=` | 11,763,632 | 65.5% |

退化整串只有三类：`akshare:stock_value_em`（9,690,052）、`local:shares_x_close+fin_ttm`（1,969,763）、`baostock:query_history_k_data_plus+derived:shares+derived:dividend`（103,817）。

`none` 段（声明「该字段无值」而非「无来源」）：`pe` 263,014 行、`pb` 12,825 行、`dv` 2,278,059 行、`mv` 0 行。

字段有值但缺段（全部来自退化行）：`pe` 11,601,499、`pb` 9,793,869、`dv` 9,793,869、`mv` 11,763,632。**这是「逐字段可解析」永远到不了 100% 的原因**，不是重写能修的东西（DG-16：不许伪造来源）。

### 5.2 重写对各形态怎么处理

| 形态 | 处理 | 代价 |
|---|---|---|
| 有段行（6,205,505） | 段随值走，逐字段重组，按 §4 表顺序；`key=none` 原样保留 | 重组串与原文逐字节相同（预测 0 改动） |
| 字段有值但缺段 | 该字段不产生段，**不伪造来源**；若整串重组后为空则回退到「组内最后非空整串」 | 该字段的可追溯性停留在「整串粗粒度」，重写不改善 |
| 整串无 `=`（11,763,632） | 当作不透明标签整体跟随其值的来源行；**只在完全没有任何段时才整体回退**，不与段混拼 | 仍是退化串，0 变化；不会出现「半段半粗串」这种更难解析的混合形态 |
| `key=none` | 原样保留 | 无 |

明确不做的事：不给退化行编造段（那会把「不知道来源」写成「有来源」）；不把 `none` 当缺失丢掉（丢掉等于把「声明无值」变成「来源未知」）。

### 5.3 验收分档（不能只看一个数字）

| 档 | 重写前 | 重写后要求 | 判据 |
|---|---|---|---|
| 完全可解析 | 6,205,505 | **≥ 6,205,505** | 下降即 FAIL |
| 部分可解析 | 0 | **= 0**；若 > 0，必须逐行列出「哪个字段缺段、该段的原始串」 | 上升即 FAIL，除非逐行原因可解释并经批准 |
| 退化为整串 | 11,763,632 | **≤ 11,763,632** | 上升即 FAIL |

三档同时成立才算「`source` 逐字段可解析」这一项通过；只报「完全可解析 6,205,505」一个数字不算通过。
