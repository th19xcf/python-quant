# 因子单调性门槛与分组数绑定（含「空判」结论更正）

> **一句话结论**：`mono ≥ 0.6` 并非恒假的死条件——在原判断所引的那条代码路径上它可达且已生效；
> 「门槛永远达不到」只在另一个同名指标上成立。真正要修的是**同名指标两套定义**与
> **阈值未与分组数绑定**，本次已把两者一起做成显式、校验、可复现的配置。
> 默认值保持 `5 分组 + A 0.6 / B 0.4`，`10 分组 + 0.6` 与 `5 分组 + 0.25/0.30` 作为可选档。

## 1. 更正：原结论错在哪

被更正的原文在 `docs/中性化AB实测_2026-11-11.md` §8.1：

- 原结论：「`mono ≥ 0.6` 这个判定阈值在 5 分组口径下永远无法达到，该条件对任何因子都恒为 False，
  等于从未生效」「TIER_A 的这一条实际是死条件」。
- 错在哪：把两个不同模块的同名指标当成同一个统计量。
  - 原文证据二（147 个因子 × 期限组合、上限 0.513）量的是
    `src/advice/factor_eval.py` 的 `_monotonic_stats`——**每日**做 N 点 Spearman，再**跨日平均**（下称定义 B）；
  - `src/quant/factor_lib/report.py` 的 `tier_of` 读的是
    `src/quant/factor_lib/evaluate.py` 的 `_monotonicity`——**先按组汇总全期平均收益，再对组序号做一次 Spearman**（下称定义 A）。
    两者的输入、聚合顺序都不同，数值量级差一个数量级，不能互相套用阈值。
- 正确结论：
  - **定义 A 下 0.6 可达且生效**：本次重跑 P90(|mono|)=0.99，`mono ≥ 0.6` 命中 57/169；
    已提交的 `reports/factor_lib/factor_eval.csv` 中命中 38/162，按 A/B/C/D 分级实际产出 4 个 A、3 个 B；
  - **定义 B 下 0.6 不可达**：本池（80 只）上限 0.243、P90 0.127；原文档全市场口径上限 0.513、h=20 的 P90 0.256；
  - 因此「空判」不是门槛数值选错，而是**阈值被套到了不该套的定义上**，且分组数与阈值分处两个模块、没有绑定。

## 2. 两套定义（同名不同义）

| 定义 | 代码位置 | 计算顺序 | 取值特征 | 谁在读它 |
|---|---|---|---|---|
| **A 汇总后 Spearman** | `src/quant/factor_lib/evaluate.py::_monotonicity` | 组内收益先跨期求均值 → 再对「组序号 vs 组均值」算 1 次 Spearman | 集中在 ±(0.6~1.0)，易达 0.6 | `factor_lib/report.py::tier_of` 的 A/B 档 |
| **B 逐日后平均** | `src/advice/factor_eval.py::_monotonic_stats` | 每日算 1 次 N 点 Spearman → 再跨日取均值 | 集中在 ±(0.05~0.25)，0.6 不可达 | `factor_eval.EvalConfig.min_monotonic`（当前 0.0） |

## 3. 三种配置的实测对照

**数据与运行**：`src.quant.factor_lib` 面板缓存，参数同 `reports/factor_lib/run_meta.json`
（`--size 80 --start 2021-01-01 --end 2026-10-31`，109,634 行 / 80 只 / 1,410 个交易日）；
本次实跑时间 2026-11-11 21:46~21:48，当前登记可算因子 **170** 个（run_meta 那次记录 163，登记表其间有变动）。
「通过数」= 满足该档全部条件（|ICIR 年化|、t 值、单调性）的因子数，分母为有效因子数 169。

### 3.1 定义 A（`report.py` 实际读取的口径）

| 配置 | h=5 A/B/A+B | h=20 A/B/A+B | h=60 A/B/A+B | 建议清单（h=20，生产跑） |
|---|---|---|---|---|
| **5 组 + 0.6 / 0.4（默认）** | 2 / 2 / **4** (2.4%) | 3 / 7 / **10** (5.9%) | 3 / 7 / **10** (5.9%) | 34 个，A 2 / B 3 |
| 5 组 + 0.25 / 0.25 | 3 / 2 / **5** (3.0%) | 3 / 7 / **10** (5.9%) | 3 / 7 / **10** (5.9%) | 34 个，A 2 / B 4 |
| 5 组 + 0.30 / 0.30 | 3 / 2 / **5** (3.0%) | 3 / 7 / **10** (5.9%) | 3 / 7 / **10** (5.9%) | 34 个，A 2 / B 4 |
| 10 组 + 0.6 / 0.4 | 2 / 2 / **4** (2.4%) | 3 / 6 / **9** (5.3%) | 3 / 4 / **7** (4.1%) | 32 个，A 2 / B 3 |

单调性分布（定义 A，h=20）：5 组 max 1.000、P90(|m|) 0.900、`≥0.6` 57 个；
10 组 max 0.988、P90 0.736、`≥0.6` 27 个。

已提交产物 `reports/factor_lib/factor_eval.csv`（2021-2026、h=20、5 组、162 个有效因子）复核：
max 1.000、P90 0.990、`mono ≥ 0.6` **38 个**；分级 0.6/0.4 → A 4、B 3；换成 0.25/0.30 → A 4、B 5。
即门槛在定义 A 下**是有效约束**，只是约束的是 B 档（3 → 5）。

### 3.2 定义 B（`factor_eval.py` 读取的口径，147 组合证据的来源）

同一面板、同一批 170 个因子：

| 配置 | h=20 max / P90(|mono|) | h=20 `≥0.6` | h=20 `≥0.25` | h=5 max / P90 | h=5 `≥0.25` |
|---|---|---|---|---|---|
| 5 组 | 0.243 / 0.127 | 0 | 0 | 0.140 / 0.086 | 0 |
| 10 组 | 0.190 / 0.100 | 0 | 0 | 0.114 / 0.059 | 0 |

要点：**在这条口径上，把门槛改成 0.25 或把分组改成 10 组，都仍然是 100% 空判**——
只有降到 P90 量级（≈0.13）才可能有因子通过。这正是「不得把定义 A 的 0.25 档套到定义 B」的实测依据。

## 4. 代价

| 项 | 5 组 | 10 组 | 说明 |
|---|---|---|---|
| 每组中位样本（h=20，advice 分组） | 16 只 | 8 只 | 80 只池均分；稀疏日期可低至 1 只 |
| 每组中位样本（h=20，factor_lib 分层） | 18 只 | 14 只 | 该链路先滤 next_tradable，组内人数不均 |
| 组均值的标准误 | 1.0× | ≈1.4× | 与 1/√n 成比例 |
| 评估耗时（h=20，factor_lib，170 因子） | 1.21 s | 1.26 s | +4%，可忽略 |
| 评估耗时（h=20，advice 口径，170 因子） | 1.6 s | 1.6 s | 无差异 |
| 建议清单数量（h=20） | 34 | 32 | 聚类/代表选取随之变化 |

结论：换分组数的代价在**样本厚度**，不在耗时。80 只池下 10 组每组中位 8 只，组均值噪声约 1.4 倍，
因此不把 10 组设为默认；耗时几乎为零不构成选它的理由。

## 5. 定论与默认值

1. **默认不变**：`factor_lib` 用 `5 分组 + 定义 A + A 档 0.6 / B 档 0.4`（与旧版逐值一致）；
2. **advice 侧 `MIN_MONOTONIC = 0.0` 不动**：当前即「不做单调性硬筛」，只要求单调性为正。
   要收紧的话，按定义 B 的量级，本池上限 0.243、P90 0.127；任何高于 0.25 的取值在本池上必然空判，
   0.10~0.13 才可能筛掉一部分。改之前必须先按 §7 的命令重测本池分位；
3. **可选档**：`10 分组 + 0.6`、`5 分组 + 0.25/0.30` 仅作为选择写进 CLI 与本文，不作为默认。

## 6. 配置项与绑定规则

门槛与分组数必须成对出现，三处入口已全部打通：

| 位置 | 参数 | 默认 | 说明 |
|---|---|---|---|
| `src/quant/factor_lib/report.py` | `TierConfig(n_groups, a, b, c, definition)` | `default_tiers(5)` | 冻结数据类；`__post_init__` 校验 n_groups ≥ 2、单调性门槛 ∈ [-1,1]、A≥B≥C 递减 |
| 同上 | `tier_of(row, tiers)` | `DEFAULT_TIERS` | 业务逻辑不再读模块级字典 |
| 同上 | `check_tier_groups(tiers, n_groups)` | — | 门槛标定分组数 ≠ 评估分组数时 **raise ValueError** |
| `src/quant/factor_lib/__main__.py` | `--groups`、`--tier-a-mono`、`--tier-b-mono`、`--tier-a-icir`、`--tier-b-icir`、`--tier-a-t`、`--tier-b-t` | 5 / 0.6 / 0.4 / 1.0 / 0.5 / 2.0 / 1.5 | 生效值写入 `run_meta.json` 的 `tiers` 字段 |
| `src/advice/factor_eval.py` | `EvalConfig.n_groups`、`EvalConfig.min_monotonic` | 5 / 0.0 | `__post_init__` 校验；`n_groups` 贯通 `evaluate_factor` / `evaluate_candidates` / `walk_forward` |
| `tools/eval_daily_advice.py` | `--n-groups`、`--min-mono` | 5 / 0.0 | 两者一并进 walk-forward 缓存 key（`version` 升到 6，旧缓存自动失效） |

## 7. 复现命令

```powershell

.venv\Scripts\python.exe -m src.quant.factor_lib --size 80 --start 2021-01-01 --end 2026-10-31 --horizon 20 --groups 5

# 复现 10 组 + 0.6 可选档
.venv\Scripts\python.exe -m src.quant.factor_lib --size 80 --horizon 20 --groups 10 --tier-a-mono 0.6 --tier-b-mono 0.4

# 复现 5 组 + 0.25 可选档
.venv\Scripts\python.exe -m src.quant.factor_lib --size 80 --horizon 20 --groups 5 --tier-a-mono 0.25 --tier-b-mono 0.25

# advice 侧：换分组数 / 加单调性硬筛（默认 5 / 0.0）
.venv\Scripts\python.exe tools\eval_daily_advice.py --n-groups 10 --min-mono 0.0
```

本文数字来自两个只读测量脚本（未入库，均不写 `data/`、不写 `reports/`）：
`%TEMP%\mono_gate_measure.py`（定义 A + 分级计数，总耗时 26.2 s）与
`%TEMP%\mono_advice_measure.py`（定义 B，直接调用生产函数 `_monotonic_stats`，总耗时 17.1 s）。

端到端冒烟（2026-11-11 21:53，报告目录重定向到临时目录，未覆盖 `reports/factor_lib/`）：

5 组 0.6/0.4、5 组 0.25/0.25、10 组 0.6/0.4；建议清单 tier 分布依次为 A2/B3、A2/B4、A2/B3，
与 §3.1 表格一致，证明「换配置能复现，且配置留痕」。

## 8. 局限

- 只覆盖 80 只流动性最好的标的、单一区间（2021-2026），分位数不能外推到全市场；
  原文档 §8.1 的全市场口径（上限 0.513）与本池（0.243）差异正说明定义 B 的上限随截面宽度变化；
- 定义 A 的 mono 也是「分组收益」口径，未做行业/市值中性，组内成分差异仍会进入该数值；
- 10 组下的样本代价按 80 只池估算，池子扩到全市场后每组中位样本会显著变厚，届时需重估；
- 本次只改门槛/分组数的配置与校验，未改动任何既有正式数据与打分逻辑本身。
