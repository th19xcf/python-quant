## 0. 使用约定

### 0.1 判定口径（7 值）

| 判定 | 含义 | 与任务书五档的对应 |
|---|---|---|
| **已修** | 缺口已补齐、已销案或已定性关闭且数据已落盘 | 已修 |
| **可补** | 本地可推导或已有可用源，尚未补 | 可补 |
| **不可补** | 源端确无（有取证）或结构性不成立 | 不可补 |
| **待采** | 外部源存在、尚未采集 | 待采 |
| **接受偏差** | 可补但按影响判定不采，必须写重开条件 | 不可补（按影响判定不采） |
| **待核实** | 缺口成立但成因或解法未定向（含 unresolved） | 待采（未定性） |
| **已退役** | 条目或编号作废，保留行以备追溯 | 已退役 |

### 0.2 核实标记（逐条给出核实方式）

| 标记 | 含义 |
|---|---|
| **实测** | 本轮直接在仓库内读到数据文件 / JSON 的当前值，数字为现测 |
| **锚点** | 只在文档中有记录；本轮已读到该段落，但未重跑产生该数字的脚本 |
| **锚点+实测** | 文档有记录，且本轮也直接读到了对应文件的关键值 |
| **unverified** | 无法在仓库内确认，或两处文档互斥且无第三证据；不得当作事实引用 |
