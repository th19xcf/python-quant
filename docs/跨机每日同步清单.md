# 跨机每日同步清单（非 Git 目录）

> **一句话结论**：两台机器之间**每天只需要传 `data/local_store/meta/` 里的 PIT 快照族 + `factors/` 的三个权威快照 + `reports/advice/{state,顶层报告}`**，实测全量 **365 个文件 / 29,603,678 B（28.2 MiB）**，日常增量 **0.3～1.5 MB/天**（分红/股本快照重写日 3～6 MB）。`quotes/`、`meta/financials/`、`factors/stock_turnover.parquet` 等可重算/可重拉目录**每天都不传**。
>
> 本文所有文件数与字节均为 **2026-11-09 本机实测**（`Get-ChildItem -Recurse` 聚合），未实测的项单独标注。

---

## 0. 判定口径

| 归类 | 含义 | 是否每日同步 |
|---|---|---|
| **不可再生** | 只有一个副本；重跑只会得到「今天的值」而覆盖历史，或代码根本没有重建入口 | ✅ 每天 |
| **可重算** | 由本机已有的 TDX 日线 / 已同步快照确定性重算，两台机器结果一致 | ❌ 不传 |
| **可重拉** | 能从外部源（远程接口）或本地 `research/events/data` 原始件重新获取 | ❌ 不传 |
| **一次性种子** | 新机首次需要，日常不需要（体积大） | 仅首次 |
| **不该同步** | 机器专属、可重生缓存、历史归档、临时产物 | 永不 |

判定的核心不是体积，是**会不会分叉**：两边各跑一次能得出同一个结果 → 不同步；会得出两套口径 → 必须单向同步。

### 2.2 日均体积的实测口径（为什么不是「最近 7–30 天增量」）

原本计划用 `LastWriteTime` 落在最近 7/30 天的文件求和做日均估算，**本次实测该口径失效**：上表 17 个路径的 365 个文件里，`7d` 与 `30d` 窗口统计结果完全相同（全量），因为 11-03～11-09 是一轮集中重建，所有文件 mtime 都落在 7 天窗口内。

替代口径：按 `LastWriteTime` 的**日粒度直方图**统计「某一天实际被写入的字节」。为排除一次性批量产物，直方图只取其中的 297 个文件（扣掉 `reports/advice` 的 18 个与 `factors/rebuild/` 的 50 个，这两组 mtime 集中在 11-08/11-09）：

| 日期 | 文件数 | 字节 | 性质 |
|---|---:|---:|---|
| 2026-11-03 | 2 | 72,711 | 常态交易日 |
| 2026-11-04 | 9 | 499,048 | 常态交易日 |
| 2026-11-05 | 84 | 2,850,713 | 批量回补日 |
| 2026-11-06 | 9 | 275,183 | 常态交易日 |
| 2026-11-07 | 13 | 4,372,712 | 分红/股本快照重写日 |
| 2026-11-08 | 49 | 3,669,869 | 分红/股本快照重写日 |
| 2026-11-09 | 131 | 16,441,401 | 指数成分抓取日（+9.75 MB） |

取三个常态交易日（11-03/04/06）作为基线：**2～9 个文件 / 0.07～0.49 MB**；把分红快照 3.4 MB、股本表 2.2 MB 计入后 **3～6 MB**；指数成分抓取日上限 **≈16.4 MB**。

## 4. 同步脚本

### 4.1 日常增量（默认 dry-run）

脚本：[tools/sync_daily_non_git.py](file:///e:/code/python/quant/tools/sync_daily_non_git.py)

```powershell
# 1) 先看要传什么（默认 dry-run，只打印，不落盘）
.venv\Scripts\python.exe tools\sync_daily_non_git.py `
    --source E:\code\python\quant `
    --dest \\HOME-PC\quant\code\python\quant

# 2) 确认后真传（只增量复制，永不删除目标端文件）
.venv\Scripts\python.exe tools\sync_daily_non_git.py `
    --source E:\code\python\quant `
    --dest \\HOME-PC\quant\code\python\quant --apply

# 3) 传完校验（默认全量比大小 + SHA256，--sample 200 可抽样）
.venv\Scripts\python.exe tools\sync_daily_non_git.py `
    --source E:\code\python\quant `
    --dest \\HOME-PC\quant\code\python\quant --verify
```

设计要点：

- 增量判据：**目标缺失 / 大小不同 / 源 mtime 更新超过 2 秒**（容忍 SMB 与 FAT 时间戳精度）；用 `copy2` 保留 mtime，第二次运行天然幂等。
- **没有任何删除调用**：脚本内不存在 `remove`/`rmtree`/`unlink`，目标端多出来的文件一律保留。
- 输出：范围内文件数/体积、需传输文件数/体积、按目录分组表、dry-run 时列出体积最大的 10 个待传文件。
- 路径参数化：`--source` / `--dest` 均接受 UNC，无硬编码盘符。

### 4.2 新机首次灌种子（一次性）

`quotes/` + `meta/financials/` + `meta/research_inputs/` 共 3.14 GB，或直接用 robocopy 单次搬运：

```powershell
# 只复制、不镜像（不加 /MIR），/E 保留子目录结构
robocopy <源机>\data\local_store\quotes       <目标机>\data\local_store\quotes       /E /L
robocopy <源机>\data\local_store\quotes       <目标机>\data\local_store\quotes       /E
robocopy <源机>\data\local_store\meta\financials ^
         <目标机>\data\local_store\meta\financials /E
robocopy <源机>\external\tdx_hq_cache         <目标机>\external\tdx_hq_cache         /E
```

> 若新机愿意用「本机通达信 + `python -m src.data.local_store build --all`」重建 quotes，可连这一步也省掉（`--full` 全量重建仍读本机 `vipdoc/**/*.day`，所以新机要么装通达信并下全历史，要么整份拷 quotes）。

### 4.3 U 盘增量包（`--scope package --since`）

断网/临时带数据的场景走 U 盘，不依赖网络共享：

```powershell
# 先算：432 文件 / 230,613,188 B（含 meta/research_inputs、external/tdx_hq_cache、当日 reports 小产物）
.venv\Scripts\python.exe tools\sync_daily_non_git.py --scope package `
    --since "2026-11-09 07:00" --dest G:\sync\quant

# 再传：--apply 才落盘；--manifest 生成相对路径/字节/mtime/SHA256 清单
.venv\Scripts\python.exe tools\sync_daily_non_git.py --scope package `
    --since "2026-11-09 07:00" --dest G:\sync\quant --apply `
    --manifest G:\sync\quant\manifest.csv
```

- `--since` 接受 `2026-11-09 07:00` / `:00` 秒 / 纯日期三种写法；判据是「源 mtime ≥ since **或** 目标缺失 **或** 大小不同」。
- `reports/` 只取 since 之后有写入的目录；单个目录本次需传超过 **50 MB** 视为重体积可重建中间件，默认跳过并打印清单，加 `--include-heavy-reports` 才带上。`reports/advice/calibration/` 永久排除。
- 包根随包携带 `manifest.csv`、`README.md`、`restore.py`，对端用 `restore.py --dest <项目根> [--apply|--verify]` 按相对路径覆盖，同样不删除。

## 5. 跨机一致性检查

### 5.1 同步后校验

1. **全量 SHA256（推荐）**：`--verify` 对 365 个文件逐个比大小 + SHA256，一条命令给出「通过 / 缺失 / 不一致」计数。数据量仅 28.2 MiB，不必抽样。
2. **抽样比对**（网络慢或只查关键项时）：

```powershell
# 两端各取同一批文件的哈希再 diff
$a = Get-Content .\sync_files.txt | ForEach-Object {
    [pscustomobject]@{ f=$_; h=(Get-FileHash (Join-Path 'E:\code\python\quant' $_) -Algorithm SHA256).Hash }
}
$a | Export-Csv local_hash.csv -NoTypeInformation
# 目标机同法导出 remote_hash.csv，再 Join-Object 对比 h 列
```

3. **关键子集独立复核**：`python tools/backup_critical_assets.py --dest <目录> --verify` 会按 manifest 重算 26 个单文件 + 11 个目录的 SHA256（含 `names.json`、`stock_dividend`、`st_status`、`advice/state`）。

### 5.2 不能两边各跑的表（必须单向同步）

| 表/文件 | 两边各跑会怎样 |
|---|---|
| `meta/st_status/st_status_<日期>.parquet` | 取当日远程 `stock_basic` + 本机 `names.json`，两机网络时点/名称版本不同 → 同一日期两份 ST 名单 |
| `meta/industry/industry_<日期>.parquet` | 读各自 `tdxhy.cfg`，通达信版本不同 → 行业归属分叉 |
| `meta/names.json` | 由各自 `*.tnf` 生成，通达信码表更新节奏不同 → 名称/退市状态分叉 |
| `factors/stock_dividend.parquet`、`fund_dividend.parquet` | 唯一权威快照，两边各自 `refresh-factors` 会互相覆盖成两套口径 |
| `meta/financials/*` | 两条独立采集链，`parts/` 断点与 `progress.json` 不同 → 合并后口径混合 |
| `meta/index_membership/`、`meta/index_constituents/`、`meta/industry_pit/`、`meta/st/` | 外部 PIT 重抓只返回「当前修订」，两机会得到不同历史版本 |
| `meta/universe/`、`meta/pools/`、`meta/anomalies/quality_exemptions.csv` | 人工裁定结论，两边各改必然冲突 |
| `reports/advice/state/*.json` | 各跑推荐 → 两套持仓/净值，此后无法合并 |
| `meta/stock_basic/index_basic/fund_basic.parquet` | 基础信息各刷各的 → UI 名称与退市状态不一致 |

**允许两边各跑的**（确定性重算）：`quotes/`、`meta/breadth/`、`meta/suspension/`、`factors/stock_adj_factor`、`factors/fund_adj_factor`、`factors/stock_turnover`、`meta/research_inputs`、`meta/daily_index.parquet`、`meta/events`（从已入库原始件重导）、`reports/**` 审计产物。
