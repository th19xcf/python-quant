## 二、字段级来源（DG-19）

正式行情 parquet 只有 13 列固定 schema（写入前由 `assert_formal_quote_schema` 校验），**无 `source` 列**，因此字段级来源不落列、落两处侧车：

1. `_staging/g079_fill_20261112/sources_field_level.csv`：22 行 × 11 个字段逐行标注；
2. `data/local_store/quotes/stock/sz/000001.SZ.manifest.json` 的 `field_sources` 段。

语法沿用 `valuation_daily` 的字段级先例（`pe=…|pb=…`），写作 `field=source|verified=…`：

| 字段 | 标注 | 覆盖情况 |
|---|---|---|
| open/high/low/close | `baostock` + `verified=sina` / `verified=sina,tencent` | 21/22 行新浪逐值相等，3 行另有腾讯相等，1991-05-06 单源 |
| volume | `baostock/100` + `verified=…` | 19 行新浪相等、3 行腾讯相等；1996-01-02 与 1996-02-09 新浪按百股取整，差 7 股与 80 股 |
| amount | `baostock\|single_source` | 新浪 amount 为「量×均价」推算，仅 1/22 行元级相等、4/22 相对差 ≤1e-6，其余属口径不同，未采用 |
| pre_close | `derived=chain(qfq)` + `crosscheck=baostock.preclose` | 22 行链值与 baostock `preclose` 逐值相等 |
| change / pct_chg | `derived=close-pre_close` / `derived=(close/pre_close-1)*100` | 与 `build.py` 同式，保留双精度 |
| qfq_factor / hfq_factor | `copied=prev_row` | 22 天前后因子完全相同（无除权日落在缺口上） |

## 八、遗留缺陷：1993-05 四行 TDX 日期错标（本次未碰）

本地 1993-05 初存在整体 **−2 天**的日期错位，四行与上游同价同量：

| 本地行 | 本地 close / volume(手) | 上游行 | 上游 close / volume(股) |
|---|---|---|---|
| 1993-05-01（周六） | 58.05 / 2,795 | 1993-05-03 | 58.05 / 279,500 |
| 1993-05-02（周日） | 58.00 / 3,410 | 1993-05-04 | 58.00 / 341,000 |
| 1993-05-04 | 56.70 / 4,692 | 1993-05-05 | 56.70 / 469,200 |
| 1993-05-05 | 55.30 / 12,940 | 1993-05-06 | 55.30 / 1,294,000 |

也就是说，换手率表里 1993-05-03 与 05-06 的成交在本地已存在，只是被标注成 05-01/05-02 与 05-04/05-05；补 bar 会造成重复计数。

**建议处置（单独立项，不在本次范围）**：按上游日期把四行标签改为 05-03、05-04、05-05、05-06，改后 05-01/05-02 两个周末行消失、05-03/05-06 出现；改动后须同步重算 05-06 之后一行的 `pre_close/change/pct_chg`、刷新 `daily_index`、并把 4 行的 before/after 写入 manifest。风险点：本地 1991~1993 另有 39 个上游不存在的周末 bar（属日历口径差异），本次修正只动这 4 行，不触碰其余 37 个。回滚方式同本文第三节（改前 `copy2` 快照）。
