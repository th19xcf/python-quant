- 用法：任何报告、评审、派单提到「数据是否收口 / 缺口是否补齐 / 体检是否健康」，只引用本文件，不再重新论证。

## 1. 收口口径

- **范围**：`src/data/dataset_contracts.py` 中 `iter_contracts()` 登记的 **47 个数据集**（`data/local_store` 下）。
- **统一写入口**：`write_dataset()` —— 负责契约列/分区校验、原子替换、ledger 登记。生产写入不得绕开；
  已修复的两个旁路：`src/data/financials/store.py::merge_parts`（落盘后自动补登）、
  `tools/backfill_delisted_shards.py`（逐分片走 `write_dataset`）。
- **契约与豁免边界**：有 parquet 但无契约的目录只有 `meta/dividend_status/`（无分红逐只取证台账，无下游），
  已登记在 `NON_CONTRACT_DIRS`，不补契约、不进体检。
- **新鲜度分档**（`LAG_TIERS`）：日频 5 / 周频 10 / 月频 35 / 季频 200 天；按数据集 `update_frequency` 取值。
- **目录级 manifest**：`meta/*/manifest.json` 记录分区清单、总行数、max_date、生成时间；
  内容未变时 `built_at` 保持不变（幂等）。
- **异常侧车边界**（2026-11-23）：`meta/anomalies/placeholder_quote_codes.csv` 与
  `fund_pseudo_registry.json` **不纳入 `dataset_contracts`**（半人工台账、无行情分区与
  freshness 语义，纳入会给它套错判据）；但**纳入 `meta/anomalies/manifest.json` 登记树**
  并受体检一致性校验（段数、行数合计、单基金段数上限），刷新时 CSV 与 registry 必须同一次写入。

## 2. 可复现判据

```bash
# 主判据（期望：47 个数据集 / 异常 0 / 告警 0 / 健康 47）
.venv\Scripts\python.exe tools\dataset_health_check.py
.venv\Scripts\python.exe tools\dataset_health_check.py --json   # artifacts/dataset_health/<日期>.json
```

三项一致性核对的验法：

| 项 | 验法 | 通过标准 |
|---|---|---|
| ledger | `registration_summary(root)` 的每个数据集，与磁盘实测 `rows` / `max_date` / 单文件 `sha256` 比对 | 47/47 全等，无 `last_write` 缺失 |
| manifest | 逐契约读 `manifest.json`：分区清单条数 = 磁盘分片数、`rows`/`max_date` = 磁盘实测；重建用 `tools/build_partition_manifest.py --only <key>` | 全等；连跑两次 SHA 不变 |
| freshness | 对每个设了 `max_lag_days` 的数据集算 `today - max_date` | 超阈值 0 条 |
| 治理项 | 体检末四行：未登记写数据脚本、裸写清单 delta、基金伪数据台账一致性 | `未登记写数据脚本` 为空、delta ≤0、台账一致（段数/行数合计/每基金段数上限）；**这些项不进入 0/0/47 计数，但同属回退判据**；退出码覆盖异常、未登记脚本与台账不一致，裸写 delta 仍须读文本 |

任何一项不满足，即视为「已回退」，按 §5 重开。

## 5. 重开条件

只有以下两种情形允许重开数据层核对，其余一律引用本文件：

1. **源端出现新证据**。必须是可复现的原始返回，形式为：接口名 + 请求参数 + 返回摘要
   （行数、关键字段值、日期范围）落在文件里（如 `logs/<run>/` 或 `_staging/<run>/`），且与上表证据**直接矛盾**。
   例：`pro.new_share(ts_code='300646.SZ')` 返回 `price>0`；或某只退市股的 `pro.daily` 返回了本次未覆盖的日期区间；
   或交易所公告证明某行双禁实际应可交易。
2. **体检或一致性核对回退**。按 §2 的命令跑出：异常 > 0 或 告警 > 0 或 健康 < 47；
   或 ledger 的 `rows`/`max_date`/`sha256` 与磁盘不一致；或 manifest 分区数/行数不符；或 freshness 超阈值；
   或治理项回退（`未登记写数据脚本` 非空、裸写 delta > 0）。

不构成重开理由：旧文档里的历史数字、印象、没有原始返回的「再确认一下」、凭感觉怀疑。
重开时必须写明：触发项（1 或 2）、证据文件路径、与本文件哪一条冲突。

## 6. 已知口径偏差（2026-11-22 实测核实）

以下两处不是"数据洞 / 源端缺数"，而是已核实的口径偏差：数据按既定口径产出，使用方需知道边界。两条都已登记缺口表，处置均为"接受偏差"，不影响本文件其余结论。

### 6.1 2011 年 `pe` 缺口（对应 G-036）

| 项 | 实测 |
|---|---|
| 缺失规模 | **152,232 / 510,975 行 = 29.8%**；把 `pe≤0` 一并计入则 **33.6%** |
| 涉及标的 | 2,246 只（在市 2,035 只 / 106,057 行，退市 211 只 / 46,175 行），无北交所 |

### 6.2 2015–2017 年 `pb` 为 PIT 推导值（对应 G-071）

| 项 | 实测 |
|---|---|
| 源表状态 | `valuation_daily.pb` 2015 / 2016 / 2017 三年 **null 率均 100%**（569,746 / 642,150 / 744,258 行） |
| 实际取值 | `meta/financials/valuation_pre2018_patch.parquet`：1,948,774 行，`pb` 非空 **1,825,566（93.7%）** |
| 推导口径 | `pb = total_mv / total_equity`（**含少数股东权益**），PIT 对齐 `ann_date ≤ trade_date`；标记 `equity_basis=total_equity_incl_minority`、`bp_source=derived:*`、`calc_version=v1_20261109`；**不前视** |
| 误差方向 | 分母含少数股东权益 → **PB 偏低**（即 BP 偏高）；2018–2020 对拍：中位相对误差 **3.15%**、p90 **21%**、Spearman **0.97**、`pb_calc/pb` 中位 **0.9842** |
| 处置 | **接受 + 触发条件**；可信归母净资产源出现后重算补丁，并与 2018–2020 重新对拍（中位 ≤1%、p90 ≤5%、Spearman ≥0.99）才可替换 |
| 使用影响 | BP 在该区间**可用但系统性略高估**（PB 偏低约 1.6%）；跨 2018 年比较 BP 时须注意口径跳变，按 `calc_version` / `equity_basis` 标记分段，不得把 2015–2017 与 2018 后视为同一口径 |
