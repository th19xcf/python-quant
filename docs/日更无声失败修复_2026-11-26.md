## 一、启动脱离父终端（`--detach`）

实现（`tools/daily_update.py`）：

- `_popen_detached`：Windows 用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`，并优先带
  `CREATE_BREAKAWAY_FROM_JOB`（被作业对象拒绝时自动退回不带 breakaway 的方式）；两条都
  不需要管理员权限。非 Windows 用 `start_new_session=True`。
- `_relay` / `_spawn_detached`：Windows 走两跳——本进程 → 中继（拉起目标后**立即退出**）→
  目标进程。目标进程的父进程已消失，父终端按进程树硬杀时枚举不到它。
- 目标进程 stdout/stderr 在 OS 层追加到 `logs/daily_YYYYMMDD_console.log`，并设
  `PYTHONUNBUFFERED=1`（硬杀也保留已输出内容）；`QUANT_DAILY_DETACHED=1` 时跳过进程内
  tee，避免同一条输出写两遍。
- 用法：`python tools/daily_update.py --detach --apply --allow-remote`；拉起方只打印
  「已脱离终端拉起（pid …）」后立即返回。

## 验证「脱离父终端」（可复现）

脚本：`work/verify_detach_20261126.ps1`（PowerShell，不需要提权）。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File work\verify_detach_20261126.ps1
```

步骤与判据：

1. 起一个 PowerShell 作为「拉起方」，它调用 Python 拉起方；Python 拉起方经
   `du._spawn_detached` 启动心跳子进程（每 0.5s 追加一行），把子进程 pid 写入
   `work/_detach_probe/child.pid` 后驻留。
2. `taskkill /F /T /PID <拉起方 PowerShell>`——复刻 2026-11-25 16:11 的「父终端按进程树硬杀」。
3. 判据：拉起方已不存在 + 子进程仍在 + 心跳文件继续增长。

本次实测（2026-11-26）：拉起方 PowerShell pid=35540，脱离拉起的子进程 pid=17452；
硬杀后拉起方不存在、子进程存活、心跳字节 6 → 27，脚本退出码 0（PASS）。

端到端冒烟（真实入口，不写数据）：

```powershell
python tools\daily_update.py --detach --only nosuchstep
```

输出：`[daily] 已脱离终端拉起（pid 29388），stdout/stderr 追加到 …logs\daily_20261126_console.log`；
约 10 秒后该日志内出现子进程那行 `[daily] 未知步骤键：nosuchstep…`，证明 stdout/stderr
照旧落到 `logs/daily_YYYYMMDD_console.log`。

## 二、被活跃锁挡下留痕

- `_acquire_lock(token, target=...)` 新增 `target`（`main` 传 `--end`，缺省回退本地最新末根，
  取不到写 `auto（未探测）`）。
- 被活跃锁挡下时，先写统一日志事件：

```json
{"event": "lock_blocked", "pid": <本次 pid>, "holder_pid": <持锁 pid>,
 "lock_mtime": "...", "holder_started_at": "...", "target_date": "...",
 "lock_path": "...", "ts": "..."}
```

  再 `logger.error` 一行（WARNING 级别以上默认落 stderr → 控制台日志），然后退出。
- 抢占与 TTL 语义未改：陈旧锁仍按原逻辑归档并写 `stale_lock` / `stale_lock_unfinished_run`。
- 检索方式：`Select-String -Path work\logs\daily_update.log -Pattern 'lock_blocked'`。

## 三、月度分红跳过留痕

- `_step_dividend_monthly` 两条跳过路径都写 `dividend_monthly_skip` 事件
  （`reason`：`not_due` / `timeout`），字段含 `last_success`、`days_since_success`、
  `threshold_days`、`target_date`，并同步 `logger.warning` 一行。
- 时间语义未改：`_dividend_monthly_due` 改为复用 `_dividend_monthly_lag()`，判定条件与原实现一致。
- 滞后进体检告警：`_step_dataset_health` 调用 `_dividend_monthly_lag_warning()`，超过
  `--dividend-monthly-days`（默认 28）时在体检摘要里追加一行
  `[WARNING] dividend_monthly（月度分红全量）· stale_state：…`，同时 `logger.warning`；
  只走已有 warning 通道，不增加 error 判据、不改退出码。
- 检索方式：`Select-String -Path work\logs\daily_update.log -Pattern 'dividend_monthly_skip'`。
