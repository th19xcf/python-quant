# 数据命名规范（2026-11-22）

目的：让文件名/数据集名直接表达**语义与可回溯性**，不再靠口口相传。本页是规则页，机器可读版本在
`src/data/dataset_contracts.py`（契约注册表），两者冲突时以注册表为准并回改本页。

## 1. 后缀规则（必须）

| 后缀 | 适用 | 硬性要求 |
|---|---|---|
| `_daily` | 按交易日连续更新的面板（行情、ST、涨跌停、两融、估值） | 必须有 Date 型日期列（`date` 或 `trade_date`）；每月分区文件写 `<dataset>_YYYYMM.parquet` |
| `_snapshot` | 单时点截面（如近期行业归属） | 必须能读出唯一 `as_of`/`effective_date` 断面；**禁止**按 PIT 区间语义回溯；不得命名为 `_pit` |
| `_pit` | 区间表，支持 as-of 查询 | 必须含 `(in_date, out_date)` 区间列；只有区间表才能叫 `_pit`；单断面表一律不得使用 |
| `_history` | 全历史序列（可含多个 `as_of` 的历史堆叠） | 必须保留 `as_of` 列，且各期可区分 |
| `_recent` | 近 N 日窗口视图 | 文件名与 `semantics` 都要写明窗口天数；不得被当作 PIT |
| `_patch` / `_backup` / `_vN` / 日期后缀 | 修数中间态、备份、版本副本 | 只能放在 `_backup/`、`_staging/` 或 `backups/`；不得与正式产物同目录并列 |
| 无后缀（`stock_basic.parquet` 等） | 低频名单/基础表 | 必须在同目录 manifest 写明更新方式与权威来源 |

补充约定：

- 一标的一文件的行情统一 `quotes/<kind>/<market>/<ts_code>.parquet`，日期列：stock/fund/index 用 `date`，
  futures 沿用交易所原生 `trade_date`（String，见 `quote_schema.py`）。
- 数据集 key 与产物路径一一绑定（见注册表 `CONTRACTS`），key 即语义：`quotes_stock` 只表示个股日线。
- `daily`/`snapshot`/`pit` 是语义承诺，不是形容词；改语义必须同时改名并更新 manifest/契约/本页。

## 3. 落地方式（已实施）

1. 写入：统一走 `src/data/dataset_contracts.py::write_dataset`，写前按契约校验 schema/日期列/关键列空值，
   不匹配抛 `ContractViolation`；写成功后自动登记 `rows/sha256/max_date` 到
   `meta/registry/auto_register.json`，单文件表同时补丁本目录 `manifest.json`。
2. 体检：`tools/dataset_health_check.py` 按同一份注册表扫磁盘，检查文件/行数/schema/日期列/空值率/
   `max_date` 滞后，并对账 ledger 与目录 manifest（落后自动暴露）；异常退出码 1，报告写
   `artifacts/dataset_health/YYYY-MM-DD.md`。
3. 新增数据集：在注册表补一条 `DatasetContract` 并同步本页表格，不新增命名方言。
