# 外部策略内容可用性评估（小红书 / 抖音 / 雪球 → 本项目分析回测筛选）

- 评估日期：2026-11-20
- 范围：只做评估与方案；未发起任何平台抓取、登录或逆向操作，未改代码、未写 `data/`
- 结论口径：技术上能拿到 ≠ 合规上可以拿；项目能力以当前仓库代码为准

## 一、结论摘要（分档）

| 档位 | 内容类型 | 项目承接 | 建议 |
|---|---|---|---|
| A 可直接落地 | 双 ETF 强弱比轮动/二八切换、单标的定投补仓+止盈回撤、日线均线/动量/回撤择时、日频选股因子（估值/低波/财务） | 四类规则已覆盖，写 JSON 即可回测 | 值得做，人工摘录 + 规则化 |
| B 需小幅扩展 | 3 只以上轮动/多标的排序、周频或日频调仓、止损与移动止损、波动率目标仓位、多信号组合（AND/OR） | 规则词表/引擎需扩展，属独立开发单 | 先评估扩展成本，不为单条内容改引擎 |
| C 无法表达/成本过高 | 盘中分时、打板、集合竞价、盘口挂单、个股资金流/北向/龙虎榜、新闻情绪、主观判断、事件驱动、组合优化、做空、港美股 | 无对应数据或无执行语义 | 不建议为这类内容补数据或改引擎 |

**总体判断**：作为「灵感来源 + 人工筛选」可行且有价值；作为「自动抓取建库 + 批量回测」不可行（合规风险高、内容可量化率低、维护成本高）。

## 二、平台侧可取性

| 平台 | 内容形态 | 是否需登录 | 公开接口 | 反爬强度 | 条款限制 | 技术可取 | 合规可取 |
|---|---|---|---|---|---|---|---|
| 小红书 | 图文笔记为主，长文少，短视频次之 | 是（Web/App 均需登录态） | 无面向个人的内容 API；开放平台开发者限「软件服务商/商家自研」，内容类接口不对个人开发者开放 | 高（签名参数、设备指纹、验证码，算法频繁变更） | 用户协议禁止未经授权的抓取与转载 | 非官方手段可拿，但稳定性差 | 否（无授权） |
| 抖音 | 短视频/口播为主，图文为辅 | 是 | 有官方「抖音视频搜索」OpenAPI（scope `aweme.dy.video_search_v2`），但要求正式上线应用、有用户规模、有明确场景，且限 C 端展示用途 | 高（a_bogus/msToken 类签名、风控） | 开放平台规范限制展示方式与用途 | 官方接口合规但门槛高；非官方手段风险高 | 官方路径「可申请」，但用途不匹配本研究场景 |
| 雪球 | 长文/帖子/评论，策略讨论密度最高 | 部分内容需登录 | 无公开内容 API（历史非官方接口不稳定） | 中高（登录态、频控、验证码） | 常见问题明确禁止爬虫/抓取工具；转载引用需用户或雪球书面同意 | 可拿但不稳定 | 否（无授权） |

**关键区分**：
- 「技术上能拿到」：用登录态 + 非官方接口/浏览器自动化，三个平台都能取到正文；但签名与风控会持续变更，维护是长期成本，且账号封禁风险由操作方承担。
- 「合规上可以拿」：三家的用户协议均把「未经授权的抓取」列为禁止行为；雪球还单独要求转载/引用取得书面同意。即使内容公开可见，也不等于授权批量采集与二次使用。

**本评估的合规建议**：只做「人工阅读 → 自己改写为结构化摘要 → 不保存原文、不建原文库」。这是风险最低的用法；任何自动抓取、原文落盘、批量分发都不建议。

## 三、内容侧可用性

### 3.1 典型形态归纳（不针对具体博主）

1. **纯结论型**：「XX 方向要起来了」「这个位置可以布局」——无标的、无参数、无规则。
2. **半规则型**：「均线金叉买入」「跌破就止损」——有信号名，缺周期、标的口径、仓位、止损幅度。
3. **晒单型**：只给一笔成功交易的交割单/收益截图，无完整净值、无失败样本。
4. **事后挑选型**：用已经走出来的行情反推「当时应该买」，存在明显未来函数。
5. **口径模糊型**：「低位」「放量」「强势」——没有可计算的阈值定义。
6. **营销钩子型**：内容本身用于引流课程/社群/开户，策略细节被刻意隐藏。
7. **口播/图文转写损耗**：指标名、代码、参数在视频转文字后错漏，需要回到画面核对。

### 3.2 落成可回测规则需要补什么

| 缺口 | 必须补齐的内容 | 谁来补 |
|---|---|---|
| 标的 | 具体代码（6 位 + 交易所后缀）或可代理的指数/ETF | 人工判定 + 与用户确认 |
| 信号 | 用项目已开放字段与运算符重写（见 `src/quant/strategy_lab/fields.py`） | 人工 |
| 参数 | 窗口、阈值、档位；原文缺失时给默认值并记录假设 | 人工，写进 `description` / `data_policy` |
| 调仓 | 月频/半年频（选股）或事件触发（切换/择时/定投） | 按规则类型选 |
| 仓位 | 等权、固定权重档位或全仓单腿；项目不支持做空与杠杆 | 人工 |
| 成本 | 滑点/佣金/印花税；默认口径已在 `rules.py` 的 `DEFAULT_COST` | 默认即可 |
| 样本 | 起止区间；必须留样本外区间做验证 | 人工 |

### 3.3 人工成本量级（估算，非实测）

- 单条内容从「读到」到「跑出净值」：约 30~90 分钟（含查代码、补参数、写 JSON、跑回测、看结果）。
- 可量化比例：粗估 10%~20% 的内容能落成规则，其余在「口径模糊/纯结论/事后挑选」阶段被丢弃。**该比例无法确认**，需要实际抽样 50~100 条并逐条判定后才能给出可信数字。
- 主要成本不在回测（分钟级），而在**读懂 + 补全 + 判断是否过拟合**。

## 四、项目侧承接能力

### 4.1 可表达（A 档）

| 外部策略形态 | 对应 `rule_type` | 依据 |
|---|---|---|
| 两只 ETF/指数按强弱比切换、二八轮动 | `asset_switch` | 比值中枢 + 上下阈 + 最短持有 + 全仓或分档权重，见 `rules.py` L330-L432 |
| 单标的定投、跌了补仓、止盈后回撤清仓 | `dca_grid` | 份数、补仓跌幅、止盈阈值、止盈回撤，见 `rules.py` L514-L551 |
| 单标的/组合按均线比、动量、回撤调仓位 | `timing` | 三种信号 `ma_ratio` / `momentum` / `drawdown` + 档位 + 滞回，见 `rules.py` L61、L459-L507 |
| 低估值、低波动、财务质量等日频选股 | `stock_select` | 条件链 + 排序 + 取前 N，字段白名单见 `fields.py` L57-L152 |
| 单因子分层/剔除类研究 | 因子研究链路 | `src/backtest/runner/registry.py` L155-L195 的 `FACTORS` / `CONDITIONS` |

### 4.2 需要扩展（B 档）

- 3 只以上标的的截面轮动/排序（`asset_switch` 只按一对分子/分母切换）。
- 周频、日频调仓（选股规则只支持月频与半年频，见 `rules.py` L55）。
- 止损、移动止损（除 `dca_grid` 的止盈回撤外无通用风控）。
- 波动率目标仓位、风险预算、行业权重约束（目前只有等权或固定档位权重）。
- 多信号组合（`timing` 只能选一种信号，不能 AND/OR 组合多个条件）。
- 指定股票池（选股只支持 `all_market`，见 `rules.py` L307-L313）。

### 4.3 无法表达（C 档）

- 一切盘中决策：分时、打板、集合竞价、盘口挂单、日内 T+0。项目执行口径固定为「信号日收盘生成、下一交易日开盘成交」（`rules.py` L57、L289-L300）。
- 个股资金流、北向资金、龙虎榜、大单：本地无对应数据表。
- 分钟线策略：本地无分钟线列存，`docs/数据权威路径清单.md` 明确登记 `stock_minute` 仅写 MySQL、本地列存未接线。
- 新闻/研报情绪、主观判断、事件驱动：无文本与事件打分链路。
- 做空、杠杆、期货期权组合：规则权重限制在 `[0, 1]` 且合计不超过 1（`rules.py` L416-L419）。
- 组合优化与机器学习模型：规则层不接受代码求值，只接受预定义字段与运算符（`rules.py` 模块文档 L1-L16）。

## 五、最小工作流（若要做）

1. **人工摘录**：读到一条内容后，手工填一张结构化卡片——标的、信号、参数、调仓频率、仓位、风控、样本区间、原文链接（仅记录链接，不落原文）。
2. **可表达性判定**：对照 4.1/4.2/4.3 三张表；落在 C 档直接丢弃，落在 B 档先记录需求、不急着改引擎。
3. **补全与假设登记**：缺失参数给默认值，写进规则的 `description` / `data_policy`；同一策略的多次调整只保留一份最终版本。
4. **规则化与回测**：写规则 JSON → `validate_rule` 校验 → `run_rule` 回测（`src/quant/strategy_lab/backtest.py` L741）；先看样本内，再用样本外区间与参数敏感性验证。
5. **归档**：只有通过样本外验证的规则才进 `config/strategy_lab/rules/`；原始内容不建库、不落盘。

**不值得做的环节**：
- 自动抓取/建内容库（合规风险最高、维护成本最高、噪声最大）。
- 全量视频转文字（信息密度低，转写误差还要人工回看）。
- 全自动「LLM 抽取 → 直接回测」（缺人工口径确认，容易把事后挑选当策略）。
- 平台内按点赞/收藏「筛策略」（样本偏差极强，几乎必然过拟合）。
- 为外部内容补分钟线或资金流数据（成本远超收益）。
