## 2. 落库与因子口径

### 2.1 表结构

| 文件 | 规模 | 字段 | 说明 |
|---|---|---|---|
| `data/local_store/factors/fund_dividend.parquet` | **3,407 行 / 435 只** | `ts_code / ex_date / record_date / cash_amount / source / fetched_at` | 与个股 `stock_dividend` 现金分红同语义；`record_date` 空值 0；金额 0.0003~7.912（中位 0.02847） |
| `data/local_store/factors/fund_share_change.parquet` | **2,704 行 / 681 只** | `ts_code / ex_date / split_type / share_ratio / source / fetched_at` | 份额分拆 1,361 + 份额折算 1,343；比例 0.01~12.0 |
| `data/local_store/factors/fund_adj_factor.parquet` | **2,862,075 行 / 2,615 只**（1.35 MB） | `ts_code / trade_date / qfq_factor / hfq_factor` | 与个股因子完全同 schema、同公式 |
| `data/local_store/factors/fund_covered_codes.txt` | 2,615 行 | 已覆盖基金代码 sidecar | 供后续重建/校验对齐 |
| `data/local_store/factors/fund_meta.json` | — | 规模、来源、对齐规则、耗时 | 机器可读元数据 |

**份额折算为什么单独成表**：份额折算没有现金流出，是「1 份变 x 份」的乘性变换；现金分红是加性口径。混表会让下游把 `share_ratio=0` 的行误读成「零分红事件」。单独成表后，两类事件各自可审计。

**因子为什么不并入 `stock_adj_factor.parquet`**：实测个股因子快照 5,655 只、基金代码 0 只；该快照的 `covered_codes.txt` 语义是「已覆盖个股集合」，混入基金代码会破坏个股线的覆盖判定。独立 `fund_adj_factor.parquet` + `fund_covered_codes.txt` 可保持两条线互不污染；schema 一致，读侧可统一处理。

### 2.2 因子口径（与个股一致）

```
factor = (prev_close - cash_amount) / (prev_close * share_ratio)
```

- `share_ratio` 即拆分比例 `1:x` 中的 x（无份额变动为 1）；反向折算 `1:0.01` 会让因子达到 100，因此仅基金路径把 `max_factor` 放宽到 1000（个股仍为 10）。
- qfq = 未来事件因子累乘（展示）；hfq = qfq / 全部事件因子（收益）。事件行处因子跳变，与个股一致。
- 事件生效日对齐（实测）：
  - ETF（159/51x/56x/58x/520/530）现金分红：公告除息日**当天**；
  - LOF（16x/15x/50x）、REITs（508/180）现金分红：除息日**下一个交易日**（场内价格比净值晚一天切换）；
  - 份额分拆/折算：折算日**下一个交易日**。
  - 事件表保留公告原始日期，对齐只发生在因子挂载时。

## 4. 两个边界问题

### 4.1 哪些基金分红拿不到 / 不需要复权

| 类别 | 规模 | 影响 |
|---|---|---|
| 从未发生现金分红的基金 | **2,180 / 2,615（83.4%）** | 无需复权；其中 202 只分级子份额无分红但有份额折算，已覆盖 |
| 累计型 ETF、货币基金（511xxx 为主） | 511 前缀 50 只，仅 13 只有分红；货币基金收益计入份额、通常不分红 | 无现金分红事件，价格本身不含除息跳空，无需复权 |
| 无分红 LOF / 场外份额 | LOF 570 只中 366 只无分红 | 同上，无需复权 |
| `close=1.0` 占位行情基金 | **84 只**（严格口径：每行 close 均为 1.0） | 其中 **24 只 / 177 条**有现金分红事件，**18 只 / 148 条**落在行情区间内（17 只全部事件都在区间内），这 17 只的区间内因子非 1。没有可用价格，无法复权；166005 分红 1.0371 > 占位价 1.0，事件因子被公式判为无效 |
| 拆分页抓取 | **0 只最终失败**（首批 17 只瞬时失败，3 次指数退避后全部补齐） | 份额折算覆盖无缺口 |
| REITs | 93 只中 82 只有分红，11 只无分红 | 无分红者无需复权；有分红的已覆盖 |

**结论**：真正「拿不到有效复权」的只有 84 只占位行情基金（3.2%），按严格占位口径其中 **24 只 / 177 条**有分红事件、**18 只 / 148 条**落在行情区间内；另外 2,180 只本身没有现金分红（产品不分红），不需要复权。不存在系统性缺口。

**口径更正：旧稿的「10 只」错在哪**

旧稿写的「84 只中仅 10 只有分红」是把另一条统计挂错了对象。该「10」的算法是全集差集 `{有现金分红的代码} − {因子存在非 1 行的代码}`，即「有分红但因子未变」，其成员是 6 只占位基金（160425、160627、162511、166005、166109、169108）+ 4 只非占位基金（166012、501049、501054、501063，行情止于 2019-09-17），**不是**「84 只占位组里有分红的只数」。按 84 只严格占位清单（每行 `close=1.0`）复算：有分红 **24 只 / 177 条**；至少 1 条落在行情区间内 **18 只 / 148 条**；全部事件都在区间内 **17 只**；区间内且有非 1 因子 **17 只**。差异来源是**统计条件/集合错配（复合条件误用）**，不是旧快照，也不是统计窗口不同。

**区间外事件是否应改变因子（160217 等 6 只）**

判定：**符合预期，区间外事件不改变因子**。

- 晚于行情末端的现金分红/份额折算：`prepare_events_for_code` 在 `event_date > last_date` 时直接 `continue`，不进入事件表。
- 早于行情起点的现金分红/份额折算：`_next_trade_date` 把事件映射到首行，随后 `calculate_factors` 的 `searchsorted(..., side='left')` 得到 `pos == 0`（没有前收），按既定规则丢弃。
- 160217.SZ 的 5 条分红（2020-09-24 ~ 2026-09-23）全部晚于行情末端 2019-09-17，**一条都没有参与因子计算**；它出现的非 1 因子来自**区间内 8 次份额折算**（2013-01-04 ~ 2019-01-02，累计比例 1.4067，对应 qfq 0.7108 / hfq 1.4068）。
- 本快照中 160217 的行情只有 4 行（2011-12-05 ~ 2019-09-17，全部 close=1.0），所以因子非 1 行数是 **4**；台账侧的 **2,346** 说明其行情快照是完整日线而非这 4 行占位，非 1 的来源仍是区间内那 8 次份额折算，结论不变。
- 其余 5 只（160425、160627、162511、166109、169108）在本快照中因子非 1 行数为 **0**：事件全部在区间外，已被跳过；若台账侧看到非 1，应来自其行情快照包含更早历史，使份额折算落入区间。

补充：这 84 只的行情是 close=1.0 占位序列，即使因子数学上成立（如 160217 的份额折算），经济上也无意义；第三条线重建 `quotes/fund` 副本时应跳过占位行情，不要把这类因子用于回测/展示。

## 7. mypy 门禁修复说明

修法一句话：**对 `.max()` 的返回值显式 `isinstance(rel, (int, float))` 收窄后再 `float(...)` 累加，不用 `# type: ignore`，不改变算法语义。**

类型含义说明：`None` 只可能来自「空序列的 max」；该分支已由前面的 `frame.is_empty() / snap.is_empty()` 排除，因此 `None` 在这里代表「没有可校验的行」，而不是「因子值为 None」。若真遇到 `None`，跳过该标的不计入误差是正确行为；没有把它静默兜成 0，也没有修改因子计算。因子列本身在写盘前已 `fill_null(1.0)`（日期不在快照 = 当日无事件、因子为 1），与可逆性校验互不冲突。
