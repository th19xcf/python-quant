## 0 先分清两条轴

- **轴一（存储与归属）**：写入按三级上台——① 采集原样落 `_staging/<任务>_<日期>/`；② 同目录候选 parquet 经逐值对拍与行数守恒后才可上台；③ 正式层 `data/local_store/`。正式层再分三类：**基础表**（七类）、**派生表**（由基础表算出、可整表重建）、**跑批产物**（`backtest_runs/`，不属正式口径）。
- **轴二（维护口径）**：**数据层** = `quotes/` 下 stock / fund / index 全部有行情的标的，检查断裂、缺失、滞后，不因是否入池而缩小范围；**视图层** = 数据层之上筛出的消费视角（ETF 候选池、股票池分层、剔除标记），只判视图是否新鲜、池内标的是否可交易。两套口径各出结论、互不抵扣。

**收口判定（2026-11-15 实测）**：**可收口**。保鲜体检 13 行 `error 0 / warning 0`（唯一 `known_exception` 为 505888.SH）；最大滞后 2 天落在 `factors/fund_dividend.parquet`（事件表按文件刷新日判，合法）；行情全集 9,789 只（股票 5,832 / 基金 2,622 / 指数 1,335）无未登记断裂，已知停更 696 只均已登记 `stale_status`；13 行受检表全部 ok（6 张日频表末日 = 行情末日 2026-11-13，事件表落 11-14 / 11-11，名录按最后检查日期 11-12~11-15）。158 条缺口登记全部定案：已修 68 / 接受偏差 51 / 等外部源 23 / 存量只读 14 / 合法零值 1，另有 1 条动作已定、条件不具备的标注项（G-144，动作/后果/重开条件已写死）。**剩余项只有五类**：接受偏差、等外部源、存量只读、合法零值、待执行标注——都不构成「数据不可用」，不再逐次回头评估。其中存量只读 14 条集中在三处：早期基金价格语义（G-062~G-066）、1993 年单源估值与量额（G-108~G-110、G-119、G-130、G-140）、冻结快照与离线宏表（G-075、G-114、G-117）；逐条名单见 `docs/数据缺口登记_正式表_2026-11-12.md` §5.5。

**重开条件（只有这五种才重评，其余按已定案执行）**：① 保鲜体检出现 `warning` / `error`（含全集未登记断裂 > 0、名录滞后 > 7 交易日）；② 「等外部源」条目拿到可采件；③ 消费方报错，或新增消费方按该字段取数；④ 基础表版本更替后 `audit` 出现 `missing`，或 `stale` 跨两个周更周期未消；⑤ 用户明确要求重评。另有两项不计缺口的观察项：`etf_pool` 当前 `stale`（下一次周更重建后自动转 `ok`）；`freshness_check` 尚有 53 条权威清单路径未纳入自检（属覆盖登记，出现异常按第 ① 条处理）。

**末日断言（第 4 步）**：`meta/daily_index.parquet` 的 `end` 最大值必须等于 `src.data.trading_calendar` 给出的最近已完成交易日（15:05 前当日 K 线未完成，取前一交易日）。不等即判失败，不再只记 warn 继续跑；显式 `--end` 早于最近交易日的回补模式按明示目标跳过该断言。

**第 5~6 步的增量口径**：先算范围再落盘，末日已最新时整步跳过；基金行情按通达信源末行增量，复权因子只重算「行情末日 > 因子末日」的标的，并把同步重写的行情副本登记进第 14 步白名单。可用 `--skip-fund-refresh` / `--skip-factor-refresh` 显式关闭。

采集按批次先落 `_staging/<批次>/`（`gaps.parquet` + 带输入集合哈希的 `input_set.json`），一次性 apply，同一批次名不允许换输入复用。

### 3.2 保鲜体检：判什么、怎么分档

`python -m src.data.quality.freshness_check --summary`，共 13 行 = `TABLE_SPECS` 12 张 + 行情全集 1 行。每行判「数据末日 / 行情末日 / 滞后 / 缺口 / 判定」，按 `kind` 分派：

| 判据 | 维度 | 分档 |
|---|---|---|
| 日频表（`daily`） | 数据末日落后行情末日的交易日数 | `0~1` ok / `2~5` warning / `>5` error |
| 事件表（`event`） | 按**文件刷新日期**算自然日滞后（连续无新公告属合法） | `≤30` ok / `≤90` warning / `>90` error |
| 名录（`base_info`） | manifest `last_checked_at` 的交易日滞后 + 「行情有而名录无」的未登记标的数 | 滞后 `≤7` ok / `8~10` warning / `>10` error；未登记 `>0` warning / `>5` error；`505888.SH` 为已知例外单列 |
| 估值（`valuation`） | 日期滞后 + 「行情末日仍在交易但估值缺失」只数 | 滞后同上表；缺失 `>0` warning / `>5` error |
| ST 水位（`st_watermark`） | `meta/st/coverage.json` 的 `snapshot_date` 滞后 | 同 `daily` |
| ST 覆盖窗口（`coverage`） | `coverage_end` 滞后 | 同 `daily` |
| 候选池（`pool`） | `coverage_end` 滞后（**视图层**） | `≤1` ok，其余只到 `warning`，不升 `error` |
| 行情全集（`universe`） | 行情文件未进 `meta/daily_index.parquet` 的只数 + 末根落后超 5 个交易日且未登记 `stale_status` 的断裂只数 | `>0` warning / `>5` error；已登记停更只报数量、不计缺口；指数侧车 `tail_gap` 声明的连续尾部缺口（源端只更新到此）同样不计缺口 |

汇总行格式：`[保鲜] | 行情末日 <日期> | 全集 N 只 | 名录 M 张最大滞后 K 天 | 表 13 | 最大滞后 K 天 | error E / warning W | 全部正常 / 红: … / 黄: …`。有 `error` 时命令以非零退出码结束。

2026-11-15 实测（本次收口判定依据）：`[保鲜] | 行情末日 2026-11-13 | 全集 9,789 只 | 名录 3 张最大滞后 1 天 | 表 13 | 最大滞后 2 天 | error 0 / warning 0 | 全部正常`；`--detail` 同次列出 53 条「权威清单中尚未纳入自检的固定路径」，属覆盖登记、不参与分档。

**登记表 §0.1 的五条重开条件分别由谁检查**：① 体检出现 `warning` / `error` —— 由既有 17:10 每日门禁 `tools/daily_data_gate.py` 的 `freshness_summary` 项自动判（随该命令执行，不新开会话、不额外计费；判据同本节，`error` 即门禁失败、`warning` 只记录）；② 「等外部源」拿到可采件 —— **人工发起**；③ 消费方报错或新增消费方取数 —— **人工发起**；④ 基础表版本更替后 `audit` 出现 `missing` 或同一派生表连续两次仍 `stale` —— 由同一门禁的 `version_audit` 项自动判（随该命令执行，不新开会话、不额外计费；`missing` 即失败；`stale` 对照最近一份 `gate_*.json`，同一表两天都落后即打印「连续两次落后」并落进 `checks.version_audit.stale_two_days`，仍只记录不阻断）；⑤ 用户明确要求重评 —— **人工发起**。五条中仅 ①④ 随每日门禁自动判，②③⑤ 与「等外部源」由人工发起，不新开定时任务或探测脚本。

### 3.3 候选池周更与排除清单

- 周期：`DEFAULT_POOL_REFRESH_DAYS = 7`，距 `meta/multi_asset/etf_pool.parquet` 上次重建不足 7 天不重建；重建前后按代码集合求差，输出「新入池 / 出池」。
- 排除清单：`meta/multi_asset/etf_pool_excluded.json`，`rule = equity_watch_no_candidate`，`criteria = 权益 ETF 且（adv_60d < 20,000,000 或上市不足 365 天）`；2026-11-13 评估 941 只，每条带 `reason` 与 `evaluated_at`。
- 口径边界：候选池是视图层筛选结果，不承担数据完整性；被排除标的的行情/分红由保鲜体检的全集判据负责，不能用「未入池」解释数据缺口。

### 3.4 基础表版本号与派生表 `based_on_version`

- `data/local_store/meta/data_version.json`：基础表版本台账，标识 `dv-YYYYMMDD-<12hex>`，`YYYYMMDD` 取行情末日（`daily_index.parquet` 的 `end` 最大值），`hex` 为七类基础表登记统计的汇总哈希。七类基础表在代码里归为**六个组件组**（行情 / 名录 / 财报+估值 / 因子 / 日历 / 事件），财报与估值同用 `meta/financials/manifest.json`。
- 只增不覆盖：`versions` 保留最近 50 个不同版本；同一版本重复计算只更新 `last_seen` / `seen_count`。
- `data/local_store/meta/derived_versions.json`：派生表侧车，记每张派生表「建它那一刻看到的是哪版」；**只记最新一次、不回填、不猜**，没有标记即 `unstamped`。
- 审计四态：`ok`（侧车 digest 与当前版本一致）/ `stale`（基础表已变、派生表未重建）/ `unstamped`（从未标记）/ `missing`（派生表文件不存在）。`python tools/data_version.py audit` 只报状态，不触发任何自动重建。
- 当前跟踪的派生表为 8 张：`etf_pool`、`breadth_daily`、`breadth_ma_daily`、`stock_turnover`、`st_intervals`、`universe/layers/l5_pool`、`state_vector_daily`、`research_inputs/analysis_monthly`；其余派生表暂无侧车（见第 4 节）。

### 3.5 备份与提交收尾

统一入口 `python tools/finalize_commit.py --paths <本次文件> --message <中文提交信息>`，默认 dry-run，`--apply` 才执行：

1. 取清单：`git status --porcelain` + 未跟踪文件，按文件族分组；
2. 隔离索引提交：只提交 `--paths` 命中的路径，`GIT_INDEX_FILE` 临时索引五步（基准取提交时刻父提交 → 种子化 → 显式更新 → 与预期清单比对 → 提交前复核 HEAD 未变），提交后另起进程 `git read-tree HEAD` 回填共享索引；
3. 备份同步：`resolve_backup_root()` 解析备份仓（环境变量 → `.trae/backup.local.json` → 报错停止），`copy2` 变更文件、对位删除源端已删文件，逐文件 SHA256 校验，核对「改动清单条数 == 已处理条数」；
4. 备份仓提交并推送（备份仓是唯一关联 GitHub 的仓库；源仓库仅本地提交）；
5. 自证：`git diff-tree --no-commit-id --name-status -r HEAD` 与预期清单逐条比对，多出或少掉即非零退出。
