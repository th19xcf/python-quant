## 0. 一句话结论

**六类候选里，本地「有数据且未因子化」的只剩公告标题这一条，而它是已有事件表的二次利用；
真正换信息源的新族，本地是零个。**

- 财务三大报表是唯一数据与 PIT 都齐备的类别，但它**已经被挖过**：26 因子池里有 6 个财务/估值因子，
  12 个财务候选全部实测过，最终在池内的只有 `g_sue` / `v_ep` / `v_cfp` 3 个（其中 `v_ep` 是池内原有同名因子），
  其余 9 个未采纳。
  继续在财务表里切新字段（费用率、周转率、应计细分）属于**同一信息源再切分**，不满足「信息源不同」的标准。
- 分析师预期、个股资金流/北向/龙虎榜、股东户数/股权质押（回购只有股本变动代理）、宏观景气指标、研报与舆情，
  本地**全部没有**，且项目里也没有对应的采集代码与数据库表，只能靠新增外部源。
- 公告文本只有**标题级**素材（185,653 行，中位 21 字，无正文），且已被结构化为 9 类事件并验证过
  「零个能进主池」。

因此「因子扩容可不可行」的答案取决于是否愿意补外部源，而不是取决于本地还有多少可挖。
本地这条路的结论是：**不可行（新增容量 ≈ 0）**；外部源这条路的结论是：**可行，但每个族都要先补数、再补 PIT 断言**。

## 1. 判定口径

| 判定 | 含义 |
|---|---|
| **现在就能做** | 本地已有原始数据、有可用的时点字段（或该族天然无前视），不需要新增外部采集即可构建因子 |
| **修完前置才能做** | 本地有部分素材（分类/代理/片段），但缺关键字段或口径，必须先补一层才能构建 |
| **本地没有** | 本地不存在该信息源的任何正式表、采集代码或数据库表，补源必须新增外部接口/账号/token |

**「覆盖度」三个数字的定义**：可用标的数 = 该表 `ts_code` 去重数；可用月份/年份数 = 该表 `end_date`/`date` 覆盖的独立月份/年份；
字段非空率 = `1 - null_count / rows`，按整表统计（不按行内条件过滤）。

### 2.4 PIT：现状到底缺哪一层（本节是重点）

**第一层（数据字段）——齐备。** 三表都有 `ann_date` 与 `ann_date_source`：

- `ann_date` 空值 **0**（三表都是 0），`ann_date < end_date` **0 行**（三表都是 0）。
- 但 `ann_date == end_date` 不是 0：income **720**、balance **649**、cashflow **7** 行，且**全部来自 `sina_publish`**，
  年份全部落在 1990–2009（income/balance）与 1998/2000（cashflow）。即新浪旧报表段这部分记录的「公告日」
  实际是**报告期本身**，不是真披露日 —— 详见本节「第四层」。
- 来源三态（以 income 为例）：`em_notice` 275,802 行（东财 `RPT_LICO_FN_CPD` 的 `NOTICE_DATE`，真公告日）、
  `sina_publish` 67,681 行（新浪返回的真实披露日）、`statutory_deadline` 1,220 行（源端无公告日，用法定披露截止日兜底）。
  balance / cashflow 的 `statutory_deadline` 分别为 1,252 / 1,236 行，三表合计 **3,708 行**。

**第二层（消费实现）——存在三套并行口径，且互不一致。**

| 实现 | 版本选择规则 | 用途 |
|---|---|---|
| [store.py](file:///e:/code/python/quant/src/data/financials/store.py#L211-L252) `latest_announced_as_of` / `latest_announced_panel` | 同一报告期取**最新**公告版本 | 供 `fundamental_factors.py` 等生产读侧 |
| [fundamental_factors.py](file:///e:/code/python/quant/src/advice/fundamental_factors.py#L247-L254) `_asof_join(..., 'ann_date')` | 按 `ann_date` 做 asof join，隐含「最新版本」 | 生产因子 `ff_*` |
| [build_new_factors.py](file:///e:/code/python/quant/tools/research/build_new_factors.py#L41-L46) `_first_announced` | 同一报告期取**最早**公告版本 | 研究候选 `q_*` / `g_*` / `v_cfp` |

「最早版」与「最新版」在发生财报更正/追溯调整时**会给出不同的因子值**，目前没有任何测试比对两者，
也没有任何断言禁止新代码直接按 `end_date` join。

**第三层（强制断言）——缺失，这是真正的缺口。**

- 全仓没有「财务因子必须带 `ann_date` 且 `ann_date <= t`」的断言或测试；
  `tests/` 下与 PIT 相关的只有 `test_adjustment_pit.py`（复权因子）与 `test_backtest_stale_filter.py`（退市/停更过滤），
  没有任何针对三大报表 PIT 的守护用例。
- 结果：新增财务因子时，只要有人写 `join(income, on=['ts_code','end_date'])` 就会静默产生前视，
  当前没有任何机制能拦住。

**第四层（数据质量，已知不可用于 PIT 的片段）。** `sina_publish` 段（利润表/资产负债表 1990–2009、
现金流量表 1996–2009，三表合计 181,939 行 = 67,681 + 62,175 + 52,083）
有 720 / 649 / 7 行 `ann_date == end_date`（income / balance / cashflow，全部来自新浪、全部落在 1990–2009），说明新浪旧报表接口
对这部分记录返回的是**报告期本身**而不是披露日。该段只能当「1990–2009 的财务数值来源」，
**不能当 PIT 可见性依据**；现有因子评估从 2015 起，规避了这段，但若把评估窗口前移到 2010 以前必须先处理这条。


### 2.5 重复度：这一族已经被挖过多少次

- 26 因子池（`docs/L1等权合成基线_2026-11-11.md` §2.2）里的财务/估值因子：`v_ep`、`v_cfp`、`ff_value_bp`、
  `ff_sales_yield`、`ff_div_yield`、`g_sue` —— **6 个 / 26 个**。
- 12 个财务候选的完整实测（`docs/候选因子增量评估_2026-11-11.md`）：
  6 个质量（`q_roe_ttm` / `q_roa_ttm` / `q_gross_margin` / `q_asset_turnover` / `q_accruals` / `q_ocf_to_profit`）

  分档结果：值得纳入 1（`g_sue`）、观察 3（`v_cfp` / `g_revenue_yoy` / `q_ocf_to_profit`）、不纳入 8
  （`q_roe_ttm` / `q_roa_ttm` / `q_gross_margin` / `q_asset_turnover` / `q_accruals` / `g_profit_yoy` / `v_ep` / `v_sp`）。
  其中 `v_ep` 被判不纳入，是因为池内已有同名存量因子，不是因为它无效。
  最终 12 个候选里只有 `g_sue` 属于「新增」入池；`g_sue` 在 h=5 过 N=20 门槛（t=4.35），h=20 的 t=2.66 不过线，属边际入池。

  `inventory`（存货周转）、`advance_receipts`。**但这些是同一张报表的再切分，不构成新信息源**，
  按题设「信息源不同」的标准不计入扩容容量。

### 2.6 判定

**现在就能做（数据层）/ 实际增量接近零（因子层）。**

- 数据与 PIT 字段齐备，今天就能构建新财务因子，不需要补数。
- 但同类信息已饱和：26 池已含 6 个，12 个候选里只有 3 个在池内、9 个未采纳。若还要在财务表上加因子，
  必须先回答「它和 `v_ep` / `v_cfp` / `ff_*` / `g_sue` 的区别在哪」，否则就是同一批信息换包装。
- **前置（非阻塞但必须补）**：① 加一条 PIT 断言/测试，禁止无 `ann_date` 的财务 join；
  ② 统一「最早版 vs 最新版」口径（当前三套实现并存）；③ 若评估窗口前移到 2010 年前，先处理新浪段 1,376 行报告期占位。

### 5.2 重复度：增减持这一半已被证伪

- `ev_dec`（τ=20 / τ=60）与三类增持已在 34 候选里完整测过：`ev_dec_t60` ΔIC +0.0014（t=3.53）、
  `ev_net_inc_big_t60` +0.0013（t=3.89），虽然过了 Bonferroni 门槛（|t|≥3.18），但幅度只有 +0.1% 量级；
  且这两个因子换成 zscore 残差后**直接反号**（Δ=−0.0011、t=−3.49），说明增量主要来自稀疏事件的尾部结构。
- 结论记录在 `docs/事件因子增量检验_2026-11-11.md`：**34 个候选能进主池的是零个**。
- 所以「股东行为类」里唯一有本地数据的子类（增减持）**已经被计入过扩容容量并判定为无增量**，
  不能再算一次。

### 5.3 PIT

- 增减持：`events.publish_time` 是公告发布时间，但实测 **85.3% 只有日期没有时分**
  （158,306 / 185,653 行的时分秒为 `00:00:00`，本任务实测；探测报告 §1.1 对 2025 年样本记 96%），
  现行面板统一按 T+1 保守处理，无前视。
- 回购代理（`stock_shares.effective_date`）是**股本变动生效日**，通常晚于回购实施，用它做因子会低估时效，但不产生前视。
- 股东户数 / 质押：不适用（无数据）。这两类若补源，披露口径天然带「报告期末 vs 披露日」两套时间，
  必须取披露日，否则同样是前视。

## 10. 结论

1. **按「信息源不同」的标准，本地可直接开工的新族只有一条：财务三表**，而它已经被挖过 12 个候选、
   26 池里占用 6 个席位、12 个候选只入池 3 个。继续在此加因子的预期增量接近零。
2. **公告文本是唯一「有素材但没因子化」的资产**，但只有标题级，且同源的结构化事件已被证伪；
   它能提供的是「结构之外」的信息，属于未验证假设，不算确定的扩容容量。
3. **其余四类（分析师、资金流、股东户数/质押、宏观景气）本地零资产**，且项目里连采集代码都没有。
   要扩容只能补外部源，每个族都要走「接源 → PIT 双日期 → staging → 对拍 → 原子替换」的完整治理流程。
4. **与现有结论一致**：候选因子线（34 个候选，过 |t|≥3.18 的只有 4 个，增量 +0.0008~+0.0019）
   与事件线（34 个候选 0 个入池）已经说明「同源再切分」没有容量。本次盘点把「不同源」也查了一遍：
   **本地没有不同源**。
5. **建议的下一步优先级**（若决定补源，按「独立性强 + 无 token + PIT 干净」排序）：
   ① 分析师预期（与现有全部因子正交性最高，东财接口无 token）；
   ② 股东户数（季度频、披露日明确、与量价/财务相关性低）；
   ③ 个股资金流（数据量大、需节流，且与换手/动量存在相关性风险，需先做正交性检验）；
   ④ 宏观景气（只对行业/风格层有用，对个股横截面 IC 帮助有限，优先级最低）。
   以上四项都**不在本任务范围内**，本任务只出清单与判定，未做任何采集。
