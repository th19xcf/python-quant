## 2. 相关系数实测：是「反向加权」，不是「重复计数」

关键对（完整 136 对见 `factor_correlations.csv`；`signed` = 乘双方 direction 后的有效相关，才是打分真正看到的符号）：

| 因子对 | 同组? | Spearman ρ | 符号后 ρ | 判读 |
|---|---|---|---|---|
| `momentum_6m` ↔ `momentum_12m` | 是（legacy 内） | **0.624** | 0.624 | **真重复**：同一动量在不同回看期 |
| `momentum_6m` ↔ `trend_slope_60` | 是（legacy 内） | 0.509 | 0.509 | 高度同向，信息重叠约 25% |
| `trend_slope_60` ↔ `sharpe_ratio_20` | 是（legacy 内） | 0.477 | 0.477 | 同向，重叠约 23% |
| `gtja_003` ↔ `gtja_024` | 否（趋势 vs 动量） | **0.663** | 0.663 | 跨组真重复：6 日方向动量 vs 5 日动量 |
| `momentum_6m` ↔ `gtja_024` | 跨来源 | 0.225 | **−0.225** | 有关但不同义；符号相反 → 部分对冲 |
| `momentum_12m` ↔ `gtja_024` | 跨来源 | 0.164 | **−0.164** | 同上 |
| `momentum_6m` ↔ `a101_024` | 跨来源 | 0.111 | **−0.111** | 弱相关，符号相反 |
| `trend_slope_60` ↔ `qlib_rsqr20` | 跨来源 | **−0.032** | +0.032 | **几乎无关**：带符号斜率 vs 无方向拟合度 |
| `trend_slope_60` ↔ `gtja_003` | 跨来源 | 0.036 | **−0.036** | 几乎无关 |
| `gtja_024` ↔ `a101_024` | 同组 | −0.263 | −0.263 | 同组内反向：短动量 vs 条件反转 |

**结论（与「两套动量/趋势因子方向相反、重复计权」这一假设有出入，必须分开说）：**

1. **统计意义上的重复只有 3 对**：`momentum_6m`/`momentum_12m`（ρ=0.62）、`momentum_6m`/`trend_slope_60`（0.51）、`gtja_003`/`gtja_024`（0.66）。它们才是「同一个概念被算了两次」。
2. **legacy 与 extended 之间不是重复**：动量对 0.11~0.23、趋势对 0.03~0.04。它们是**不同定义、不同回看期**的量（简单收益率 vs 平滑短动量 / 条件反转；带符号斜率 vs 无方向拟合度）。按任务边界要求，**不能硬并成一组当重复处理**。
3. **但方向冲突真实存在**：这些低相关因子的**符号相反**（signed ρ 为负）。所以配方做的不是「同一个指标加两遍」，而是「给两个相关度不高的指标相反的符号」——净权重 +0.025 看起来中性，实际是在用两个不同信号互相压制，留下的是噪声与风格漂移（见 §3 的方差与 §4 的选股结果）。

## 4. 净效果量化：不是「互相抵消到没作用」，而是「符号组合制造噪声」

各分组贡献 = `w·d·z`（缺失记 0），score = Σ贡献 / Σ|w|。方差份额用 `cov(贡献组, score)/var(score)`，各组之和为 1。

|---|---|---|---|---|---|
| 动量 | **0.4665** | **0.4544** | **0.5020** | **0.4718** | **0.4218** |
| 趋势 | 0.2494 | 0.2756 | 0.1617 | 0.1115 | **0.3515** |
| 风险调整收益 | 0.0810 | 0.1462 | 0.1263 | 0.1692 | 0.1427 |
| 回撤 | 0.0835 | 0.0631 | 0.0940 | 0.0861 | 0.0231 |
| 下行波动 | 0.0131 | −0.0485 | −0.0171 | −0.0334 | −0.0200 |
| 量价反转 | 0.0087 | 0.0145 | 0.0143 | 0.0149 | −0.0052 |
| 流动性 | −0.0034 | 0.0139 | 0.0108 | 0.0126 | 0.0246 |
| 跳空反转 | 0.0316 | 0.0256 | 0.0320 | 0.0596 | 0.0240 |
| VWAP | 0.0525 | 0.0551 | 0.0768 | 0.1087 | 0.0386 |

- **动量+趋势合计占 70.2%~79.4%**，是 score 的主要方差来源。所以「两个维度几乎互相抵消、实际没在起作用」**不成立**。
- 组内两块的抵消程度（`cancellation.csv`）：
  - 动量：legacy 块 std 0.137~0.148，extended 块 std 0.045~0.100，两块相关 **−0.212/−0.062/−0.349/−0.324/−0.020**，净 std 0.141~0.174，**净/两块之和 = 0.61~0.79**。
  - 趋势：legacy std 0.064~0.069，extended std 0.082~0.099，相关 0.004/0.202/−0.131/−0.260/0.088，净 std 0.105~0.119，**比值 0.63~0.78**。
- 判读：净 std **不小于** legacy 单块（动量 0.152 vs 0.147 等），说明扩展块更多是在「加方差」而非「互相抵消」；真正的伤害不是方差被抹平，而是**高分区被两组相反符号拉向中间，排序被噪声主导**——这与 §5 的选股结果一致（Top15 的 MA 多头数 1/0/6/2/0）。

1. 归零 legacy 确实把「Top15 与多头排列」的冲突基本解掉（14/10/12/13），**但 2026-07-20 仍是 0**——那天全市场只有 7.4% 的票在 MA20/MA60 之上，属于**市场状态问题，不是因子问题**。

3. 两版 Top15 重合只有 1/1/4/1/2 只，**组合被彻底改写**——这一改动的风险不是「微调」，是换了一套持仓。

补充：把软筛选的「多头排列」反转成 `ma20_gap<0 & ma60_gap<0` 的实测通过只数为 **2/3/0/0/0**，比现行更差，说明「顺着反转方向改软筛选」也不成立。

方案 B 的折算规则（避免重复计权、又不大改权重）：

- 对相关 ρ 的一对因子，合并为 `z_c = (z_1 + z_2) / sqrt(2(1+ρ))`，权重取两者符号权重之和（保持该组总权重不变）。
- ρ=0.62 时，合并后方差与「两个独立因子」口径一致；不除这个因子会把重复信息放大 1.6 倍（`2/(2(1+0.62))` 的倒数）。
- ρ<0.3 的对一律不合并（本档里 legacy↔extended 全部属于此类）。

## 7. 结论

1. **重复计权只有 3 对**，且其中 2 对在 legacy 内部；「legacy 与 extended 是同一个概念算两遍」不成立——相关系数 0.03~0.23，是不同的定义。
2. **方向冲突成立**：`cb55a9e`（2026-11-11 13:19）只翻了 legacy，扩展仍 +1，signed ρ 为负；软筛选也是 `440d228` 引入、当时与 legacy 同向，翻转后变成对立。
3. **净效果不是「互相抵消到没作用」**：动量+趋势占 score 方差 70%~79%，净 std 并未塌缩；问题是高分区被两股相反符号拉向中间，排序变成噪声。
4. **legacy 归零能修「Top15 与多头排列」的冲突，但修不了空仓**：两个空仓期仍为 0，2026-07-20 更是全市场仅 7.4% 多头排列的市场状态问题。
5. 因此**下一步应先把「可买只数」做成时间序列**（与市场状态解耦地看），再谈因子合并；直接改权重会把「市场状态」「打分方向」「软筛选」三件事混在一次试验里，无法归因。详见 [寻优路线图_2026-11-11.md](file:///e:/code/python/quant/docs/寻优路线图_2026-11-11.md)。
6. **§9 补充（同日补算）**：extended 12 因子首次做同口径 OOS 验证，`gtja_024`/`gtja_003`/`gtja_010`/`a101_020` 四个方向与实证相反，因此方案 A 原样不可执行；扩展因子也不能沿用「48 组已验过方向」的结论。以 §9 为准。

## 9. 前置问题：extended 的 IC 符号（2026-11-11 补算）

### 9.1 一句话回答

**不一致。归零 legacy 之后，动量维度不是「纯顺势」，而是「一个实证反向 + 一个实证正向」的对冲：`gtja_024` 的 OOS IC 是负的（h=60：−0.0929，t=−6.81），与 legacy 同向；只有 `a101_024` 是正的（+0.0343，t=+2.49），强度约为前者的 1/3。两者权重都是 0.10。所以 A 方案原样执行，会把「实证正确但撞软筛选」换成「一半与实证相反、且反向的那一半更强」，不能做。**

### 9.2 口径

- 样本与统计完全复用 `_staging/factor_oos_verify_20261111/run_oos.py`：全 A（剔除北交所）、上市满 250 日、剔除停牌/ST/T+1 开盘涨跌停、标签 `T+1 开盘 → T+1+h 收盘`、每 h 个交易日非重叠取样、逐日截面 Spearman、Newey-West t(lag=1)。
- 区间：IS 2015-01~2021-12，OOS 2022-01~2026-10；h ∈ {5, 20, 60}，主表给 h=60（long 档持有期），h=20 并列。
- 扩展 12 因子用生产函数 `compute_extended_candidates` 计算；价格在 hfq 空间，`vwap = amount/(volume×100)×hfq_factor`，`ret = close/close[-1]−1`。

- 范围只覆盖 `long` 档实际在用的 12 个扩展因子（`enabled_extended_columns()`）；扩展候选池里未接线的因子不在本次范围。

### 9.7 替代方案 E：动量整组降权到 ≤0.05

- **会不会引入新冲突**：不引入方向冲突，但会把权重自动让给 VWAP（归一 +0.0883）、`ff_amihud_60`（+0.0989）、`max_drawdown_20`（+0.0761）这几块，风格从「动量+趋势」整体换成「VWAP 折价 + 非流动性 + 回撤」，属于**换风格**而不是**修错**。

1. **A 方案原样不能做**：`gtja_024` 的 IC 为负且最强，归零 legacy 会让动量块期望 IC 由 +0.0188 转为 −0.0293、全表由 +0.0120 转为 −0.0138。
2. 若目标只是「解除打分与软筛选的对立」，与实证一致的最小修法是 **A′**（legacy 归零 + `gtja_024`/`gtja_003` 翻 −1），期望 IC +0.0253，优于现行 +0.0120，需 1 次复算；但这是 3 处及以上改动，须先报后动。
3. **比 A 更高杠杆的单点问题**是 `gtja_010`（w=0.10、IC −0.0868、t=−3.62）。单翻它一个，全表期望 IC 可到 ≈+0.0294；但**不得只按 IC 翻符号**——须先核对 `gtja_010` 的实现（rank 方向、`MAX(...,5)` 窗口、缺失处理）是否本身写反，确认后再决定「翻方向」还是「改实现」。这一步属于「改变既定口径」，按项目规则需带证据单独报批。
4. **D 可作为「可买只数」层的临时缓解，但不是方向修复**：它不改变任何因子的符号，只在软筛选上放松，平静期通过只数明显上升，两个空仓期仍不解；与 IC 的一致性没有改善。
5. **E 在当前因子表下不成立**：既缺价值/换手因子，又会降低已实证为正的暴露。若要做，顺序应是「先修 `gtja_024` → 再做权重合成」，而不是先降权。
6. 本次未改动任何权重、代码、配置或数据；上述 A′/A″/`gtja_010` 都只是测算，未执行。

### 10.2 逐条对照（表达式级）

**① `gtja_003`**——[gtja191.py](file:///e:/code/python/quant/src/quant/factor_lib/factors/gtja191.py#L65-L74)

原始（GTJA Alpha191 #3）：
```text
SUM((CLOSE = DELAY(CLOSE,1) ? 0
     : CLOSE - (CLOSE > DELAY(CLOSE,1) ? MIN(LOW, DELAY(CLOSE,1))
                                       : MAX(HIGH, DELAY(CLOSE,1)))), 6)
```
当前实现：
```python
prev = o.delay(C('close'), 1)
inner = pl.when(C('close') > prev).then(
    pl.min_horizontal(prev, C('low'))
).otherwise(pl.max_horizontal(prev, C('high')))
return o.ts_sum(pl.when(C('close') == prev).then(0.0).otherwise(C('close') - inner), 6)
```
逐项：相等分支→0 ✓；上涨取 `MIN(LOW, 前收)` ✓；下跌取 `MAX(HIGH, 前收)` ✓；窗口 6 满窗 ✓。**无偏差**。公式含义是「收盘价相对前收保护位的下穿幅度」，数值越大越偏空，与登记方向 `?` 和 OOS IC −0.0684 一致。

**② `gtja_024`**——[gtja191.py](file:///e:/code/python/quant/src/quant/factor_lib/factors/gtja191.py#L33-L39) 与 [#L190-L194](file:///e:/code/python/quant/src/quant/factor_lib/factors/gtja191.py#L190-L194)

原始：`SMA(CLOSE - DELAY(CLOSE,5), 5, 1)`
当前实现：
```python
def sma_tdx(expr, period, m=1):
    return expr.ewm_mean(alpha=float(m)/period, adjust=False, min_samples=1).over(o.GROUP)

return sma_tdx(o.delta(C('close'), 5), 5, 1)
```
逐项：`CLOSE-DELAY(CLOSE,5)` ✓；通达信 `SMA(X,N,M)` 递推 `Y=(M·X+(N−M)·Y_prev)/N` 对应 `alpha=M/N=1/5` ✓；`adjust=False` 与 `min_samples=1` 保证首值取 X、不引入前置均值 ✓。**无偏差**（预热期 1 行起有值，但生产按 250 行掩码，不影响）。复算值与生产跑出的 −0.09286 完全一致，交叉验证通过。

**③ `gtja_010`**——[gtja191.py](file:///e:/code/python/quant/src/quant/factor_lib/factors/gtja191.py#L105-L111)

原始：`RANK(MAX(((RET < 0) ? STD(RET, 20) : CLOSE)^2, 5))`
当前实现：
```python
base = pl.when(C('ret') < 0).then(o.ts_std(C('ret'), 20)).otherwise(C('close'))
staged = o.stage(panel, _sq=o.ts_max(base.pow(2), 5))
return o.out(staged, o.rank_cs(C('_sq')))
```
逐项：条件分支 ✓；平方 ✓；5 期满窗最大值 ✓；横截面 `rank_cs` ✓。**表达式无偏差**。

唯一的**口径偏差**：`CLOSE` 取的是后复权价（[data.py](file:///e:/code/python/quant/src/quant/factor_lib/data.py#L14-L21) 明确「价格列为后复权价」），而论文/研报用的是**原始价**。这不是小数点问题：横截面比较后复权绝对价 ≈ 比较「累计复权因子」，会混入长期涨幅。实测改用 `raw_close` 重算：h=60 为 −0.0722（t=−2.75）、h=20 为 −0.0637（t=−2.50），**仍显著为负**。所以负号不是复权口径造成的，方向仍该翻；价格空间这处偏差另记为待办（改成 `raw_close` 属于实现口径改动，须单独一次试验，不与翻方向同批）。

**④ `a101_020`**——[alpha101.py](file:///e:/code/python/quant/src/quant/factor_lib/factors/alpha101.py#L235-L246)

原始（WorldQuant Alpha#20，Kakushadze 2016 Appendix A）：
```text
(-1 * rank((open - delay(high, 1)) * (open - delay(close, 1)) * (open - delay(low, 1))))
```
当前实现：
```python
frame = o.stage(panel,
                g1=C('open') - o.delay(C('high'), 1),
                g2=C('open') - o.delay(C('close'), 1),
                g3=C('open') - o.delay(C('low'), 1))
frame = o.stage(frame, r1=o.rank_cs(C('g1')), r2=o.rank_cs(C('g2')),
                r3=o.rank_cs(C('g3')))
return o.out(frame, -1.0 * C('r1') * C('r2') * C('r3'))
```
差异：论文是**先乘再 rank**（`rank(g1·g2·g3)`），实现是**先各自 rank 再相乘**（`rank(g1)·rank(g2)·rank(g3)`）。`rank` 不是乘性可交换算子，两者不等价；连登记表里的 `expression` 字符串也被改写成了「三个 rank 相乘」，与「逐字抄录论文」的模块声明不符。

实测反事实（同一面板、同一标签）：

| 版本 | OOS IC(h=60) | t | OOS IC(h=20) | t |
|---|---|---|---|---|
| 现行实现 `-1·rank(g1)·rank(g2)·rank(g3)` | −0.0337 | −2.05 | −0.0344 | −2.45 |
| 论文实现 `-1·rank(g1·g2·g3)` | **+0.0444** | **+3.96** | +0.0217 | +2.03 |

按论文实现，**方向 +1 就是对的**，根本不需要翻符号。所以这是 code bug，不是方向约定错。
