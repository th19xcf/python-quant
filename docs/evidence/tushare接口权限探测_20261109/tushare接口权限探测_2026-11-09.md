## 1. 探测方法

- 每个接口**只发 1 次最小请求**，失败不重试（避免刷额度）；只有 `anns` 因接口名错误补测了正确名 `anns_d` 1 次。
- 接口间 `sleep 1.5s`，避免触发分钟级限频。
- 最小参数取单只标的（`600000.SH` / `000001.SH` / `510300.SH`）+ 2024 年内正常交易日（`20240102`）或年报期（`20231231`），避开停牌与新股。
- 判定口径：
  - **可用**：返回 DataFrame 且无异常（行数为 0 但无报错也算可用，说明是数据为空而非权限问题）；
  - **积分/权限不足**：错误文本含「没有接口(xxx)访问权限」；
  - **接口不存在/参数错误**：错误文本为「请指定正确的接口名」等非权限类错误。

## 4. 一个必须说明的差异：文档门槛 ≠ 实测权限

官方权限页（`doc_id=108`）标注的最低分值与本账号实测不完全一致：

| 接口 | 官方最低分值 | 本次实测（120 分账号） |
|---|---|---|
| `daily` | 120 起 | ✅ 可用（一致） |
| `daily_basic` | 2000 起 | ✅ 可用（**高于文档标注**） |
| `index_basic` | 2000 | ✅ 可用（**高于文档标注**） |
| `index_daily` | 2000 起 | ✅ 可用（**高于文档标注**） |
| `dividend` | 2000 起 | ✅ 可用（**高于文档标注**） |
| `stk_limit` | 2000 起 | ❌ 无权限（一致） |
| `income` / `balancesheet` / `cashflow` / `fina_indicator` / `disclosure_date` | 2000 起 | ❌ 无权限（一致） |
| `fund_basic` / `fund_daily` / `fund_nav` | 2000 | ❌ 无权限（一致） |
| `index_weight` | 2000 | ❌ 无权限（一致） |
| `index_member_all` | 2000 | ❌ 无权限（一致） |
| `suspend_d`、`top10_holders` | 权限表首页未单列 | ❌ 无权限 |

**结论：以实测为准，但不能据此认为 `daily_basic` / `index_basic` / `index_daily` / `dividend` 长期可用。** 这类「低于文档门槛却放行」通常是账号历史权限、试用额度或服务端白名单，积分规则调整后可能随时收回。任何自动任务都不应把 4 个接口写成硬依赖而不做降级。

## 5. 120 积分下哪些交叉验证真能做的

### 5.1 现在就能做（有实测支撑）

| 交叉验证项 | 依赖接口 | 落地方式 | 备注 |
|---|---|---|---|
| **交易日历对账** | `trade_cal` | 拉 SSE 全量日历（单次可跨年），与本地由行情推导的交易日集合做差集 | 与 [数据可用性矩阵](数据可用性矩阵_2026-11-09.md) 第 6.1 节「交易日历可从行情推导」互为验证；这是当前最有价值的一项 |
| **股票列表对账** | `stock_basic` | 拉 SSE 在市列表，与 `names.json` / 本地 `stock_basic` 的代码集合比对缺失与多余 | 单次返回 2318 行，一次拉全，成本极低 |
| **名称变更历史对账** | `namechange` | 逐票（或按日期区间）核对 ST/更名记录，校验本地名称表的时间切片 | `600000.SH` 2024 年 0 行属正常（无更名） |
| **指数目录对账** | `index_basic` | 拉 SSE 指数清单（208 条），核对本地指数代码与名称 | 与 `index_daily` 抽样配合 |
| **分红送股对账** | `dividend` | 按票核对分红方案与除权日，校验本地分红表字段 | 单票全历史 78 行，一次可得 |
| **日线/复权/每日指标抽样核对** | `daily`、`adj_factor`、`daily_basic` | 只能**抽样**（单票单日）核对价格、复权因子、流通市值 | 受分钟级限频限制，**不适合全市场对账** |

### 5.2 必须等提分（2000 起）才能做

| 想做但被挡 | 依赖接口 | 卡点 |
|---|---|---|
| 涨跌停价校验、连板/涨跌停统计 | `stk_limit` | 2000 起 |
| 停牌日校验、停牌导致的缺口归因 | `suspend_d` | 权限表未单列，实测被挡 |
| 财务三表与勾稽校验（资产=负债+权益等） | `income` / `balancesheet` / `cashflow` | 2000 起 |
| 财务指标（ROE/毛利率等）与本地因子比对 | `fina_indicator` | 2000 起 |
| 财报披露日与事件研究窗口对齐 | `disclosure_date` | 2000 起 |
| ETF/基金净值与场内价格折溢价校验 | `fund_basic` / `fund_daily` / `fund_nav` | 2000 |
| 指数成分与权重、指数成分变动归因 | `index_weight` / `index_member_all` | 2000 |
| 十大股东、公告事件补全 | `top10_holders` / `anns_d` | 权限表未单列 / 实测被挡 |

### 5.3 一句话回答

> **120 积分真正能做的是「元数据层全量对账 + 行情层抽样校验」：交易日历、股票列表、名称历史、指数目录、分红这 5 类可以全量做，日线/复权/每日指标只能抽样。**
> 财务、基金、指数成分权重、涨跌停、停牌、公告这 6 大类交叉验证，**必须把积分提到 2000 以上**才有接口权限；`stk_limit`、`income` 等按官方权限表标注为「2000 起」，`fund_portfolio`、`fund_adj` 更高（5000 起），但这几项本次未实测，仅按官方文档记录。
