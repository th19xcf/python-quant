# MySQL 日常读取盘点与估值域切换方案（2026-11-16）

> 只读盘点，未改代码、未改数据、未访问 MySQL、未写任何 `.trae/rules/` 条目。
> 范围：`tools/daily_update.py` 的 17 步日常链路；非日常的 GUI/工具链单列第 4 节。

## 1. 结论

- 日常链路触达 MySQL 的只有 6 处：**1 处取数口径依赖**（估值/财务的标的域）、**3 处名录类**、**2 处本地缺失时才读的兜底**（日常不触发）。
- 估值域换成本地 `meta/stock_basic.parquet` 的 `status == 'L'`：域规模 **5,579**，与现状 **5,579** 持平；逐码 **+1 只（688827.SH）/ −1 只（002731.SZ）**。
- 第一次日更**不会突然多采一批**：请求数与今日相同（±1），耗时变化 <1%。
- 唯一实质风险是 `code_table` 非致命步失败时本地名录会晚一天，需在读取处加「新鲜度闸门」。

## 3. 估值域换源的量化（核心）

### 3.1 候选源对比

| 候选 | 规模 | 新鲜度 | 语义 | 判断 |
|---|---|---|---|---|
| **A. `meta/stock_basic.parquet` `status=='L'`** | **5,579** | 每日 `code_table` 重建（早于估值步） | 在市；实测 5,579 只 L 全部有行情 | **推荐**：与 MySQL `status=='L'` 同义，零新依赖 |
| B. `meta/universe/listing_intervals.parquet` 活跃区间 | 5,574 | T+1（末日 11-11） | 把 5 只停牌/久无成交判 stale | 会误剔 5 只，且本身滞后一天 |
| C. 行情文件存在 + 近 N 日有 bar | 5,832 | 当日 | 含 253 只已退市 | 域偏大，退市股每天空跑 |
| D. `meta/names.json` | — | 当日 | 纯码表，无 status/delist_date | 需再叠状态，等于重做 A |

### 3.2 与现状（MySQL 域）的差异

本地事实（实测）：

- `meta/stock_basic.parquet`：**5,916** 行 = L **5,579** + D **337**。
- `quotes/stock/`：5,832 个文件；**全部**能在 stock_basic 找到行；5,579 只 L **全部**有行情文件。
- 「有行情但不在本地名录」：**0 只**——用户要求点出的反向情形不存在。
- 253 只 D 仍有行情文件（退市后残留），另有 2 只 L 久无行情：`688496.SH`（末日 2026-09-10）、`002717.SZ`（10-12）。

MySQL 现状（推断，见 3.4）：5,813 行 = L **5,579** + D **234**（D 集与 `reports/from_www_tmp_20261109/stock_basic_234.csv` 逐码 233/234 吻合）。

逐码差异：

| 方向 | 数量 | 例子 | 说明 |
|---|---|---|---|
| 新增（本地 L，库无） | **1** | `688827.SH 钶锐`（11-10 上市） | 即本次被静默跳过的标的；11-15 已人工补入 5 行估值 |
| 减少（库 L，本地 D） | **1** | `002731.SZ 萃华退`（11-12 退市） | 退市后不再需要增量；历史行保留 |
| 净值 | **0** | 5,579 → 5,579 | |

### 3.3 第一次日更会发生什么

- 估值请求 5,579 次（现状 5,579），**没有批量回采**：`688827.SH` 已有 11-10~11-16 共 5 行；域内其它代码在 `valuation_daily` 均有历史（实测 L 集全部覆盖）。
- `002731.SZ` 停止增量；`valuation_daily.parquet` 为追加式合并，**不会删历史**。
- 耗时：±1 只标的、3 并发 + 节流，变化 <1%。
- 行为改善：以后新上市股在上市次日自动进入估值域，不再依赖库同步。

### 3.4 证据缺口与补证动作

| 缺口 | 现依据 | 补证动作 | 影响 |
|---|---|---|---|
| MySQL 侧 L 集未实测 | ① 11-10 盘点 5,813 行；② 234 只 D 清单；③ 库自 11-09 未再同步 `stock_basic` | 授权后一条只读 `SELECT ts_code,status FROM stock_basic`（5,813 行，<1 分钟） | 若不符，只需重算 3.2 两行数字，选源方案不变 |
| 本地 `symbol` 列质量 | 本地 stock_basic 含 `symbol`，与 MySQL 同源字段 | 抽查 20 只 `symbol == ts_code[:6]` | 不等价时用 `ts_code` 前 6 位兜底 |
