## 4. 关键表逐段说明

### 4.1 `stock_dividend` → 本地分红快照（**第一优先**）

- **读取路径**：唯一「库→本地」入口是 `refresh_factors`，默认拒绝，必须同时给 `--allow-remote`、`--force-overwrite`、`--confirm OVERWRITE-LOCAL-SNAPSHOT`；写前还校验「事件减少/除权日倒退/因子末值不一致」。运行期分红**只读本地 parquet**（[store.py:705](file:///e:/code/python/quant/src/data/local_store/store.py#L705)），仅当本地缺失且 `DATA__REMOTE_DATABASE_FALLBACK=true` 才回退库（[data_fetcher.py:864](file:///e:/code/python/quant/src/data/managers/data_fetcher.py#L864)）。
- **落盘**：`factors/stock_dividend.parquet`，60,052 行 / 5,681 只，`ex_date` 空 671。
- **消费者**：① `AdjFactorCalculator.calculate_factors` → 本地因子重算；② 回测 [corporate_actions.py](file:///e:/code/python/quant/src/backtest/engine/corporate_actions.py) 除权记账；③ `financials/collector.py` 股息率；④ `share_capital.py` 送转；⑤ `advice/replay.py` 风险核查。
- **校验证据**：见 §3.1。关键实测：库内 52,263 条有 `ex_date` 的行与本地 `mysql_remote` 子集**逐键完全一致，仅 2 条数值差**；但库内 `ex_date` 最大只到 **2026-07-09**，本地已到 **2026-11-13**——**本地早已超出库，库不再是增量来源**。
- **库侧可被随手改**：[update_calibrate_stock_dividend.py](file:///e:/code/python/quant/tools/update_calibrate_stock_dividend.py) 会直接改库内负值/去重，[cleanup_stock_dividend_index.py](file:///e:/code/python/quant/tools/cleanup_stock_dividend_index.py) 会直接 `DELETE` 库内指数分红行；两者都没有单测与审计日志。这进一步说明「库值」本身不是可信基准（对齐 `data_governance.md` DG-15）。
- **可替代源**：**无**。TDX 不提供分红文件，仓库无 `.day` 解析分红的实现；只能靠外部公告/东财/新浪重建。
- **结论**：风险不在「库会覆盖本地」，而在「历史 52,263 条库快照只做过抽样对拍，仍有已证实的漏记」。唯一「关键链路 + 无替代源 + 对拍不完整」的表。

### 5.1 P1 `stock_dividend` 验证方案

1. **先跑可离线部分（0 外部依赖）**：用本地行情逐只计算 `close/pre_close` 跳空，与 `stock_dividend` 事件双向匹配。
   - 样本：**全量** 5,681 只、60,052 行（有 `ex_date` 的 59,381 行）。
   - 判定：① 事件→跳空：除权日理论除权价与实际 `pre_close` 相对误差 ≤ 0.5%（现金分红 < 0.05 元可放宽）；② 跳空→事件：单日跌幅 ≥ 2% 且无事件 = 疑似漏记；单日涨幅 ≥ 2% 且无事件 = 疑似送转漏记；③ 同一 `(ts_code, ex_date)` 重复 = 0（当前仅 1 组 1991 年老记录）。
   - 产出：漏记/多记/金额不符三张清单，作为外部核对输入。
2. **再抽样外部对拍**：
   - 源：新浪分红历史（逐只，复用 `sina_cache`）+ 交易所分红实施公告（配股/送转必须看公告）。

   - 判定：送转比例 **0 容差**；现金分红误差 ≤ 0.001 元/股；一致率 ≥ 99.5%，任何送转不一致逐条裁决。
