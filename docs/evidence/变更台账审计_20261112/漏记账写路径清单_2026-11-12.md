## 结论

- 全仓搜索 `changelog`：只有 `src/data/changelog.py` 自身与 `tests/test_changelog.py` 引用，
  **没有任何数据写路径 import 或调用台账模块**。因此 9,566 条 create/update 记录只能来自

- 扫描 `write_parquet_atomic` / `write_text_atomic` / `write_bytes_atomic`（含 `_write_*_atomic`
  包装器）的全部调用点：**69 个文件 / 169 处**。
  - **112 处直接改正式表**（`data/local_store/**`，含 staging→正式层的提升调用）；
  - 57 处写 staging 分片、断点进度、`reports/**`、`logs/**` 或 `research/events/data/**`。
- 另有 24 处直接 `DataFrame.write_parquet`（未走 atomic_write），集中在
  `tools/margin_daily.py`（217/247/602）、`tools/treasury_yield.py`（213/241/479）与
  `tools/research/**`；均为分片 / 候选 / 研究产物，正式终表仍走 atomic（

- 判断：漏记账是**上百处**，且根因是「写层没有统一入口」。逐处补 112 个调用点既不可维护，
  也挡不住以后新增脚本；应在 `src/data/atomic_write.py` 的写入口统一埋点（仅当目标落在
  `data/local_store/**` 时自动记 `create/update`，写入前读旧 SHA256 记 `prev_sha256`），
  再对需要 `delete`/`move` 的少数路径保留显式 `record_delete` / `record_move`。

## 埋点落地后的覆盖情况（2026-11-12 晚）

已在 `src/data/atomic_write.py` 写入口统一埋点，规则为「目标落在 `data/local_store/**` → 记 `create` / `update`」：

- 写前不存在记 `create`、存在记 `update`，判定基于 `os.replace` 之前的目标状态；
  `prev_sha256` 优先取 `manifest.json`（bytes + mtime 同时一致才用），否则流式重算；
- `_staging/`、`_backup/`、`reports/`、`logs/`、`research/` 不记；`delete` / `move` 仍显式调用；
- 台账自身写盘用 `suspend_changelog_recording()` 显式关闭埋点（不靠路径偶然性）；
- 记账失败写 `logs/data_changelog_failures.csv` + stderr 告警，不抛异常、不影响数据。

**真实对照**（`tools/reconcile_p2_metadata.py --commit`）：台账新增 2 条目标记录，磁盘恰好 2 个目标文件变化——
`placeholder_codes.parquet` 记 `update`（bytes 3329→3331，`prev_sha256` 与改前实测一致），
`coverage_gaps.parquet` 记 `create`（bytes 4188，`prev_sha256` 为空）；两条的 `sha256` / `bytes` 与写入后实测逐值相等。

**开销实测**（612.5 MB `valuation_daily.parquet`，各 3 次取中位数）：埋点关闭 0.641 s，埋点开启 1.538 s（+0.897 s，约 2.4 倍，未出现十倍级退化）；增量来自写前旧哈希与写后新哈希两次全量读。

**仍需单独处理的例外**：

1. `manifest.json` 与历史遗留在正式目录内的 `*_progress.json` / `*_registry.json` 等断点文件，同样落在 `data/local_store/**`，按路径规则会被记为 `update`。这属于「伴生元数据/断点」，若要排除须加显式白名单；本次保持路径规则，不隐式特判。
2. **绕过 `atomic_write` 的直接写盘仍不记账**：例如 `tools/reconcile_p2_metadata.py:184` 直接 `Path.write_text` 改 `fund_meta.json`、`tools/build_trading_calendar.py:236` 手写 `coverage.json`。这类应改成 `write_text_atomic` 才能纳入埋点；按「不擅自改调用点」的约定本次未动。
3. `delete` / `move` 不做自动推断，仍由 `record_delete` / `record_move` 显式记录。
