## 3. 数据管道健全性

### 3.1 关键路径、失败阻断面与可重入性

| 环节 | 实现 | 失败会阻断什么 | 可重入 | 断点机制 | 等级 |
|---|---|---|---|---|---|
| TDX `.day` → `quotes` 增量 | `build.py` 按 coverage/source 末日期分类 | 全下游（所有回测/推荐） | 是（幂等覆盖） | 逐标的 coverage | 高（影响面） |
| `meta` 覆盖元数据 | `store.flush_meta` | 新鲜度、可交易判定、覆盖统计 | 是 | 重建 meta | 高（影响面） |
| 复权因子 / 分红 | `refresh-factors` | 所有价格可比性与收益计算 | 是 | 全量重写 | 高（影响面） |
| 财务 / 估值 | `financials/collector.py` 分片 | PE/PB、财务筛选、事件 | 是 | `progress.json` + `_mark_valuation_done` | 中 |
| 行业 / ST / 指数成分 | 日频快照 + 差分 | 行业上限、涨跌停幅度、池子 | 是 | 快照日文件 | 中 |
| 事件（公告） | 外部 parquet → `import_file` | 事件过滤、风险提示 | 是（replace/merge） | 无（靠整体重导） | 中 |

**判断"哪一步失败导致下游全失效"**：`quotes` 与 `factors` 是两个总闸；`meta` 是隐性总闸（不报错、只让覆盖判定退化）。三者都是单文件原子 + 幂等重跑，工程上可收敛；不可收敛的只有"源端已无数据"的情况（见 3.4）。[代码直接证据] + [工程推论]

### 3.3 质量门禁：判据覆盖与漏检
