## 二、逐列语义判定

### 2.1 同名同义列：只有主键，无因子列可对拍

列名交集只有 `ts_code` / `date`，**没有任何同名因子列**，因此不存在「同名但口径不同」的隐性冲突，也不存在「同名同义列取值不一致」。

| 键集完全一致 | True |
| 交易日集合相同 | True |
| 标的集合相同 | True |

即两表是**完全同键**、可无残差按键回接的两个列块。

### 2.2 异名列的「同义换名」排除

为避免「同一因子换了列名」被漏判，对 `new_factors` 每个因子与 `analysis_monthly` 全部 33 个数值列做池化 Spearman（567,541 行全量）：

| 因子 | 最相关列 | ρ | 是否构成替身 |
|---|---|---|---|
| `turnover_20` | `atr_pct` | 0.6857 | 否（价量波动幅度，非换手） |
| `accruals` | `ff_investment` | 0.3459 | 否 |
| `roe_stability` | `ff_value_ep` | 0.6281 | 否 |
| `sue` | `momentum_12m` | 0.2334 | 否 |

最大 \|ρ\| = 0.6857，**没有任何近似 1 的替身**，可排除「改名重复」。

### 2.3 四因子的口径与覆盖（`new_factors` 独有）

口径来源：`tools/research/build_new_factors.py` 顶部文档（第 5–13 行）。

### 2.4 派生关系（谁以谁为骨架）

`tools/research/build_new_factors.py`：

- 第 373–376 行：`base = pl.read_parquet(base_path, columns=['ts_code','date'])`，`base_path` 默认取 `output_dir / 'analysis_monthly.parquet'`；
- 第 388 行：`out = base.join(to, on=['ts_code','date'], how='left')`；

即 `new_factors` 以 `analysis_monthly` 的行网格为骨架、左连接 4 个因子列后写出。这与 §2.1「键集完全一致、0 孤儿键」在数据上互相印证。**它是补充列块（阶段 3/3），不是 `analysis_monthly` 的另一版本。**

### 3.1 用途是否重叠

**唯一同时读两表的是 `build_multifactor_signals.py`，且是互补左连接，不是二选一**：`analysis_monthly` 提供标签 `fwd_ret`、中性化用 `ln_mv`/`ind_code`、以及 5 个价量/估值因子；`new_factors` 只提供 `accruals`/`sue` 两个财务因子。两表在此处的角色是「同一行上的不同列块」，不存在「同一列从两个来源取、取到哪个算哪个」的分叉点。

`new_factors` 的 `turnover_20` 与 `roe_stability` 两列目前**无任何正式读取点**（`build_multifactor_signals.py:14` 明确「`turnover_20` 未加入」；`roe_stability` 未出现在任何 `read_parquet(columns=...)` 清单）。

## 四、判定依据汇总

| 判据 | 实测 | 是否支持「同语义多份」 |
|---|---|---|
| 列集是否一方为另一方的子集 | 双向皆 False，交集仅主键 | **否** |
| 是否存在同名列可对拍 | 0 个同名因子列 | **否**（无冲突面） |
| 是否存在高相关替身列 | 最大 \|ρ\| = 0.6857 | **否** |
| 行键是否完全一致 | 567,541 对 567,541，两向 0 孤儿 | 是（同粒度） |
| 产出链是否同一支 | 阶段 2/3 写 AM、阶段 3/3 以 AM 主键为骨架写 NF | **否**（上下游） |
| 消费者是否各自成链、用途重叠 | 仅 1 个脚本同时读，且为互补 join | **否** |

→ 同粒度、同键、**内容互斥且互补**，属「一个面板拆成两个列块」；按任务书分类落在 **B**。
