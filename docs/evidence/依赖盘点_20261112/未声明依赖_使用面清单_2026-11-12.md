## 三、`cupy = "*"` 与 README「运行时依赖固定 `==`」的冲突

### README 原文与位置

`README.md` 第 **340** 行是小节标题 `## 开发约定`，第 **342** 行第 1 条为原文：

> 依赖管理：Poetry；运行时直接依赖固定为 `==` 版本，`poetry.lock` 锁定全部传递依赖（不要在未更新锁文件的情况下手工 `pip install` 升级依赖，否则回测结果不可复现）

第 **343** 行第 2 条紧接着点名了 gpu 组：

> 可选依赖组：`dev`（pytest / ruff / mypy / black，默认安装）、`gpu`（cupy，`poetry install --with gpu`）；GPU 缺失时 `gpu_acceleration.py` 自动降级为 NumPy

冲突点：`pyproject.toml:79` 是 `cupy = "*"`，是全文件唯一没有版本上界的直接依赖。

### 为什么不能简单写成 `cupy = "==14.2.0"`

实测 PyPI `cupy 14.2.0` 的发布文件**只有 1 个：`cupy-14.2.0.tar.gz`（sdist）**，`requires_python >=3.10`，**没有任何 wheel**——既无 Windows wheel，也无 cp314 wheel。本机是 Windows 11 + CPython 3.14.9，写 `cupy ==14.2.0` 后 `poetry install --with gpu` 会走源码编译 CUDA 扩展，实际装不上。

能装上的是**变体分发**（`import` 名仍是 `cupy`，代码不用改）：

| 分发名 | 版本 | Windows wheel | cp314 Windows wheel |
|---|---|---|---|
| `cupy-cuda12x` | 14.2.0 | 6 个（cp310–cp314 win_amd64） | **有**：`cupy_cuda12x-14.2.0-cp314-cp314-win_amd64.whl` |
| `cupy-cuda13x` | 14.2.0 | 11 个（含 win_arm64） | **有**：`cupy_cuda13x-14.2.0-cp314-cp314-win_amd64.whl` |

代码侧兜底已就位：[gpu_acceleration.py](file:///e:/code/python/quant/src/tech_analysis/gpu_acceleration.py#L93-L95) `cp = _import_cupy()` → 失败时 `cp = np`，所以换分发名不影响运行。

### 建议改法

```toml
[tool.poetry.group.gpu.dependencies]
# PyPI 的 cupy 只发布 sdist，Windows / cp314 无 wheel；按本机 CUDA 主版本选变体，
# import 名同为 cupy，gpu_acceleration.py 无需改动。
cupy-cuda12x = "==14.2.0"   # 本机 CUDA 12.x 选这行；CUDA 13.x 则换 cupy-cuda13x
```

并在 README 第 343 行补一句：「`cupy` 在 PyPI 只有 sdist，Windows 需用 `cupy-cuda12x` / `cupy-cuda13x` 变体（`import cupy` 不变）」。

说明：本机没有 `nvidia-smi`、也没有 NVIDIA 驱动（上一份报告已记），gpu 组当前根本不可用，所以这条改动不影响现状；改的价值是让声明可执行、与 README 的 `==` 约定一致，而不是留一条永远装不上的声明。
