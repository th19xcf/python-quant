## 2. `exists → skip` 修复（DG-31）

### 2.1 旧行为

`_staging/state_inputs_20261110/collect.py` 的分片断点是：

```python
target = PARTS / f'margin_sse_{year}.parquet'
if target.exists():
    return           # 分片一旦落地，永不刷新
```

后果与现场吻合：11-12 00:35 那次运行重取到 11-10 后落盘，此后 11-11 即使源端已发布，
本地分片仍被判为「已存在 → 跳过」，缺口集合里永远不会出现 11-11。

### 2.2 新行为

`shard_state()` 把每个分片判成三态，`collect_sse()` 按态处置：

| 状态 | 判定 | 处置 |
|---|---|---|
| `missing` | 分片文件不存在 | 抓取 |
| `gap` | 分片存在，但缺至少一个应有交易日 | **重取并覆盖** |
| `ok` | 分片覆盖该年全部应有交易日 | 跳过（`--refresh-current` 时最新年份例外） |

### 2.3 改前失败输出（同一断言，旧规则必失败）

复现命令（fixture：应有交易日 = `[2026-11-10, 2026-11-11]`，分片内只有 `2026-11-10`）：

```
[改前] 应有交易日=[2026-11-10, 2026-11-11] 分片内=[2026-11-10]
  old_collect: exists -> skip，不发请求
  [改前失败输出] AssertionError: 刷新后应覆盖末个交易日 2026-11-11
[改后] status={2026: 'gap'} 抓取年=[2026] 末个交易日=2026-11-11
```

同一断言在旧行为下报 `AssertionError`，在新入口下通过——即该断言确实能对「固化滞后」失败，
不是永远为真的空断言。该对照固化在 `tests/test_margin_daily.py::test_old_exists_skip_rule_fails_refresh_assertion`。

> 说明：`collect_sse()` 返回的是**抓取前**的判定（`{2026: 'gap'}`），用于日志与后续汇总；
> 抓取是否成功看 `progress.csv` 的 `fetched rows=... still_missing=...` 一列。

### 2.4 三种情形均有覆盖

| 用例 | 锁定行为 |
|---|---|
| `test_missing_shard_is_fetched` | 缺某年分片 → 抓取，末行推进到应有末日 |
| `test_covered_shard_is_skipped` | 已覆盖应有交易日 → 不发请求，状态 `ok` |
| `test_stale_shard_is_refreshed` | 已有但滞后 → **重取**，末行推进到应有末日，状态 `gap` |
| `test_shard_state_triplet` | `missing / gap / ok` 三态判定 |
| `test_old_exists_skip_rule_fails_refresh_assertion` | 旧规则对照组（DG-31） |
| `test_refresh_current_forces_current_year_refetch` | `--refresh-current` 强制重取最新年份 |
| `test_sz_gap_days_only_returns_missing_and_not_done` | 深市缺口 = 沪市有 − 东财有 − 已完成 |
| `test_assemble_marks_sources_and_units` | 合并时 source 分段与 ×1e8 单位换算 |
| `test_patches_fill_only_nulls_and_fix_defect_row` | 只补空值 + 缺陷行 4 格，已有非空值不得覆盖 |
| `test_patches_leave_uncovered_sz_row_null` | 未命中官方记录的 sz 空值行保持为空（显式兜底，非 coalesce 出 null 别值） |
| `test_patches_missing_input_raises` | 小输入缺失直接报错（不可重建，禁止静默降级） |

## 3. 两步字段级补丁一并搬迁（口径不变的证据）

`_staging/sz_margin_sec_20261110/` 的字段级补丁：

| 补丁 | 来源脚本 | 作用面 |
|---|---|---|
| 深市融券两列空值回填 | `build_fill.py` | `sec_qty` / `sec_sell_qty` 各 1,322 处（2020-08-20 ~ 2026-11-05 东财不提供该列） |

缺陷行只改那 4 格，未命中一律 `otherwise(原值)`（DG-31 显式兜底），并在函数内断言四段语义
（两列回填数相等、回填数 ≤ 官方覆盖天数、缺陷列各 1、其余列为 0）。

## 6. `cn_treasury_yield_10y` 盘点（只盘点，未实施）

**结论：存在与两融完全同型的结构性缺口。**

### 6.1 表本身（实测）

```
rows 5464   cols [date, y10, source]   span 2005-01-04 ~ 2026-11-11
source 分段：chinabond:bond_china_yield 5,176 行 | eastmoney:bond_zh_us_rate 288 行
```

### 6.2 采集代码在哪

| 环节 | 位置 | 缺陷 |
|---|---|---|
| 取数（中债分年） | `_staging/state_inputs_20261110/collect.py:44` `treasury_chinabond()` | `if target.exists(): return` —— **与两融一模一样的固化滞后** |
| 取数（东财补段） | `_staging/state_inputs_20261110/collect.py:79` `treasury_eastmoney()` | 同上，`exists → return` |
| 组装 | `_staging/state_inputs_20261110/build.py` → `cand_treasury_yield_10y.parquet` | 只在 `_staging` |
| 发布 | `_staging/derived_catchup_20261112/publish_macro.py`（`append_only` + DG-11 + manifest） | 与两融共用一个一次性脚本 |

### 6.3 是否只在 `_staging`

是。全仓 `tools/` 下**没有任何写该表的入口**：

- `tools/build_cn_bond_tables.py:101` 只把 `cn_treasury_yield_10y.parquet` 当**对拍基准**读，
  不产出它（它产出的是 `cn_treasury_yield_curve.parquet`，多期限长表）；
- `tools/backup_critical_assets.py:90` 把它列入 `CRITICAL_FILES`（说明不可丢）；
- 消费者：`tools/build_state_vector.py:407`、`tools/verify_state_vector.py:332`（运行时读取 `y10`）。

即：**被研究链路消费、被列入关键资产、被登记权威路径，但更新代码只在可清理的 `_staging`**。

### 6.4 缺什么入口

缺一份 `tools/treasury_yield_10y.py`，形态可对齐 `margin_daily.py`：

```
collect  chinabond 分年（按年缺口重取，替换 exists→return） + eastmoney 补段
build    两段合并 → cand；断言 y10 与既有重叠日逐值一致
publish  同 margin_daily.publish：DG-11 备份 + append_only + 原子写 + manifest
```

### 6.5 实施前必须先定的两处口径（不能照搬两融）

1. **分段语义不同**：两融是「按 `market` 分 sh/sz」，treasury 是「**同一列 `y10` 按时间段分源**」
   （chinabond 5,176 行 + eastmoney 288 行），`source` 列交替出现在时间轴不同段。
   合并时必须按「chinabond 优先、eastmoney 补尾段」定序，不能像两融那样 `unique(keep='first')` 了事。
2. **东财补段的切换点**：288 行覆盖哪段区间、以什么条件触发东财段（源端缺口还是固定起点），
   现状只写在 `build.py` 里，需先读代码确认，再决定是否原样搬。

按 DG-29「改变既定口径且无实测证据即须停手」，这两点未确认前不动手。
