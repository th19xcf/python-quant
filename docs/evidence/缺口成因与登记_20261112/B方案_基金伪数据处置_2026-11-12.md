## 4. 路径一为什么本阶段不可做（schema 风险实测）

`src/data/quote_schema.py` 把行情分片 schema 定义成硬契约：

- `QUOTE_COLUMNS['fund']` 固定 13 列、**列顺序**也校验（L40-47、L133-134）；
- `assert_formal_quote_glob_schema`（L217）对**一组分片**逐文件比对签名，任一文件多一列即抛 `QuoteSchemaError`；
- 模块 docstring L5-9 记录过真实事故：2026-11-12 一次 19 行成交量修复给 7 个 `quotes/stock` 分片多加了 `basis` 列，全库 schema 不再统一，**10 个消费方同时失效**（polars 2.1.0 多文件 schema 合并不豁免列投影下推）。

因此加列必须一次做全：① 改 `QUOTE_COLUMNS`/`QUOTE_DTYPES`；② **全量重写 2,620 个基金 parquet**（不能只改这 5 只，否则任何 glob 读都 SchemaError）；③ 重跑 `flush_meta`、`_align_written_factor_copies` 与因子一致性校验。第三条正是 2026-11-11 16:25 那次全量重建崩掉的地方（`flush_meta` 抛 `ComputeError`，见 `docs/行情重写核查_2026-11-11.md`）。

与本次边界直接冲突：`quotes/manifest.json` 本阶段只读、待两条数据线收口后统一重建；另一条线正在补 G-079 的 22 行 stock 分片。加列会把三条线绑在一起，风险远大于收益。

## 5. 路径二的具体做法（建议）

1. **补登 358 行**：向 `meta/anomalies/placeholder_quote_codes.csv` **只追加行**，不改列结构；`full=false`。影响文件 1 个，不触碰任何 parquet。
2. **加一个只读门控模块** `src/data/quality/fund_price_basis.py`：
   - `pseudo_dates(root, ts_code) -> set[date]`：读 csv 展开区间；
   - `is_pseudo(root, ts_code, date) -> bool`；
   - `tradable_slice(frame, root, ts_code)`：剔除区间内行，返回可参与收益计算的行。
   纯只读、无缓存写入、不改 schema。
3. **消费侧接入三处即可覆盖主要链路**：
   - `run_backtest.py` / `clean_set.py`：在日频选池前用 `pseudo_dates` 排除当日不可交易行（现在只挡 `full=true`）；
   - `research/events/macro_event_study.py` 与任何从 `quotes/fund` 算收益的入口：首个真实成交日之前不出收益；
   - `etf_data_audit.py` 与 `build_multi_asset_etf_pool.py`：把 `placeholder_ranges` 从「自建」改为统一调用该模块，避免两套判据。
4. **登记与元数据**：在 `quotes/fund` 的 `manifest.json`（待统一重建时）与 `docs/数据权威路径清单.md` 中登记「伪数据区间」与门控模块，`_staging` 之外不新增数据文件。
5. **不删除任何行**：`data/` 红线不变，2,748 行原地保留，只做「读取侧过滤 + 台账登记」。

与 G-075 的关系：G-075 要加的 `is_template` / `exclude_reason` 在 `meta/events/events.parquet`，**与 quotes schema 完全不耦合**，不需要并进本次改动，建议按原计划单独做（入库层加列只需重建 events 一张表，不涉及 2,620 个分片）。
