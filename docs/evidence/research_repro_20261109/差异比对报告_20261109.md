## 4. 差异根因（三条独立证据）

### 4.1 行数差 100% 由 clean_set 准入规则放宽造成

- 现有产物生成于 2026-11-05 18:44；`eligible_set(d, tier='strict', data_type='stock')` 的结果随后变化：
  - `meta/clean/eligibility_2026-11-05.parquet`：strict 股票 eligible = **4,770**
  - `meta/clean/eligibility_2026-11-06.parquet`：strict 股票 eligible = **5,377**（+608 / −1）
- 新增的 608 只中，**594 只在 11-05 属 `div_doubt`，原因全为 `structural_rights_no_second_source`**；11-06 已归入 `remaining`（如 `600833.SH`、`600639.SH`、`000423.SZ`、`600066.SH`）。另有 13 只由 `data_defect` 转合格，1 只（`302132.SZ`）反向转 `data_defect`。
- 该规则变化的来源是提交 **`8b9eedd`（2026-11-09）"配股事件经独立第二源核验后不再视为存疑"**，改的是共享库 `src/data/quality/clean_set.py`，不是归档脚本。
- 数值吻合：2026-10-30 现有 4,772 行 vs 重跑 5,380 行，与 4,770 → 5,377 的差一致；新增行按年均匀分布（每年 5,869~7,418 行），649 只中多数为全历史 142 个月——说明是"整只标的准入状态翻转"，不是个别月份异常。

### 4.2 `ff_*` 在 2015-2017 由全空变为可用：估值表回补

- `data/local_store/meta/financials/valuation_daily.parquet` mtime = **2026-11-08 22:29**（晚于现有产物 11-05 18:44）；同目录 `progress.json` 的 `updated_at = 2026-11-08T22:29:08`，`statements` 列表包含 2010-2015 全部报告期 → 是一次回补刷新。
- 结果：`ff_size` / `ff_value_bp` / `ff_value_ep` / `ff_sales_yield` 在 2015-2017 的非空行数由 **0** 变为 25,948~35,928。
- 反证同一口径：`ff_div_yield` 在 2015-2017 **仍是 0**——因为 `dv_ratio` 在该区间仍全空（与审计文档 G1 一致），说明变化只来自 `total_mv` 回补，不是脚本或因子定义变化。

### 4.3 `roe_stability` / `sue`：财报三表回补

- `meta/financials/{income,balance,cashflow}.parquet` mtime 全部为 **2026-11-08 20:56**。
- 共同键上非空覆盖大幅扩张：`roe_stability` null 97,652 → 19,024，`sue` null 144,370 → 72,078，`accruals` null 63,302 → 15,178。
- `accruals`（只取最近一期）在共同键上 **0 差异**，而依赖 8 期窗口的 `roe_stability` / `sue` 有差异——与"补齐了历史报告期、最近一期未变"完全一致。

## 5. 判定与建议

- 归档脚本是**忠实搬运**：除路径参数化外未改逻辑；共同键上价量四列 + `accruals` 逐值完全相等，可证。
- 两份 parquet **可重建**，但重建结果绑定「运行时点的 `clean_set` 版本 + 数据快照」，不是位级可复现的历史快照。
- **不建议用重跑产物替换现有文件**：行数 +16.8%、`ff_*` 覆盖口径变化、`roe_stability`/`sue` 数值漂移都会改变 IC/分组/回测结论。是否升级到新口径属于研究结论变更，需单独决策。
- 建议后续：把"复现脚本 + 依赖版本（clean_set 规则提交号）+ 数据快照日期"写入产物旁注；若希望产物可位级复现，需要在生成时固定这三项并记录哈希。
