## 1. P0-1 洁净集基金分红口径（最高风险，已闭环）

**纠正误判**：`_resolve_fund_pending_scope()` 的实际默认已是 `'etf'`
（`clean_set.py:154`），模块 docstring 与测试也都按 `etf`；只有 CLI `--help`
文案写成「none（默认）」。因此「按文档默认重建会把 strict 基金打回 0」在
当前代码下**不成立**。真正的问题是：口径只在进程内存/代码默认值里，
`summary_*.json` 与 `eligibility_*.parquet` 都不记录 scope，产物无法自证，
换机器或改环境变量后无法解释池子变化。

**改动**：
- 新增 `read_persisted_scope()` / `write_persisted_scope()` / `_scope_resolution()`；
  解析优先级改为 **显式 CLI > 环境变量 > 持久化配置 > 代码默认 `etf`**。
  持久化落 `data/local_store/meta/clean/fund_dividend_pending_scope.json`
  （该目录本就在不可重建资产备份契约内）。**未走 `.env`**：`os.getenv` 不读
  `.env` 文件，写进去不会生效；`.env.example` 的读取被安全策略拦截，本轮
  未重试、未绕过、未修改。
- 新增 `fund_pending_summary()`；`summary_*.json` 增加 `fund_dividend_pending`
  块（`effective_scope / requested_scope / origin / degraded /
  etf_codes_count / etf_codes_source / persisted_scope / config_path / note`）；
  `eligibility_*.parquet` 每行增加 `fund_dividend_pending_scope` 列。
- CLI 修正 help 文案，新增 `build --persist-scope {all,etf,none}`。
- 文档 `docs/数据可用性分层_2026-11-04.md` 补口径优先级与「比较 strict 基金数
  前先核对口径」的警示；README 补重建命令。
- 新增 4 项单测（持久化往返、优先级、产物口径块、降级兜底），并给 autouse
  fixture 加配置隔离。

**实测**：写入配置 `etf` 后，不带任何 scope 参数重跑
`build --as-of 2026-11-06`，产物为
`origin=persisted_config`、`effective_scope=etf`、`degraded=false`、
`etf_codes_count=1734`，`strict` 基金 **1,693**、个股 **5,377**（未回退 0）；
eligibility 共 11 列，新增列取值唯一为 `etf`。

## 3. P0-3 停牌表（误判，不补数）

`suspension/coverage.json` 实测 `end=2026-11-06`、`complete=true`、
`generated_at=2026-11-07T22:50:42`、`codes_covered=8432`、`suspended_rows=956403`；
parquet 的 `trade_date` 最大 11-05、`detected_at` 全为 11-06。

原因是**口径**：该表只登记「停牌/缺口行」，11-06 全市场都有 bar、没有缺口，
自然没有 11-06 记录。用 `max(trade_date)` 判断新鲜度会把「已扫到 11-06」
误读成「落后一个交易日」。已在 README 契约表与门禁 `reference_contracts`
的 `note` 中固化；门禁另加硬检查：suspension 的 `coverage_complete` 必须为
`true`。**没有重跑构建**（重跑只会把 `detected_at` 改成今天，破坏证据）。

## 4. P1 历史 PIT / 指数成分

### 4.1 指数成分：真实扩一天

中证官方接口自带 `日期=2026-11-06`，不是推断值。重新抓取 4 个指数
（000300 / 000905 / 000852 / 000016 = 300 / 500 / 1000 / 50 只）全部成功并落盘：

- 快照 **1 → 2 份**（11-05 + 11-06，8 个 parquet）；

  可精确定位区间；首份快照的纳入日依旧未知，`complete` 保持 `false`。
  这是防前视偏差的正确结果，不是失败。

**新增保护**：`build_index_membership` 改为「整批 4 个指数全部抓到才落盘」。
此前逐个落盘，若 1 个指数代理失败（本轮 dry-run 时 000852 确实失败过），
差分会把该指数全部成分判成「当日退出」，凭空产生上千条假 `out_date`。
新增单测锁住部分失败拒绝 commit、dry-run 允许部分成功。

## 6. P2 占位桩 / 豁免 / 日历

### 6.1 占位桩：修复两处真实缺口

1. **行级过滤从未接线**：`placeholder_ranges()` 上一轮已定义，但全仓 grep
   无任何消费方，148 只「头部/中段占位、后期有真实行情」的基金在读侧仍能
   拿到假 bar。新增 `drop_placeholder_rows()`（按 `(code,date)` 索引 + mtime
   缓存、台账缺失 fail-open），接入 `DataFetcher` 的单票与批量两条本地读路径；
   整只全假的 84 只仍由 `placeholder_codes()` 池级剔除，语义不重叠。
   台账实测 249 段 / 84 只 `full=true`。新增 3 项单测。
2. **基金巡检被日常命令漏掉**：`--data-type all` 原本只跑
   `('stock','index')`，上一轮新增的 `fund` 占位桩规则只有显式传
   `--data-type fund` 才会执行。改为三类全覆盖并加回归锁。
   修后全量巡检 **9,765 只 / 25,456,557 行**，249 条 `placeholder_bar`
   warning 全部命中台账，`actionable_errors=0`。

### 6.2 豁免：口径澄清 + 漂移校验

「9,411 行豁免」是巡检的 **9,411 条 error**（`required_columns` 6,274 +
`volume_invalid` 3,137），不是台账行数。台账 `quality_exemptions.csv` 实测
**6,274 行 = 3,137 个 (标的,日期) × 2 条规则**，与
`quarantine_rows.parquet` 的 3,137 行逐规则比对差集为 **0 / 0**。

新增 `exemptions.validate_against_quarantine()` 与门禁 `exemption_ledger`
检查项：两份台账必须逐规则互为镜像，缺文件按 fail-closed 处理。这样以后
任何一处手工改动而另一处没跟上，都会在每日门禁暴露，而不是变成「脏行
仍在读但门禁不报」。3 项单测覆盖一致、漂移、缺失。

### 6.3 未来交易日历

新增 `tools/refresh_trading_calendar.py`，从新浪官方交易日历
`tool_trade_date_hist_sina` 落盘 `meta/trading_calendar/official_future.parquet`
+ `coverage.json`；`trading_calendar.py` 改为三段式：

| 段 | 范围 | 来源 |
|---|---|---|
| 行情权威段 | ~ 2026-11-06 | 本地 `000001.SH` 真实交易日 |
| 官方未来段 | 11-07 ~ 2026-12-31（39 个交易日） | 官方已公布日历 |
| 近似尾部 | 2027-01-01 起（223 个工作日） | 工作日 − 配置节假日 |

`authoritative_end` **保持 11-06 不前移**（停牌/缺口构建依赖它，前移会把未来
日期误判为停牌）；新增 `official_end` / `is_official()` / `official_dates()`
与 CLI 输出。实测官方未来段与工作日近似在 11 月（21/21）、12 月（23/23）

近似段从 262 缩到 223**。

**残留边界（如实登记）**：2027 年放假安排尚未公布，2027-01-01（元旦周五）
目前仍被近似段当作交易日。不编造未公布的节假日；`is_official()` 已提供
