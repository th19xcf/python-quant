### 4.3 代码级根因

本轮补数脚本 `E:\www\tmp\fund_quote_gap_capture.py`：

- 第 103 行：`pre = float(row["pre_close"])` —— 直接取 tushare 原值，仅在为 `None` 时才兜底用本地 `prev_close`；
- 第 112-119 行：把该 `pre_close` 原样写入，并用它反算 `pct_chg`、`change`；
- 第 104 行：只做 `|pre - prev_close| > 0.3%` 的**事件登记**（写 `events.json`），**不纠正、不阻断**。

即：脚本把「tushare 的同一天两个快照互相矛盾」（0225 快照的 `close` vs 0226 快照的 `pre_close`）原样落进了本地文件。

与本地存量路径的差别（可对拍证明）：2020-02-25 的 fund 行共有 239 只同时出现在两个 tushare 快照中——

- **82 只**（本轮由补数脚本写入）：本地 `close(0225)` == tushare 0225 快照 `close`（100%），本地 `pre_close(0226)` == tushare 0226 快照 `pre_close`（100%）→ 两值都"忠实于上游"，但上游自相矛盾 → 本地异常。
- **156 只**（更早批次写入，未被本轮覆盖）：本地 `close(0225)` == tushare 0226 快照 `pre_close`（旧的自洽值），≠ 当前 0225 快照 `close` → 本地自洽。

结论：tushare 的 `2020-02-25` 收盘价在两次拉取之间被改动过（当前值偏低），而 `2020-02-26` 的 `pre_close` 仍是旧值。**本地只是继承，不是本地写入逻辑错误**；但补数脚本「原样继承 + 只登记不校验」放大了它。

## 5. 与阶段一的联系

阶段一的 75 个「hfq 未反映除权」事件里，**56 个**（74.7%）与本阶段的 110 行 `pre_close` 异常**同代码同日**。

机制：`hfq_factor` 是比例法累乘、当天比值为 1.0（`hfq_ratio` 全为 1.0），而 hfq 价格列 `= close × hfq_factor`。`close(2020-02-25)` 偏低 → `hfq(0225)` 偏低 → `hfq(0226)/hfq(0225)` 虚高 17%，与 `pre_close/close` 链看起来"对不上"。

所以阶段一的判定（0 个事件支持「hfq 漏记折算」）与本阶段结论完全一致：**病根在 `close(t-1)` 这一行，不在因子、不在 `pre_close`、更不在除权口径。**

### 7.3 原子替换步骤

1. 逐只 `copy2` 原 parquet 到 `_backup/preclose_fix_20261110/<ts_code>.parquet`，记录旧 SHA256（DG-22）。
2. staging 内生成候选全量行，逐只自检：
   - `low ≤ min(open,close) ≤ max(open,close) ≤ high`；
   - 修复行 `pre_close(t) == close(t-1)`（容差 0）；
   - 相邻两行 `hfq_factor` 比值不变（因子未被误改）；
   - 与腾讯同日 `open/close` 对拍一致，或差异已登记在 `failed.csv`。
3. 走 `src/data/atomic_write.py::write_parquet_atomic`（临时文件 → fsync → `os.replace`）覆盖 76 个正式文件，**不用 `write_parquet` 直写**（DG-9）。
4. 逐文件写 `manifest.json`：新 SHA256、行数、改动行号、改前值/改后值。
5. 全部成功后删除 `_staging/preclose_fix_20261110/`（DG-8 的窄例外）。

多文件替换不是单一事务（DG-10）：顺序为「先备份全部 76 只 → 再逐只替换」，中途失败时按 `manifest.json` 里记录的 `_backup` 路径逐只 `copy2` 回滚，未替换的文件保持原样，staging 保留。
