**测量口径**（避免手抄，全部由脚本直读）：

| 字段 | 取法 |
|---|---|
| 行数 | `pl.scan_parquet(p).select(pl.len()).collect()`；分片类逐文件求和 |
| 日期起止 | 按候选列 `date / trade_date / end_date / publish_time / ann_date` 自动识别；区间表用 `in_date/out_date`、`start_date/end_date`、`coverage_start/coverage_end`；事件表用 `ex_date`；文件名含 `YYYYMMDD` 的快照取文件名日期；四类都不成立时报「不适用」并写明维度 |
| 标的覆盖 | 有 `code / ts_code / symbol` 列时取 `n_unique()` |
| 消费者 | `git grep -n -I -e <pattern> -- src tools tests config`（pattern 在 `--` 之前，`--` 之后是 pathspec），只保留真实读路径，产出侧写入不算消费者 |
| 权威清单登记 | 逐行对照 `docs/数据权威路径清单.md` 实际行号 |
| manifest | 读同目录 `manifest.json`（或 `*.meta.json` / `*_manifest.json`），把声明的 `rows` / `sha256` 与实测比对 |
| 备份状态 | 相对路径存在性 + 逐文件 SHA256 抽查；未抽查的按 2026-11-12 的 100% 镜像结论记「已镜像」 |

## 5. `factors` 整层无 manifest（专项）

### 5.1 确认结论

**确认：`factors/` 下没有任何 `manifest.json`。** 全目录实测只有两个 json：

- `factors/meta.json` —— 字段说明，含 `factor_rows=18,129,900`；
- `factors/fund_meta.json` —— 字段说明，含 `factor_rows=2,974,925`。

两个 `factor_rows` 与实测行数一致（§4.1 已复算），但它们只是字段字典里的一个计数，**不是 manifest**：不含文件 SHA256、不含上游路径与 mtime、不含口径哈希、不含列清单。
（`factors/rebuild/manifest.json` 与 `factors/turnover_parts/manifest.json` 存在，但那是两个中间目录里给断点/分片用的，与这 5 张正式因子表无关。）

### 5.2 后果

| 后果 | 具体表现 |
|---|---|
| 无法校验完整性 | 文件被截断、被半写入、被错误覆盖时，没有任何独立记录可比对；只能靠下游算出「结果看着不对」才发现 |
| 无法追溯上游 mtime | 因子由 `quotes/stock` + `stock_dividend` + `stock_shares` 派生，但派生时读的是哪个版本的上游、上游当时 mtime 是多少，全无记录；出问题只能重跑猜 |
| 无法证明「同一输入恒得同一输出」 | 没有口径哈希，`rebuild-factors` 重跑后到底是不是同一口径无法自证；DG-20 要求的「受影响文件 SHA256」在写侧拿不到基线 |
| 与同层其它表不一致 | `meta/breadth`、`meta/macro`、`meta/state`、`meta/multi_asset` 都有 manifest，唯独最大的、被全链路消费的 `factors` 层没有 |
| 备份只能比字节，不能比语义 | `G:` 镜像能证明两侧字节一致，但证明不了「这份字节就是那个口径算出来的」 |

| 字段 | 含义 / 取值建议 |
