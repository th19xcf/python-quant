# 财报 PIT 全量补全（tushare）— 2026-11-09

> 目标：一次性补上 `数据可用性矩阵_2026-11-09.md` 中「三大表 2007–2009 红块」，并为本地推导 PE 提供**可时点对齐的公告日**（`ann_date` / `f_ann_date`），消除 `local:shares_x_close+fin_ttm` 段的前视风险。
> 本次只做数据补全与校验：不跑回测、不算因子、不改任何现有 parquet、不执行 git。

## 六、已知局限（必须随数据一起传播）

1. **重述不可还原。** tushare 的三大表只保留**最新重述版本**，`update_flag` 不提供历史版本链。同一 `(ts_code, end_date, report_type)` 出现多个 `ann_date` 的比例分别为 income 1.53%、balancesheet 0.26%、cashflow 0.93%、fina_indicator 0.13%，说明上游确实有更正公告，但**去重后只保留最新值**。
   → 「能用 `ann_date` 做时点对齐」**不等于**「能还原当时公布的原值」。做 PIT 时，2020 年的回测里看到的 2019 年报数字是 2024 年重述后的版本，存在**轻微前视（重述前视）**，量级远小于「报告期未公告就使用」的严重前视，但不可忽略。
2. **`ann_date` 的可信度分层。**
   - 全表 0 空值、0 条早于报告期末，中位滞后 51 天，与 A 股披露节奏吻合。
   - 但 14.6%（51,793 / 355,040）的行 `end_date < list_date`（上市前历史），其中 43,289 行 `ann_date < list_date` —— 这批「公告日」实际是**招股书披露日**，不是交易所公告日。由于个股上市前不可交易，不影响回测可用性，但不能当作严格意义的公告日引用。
   - 40 行 `ann_date == end_date`（1990–1996 年报），属早期数据瑕疵。
3. **`fina_indicator` 字段不全。** 无 `f_ann_date`、`report_type`、`update_flag`，已补空列；该表不能区分报告类型（合并/单季/调整），去重键退化为 `(ts_code, end_date)`，且无法判断版本新旧。若只需净利润/ROE/EPS 等指标，优先用 `income` + `balancesheet` 自算，`fina_indicator` 作为交叉校验。
4. **`update_flag` 同 `ann_date` 的双版本。** 约 23.8% 的 income 键存在 `update_flag` 0/1 两行；差异多在 `ebit/ebitda/assets_impair_loss` 等派生项，核心科目基本一致。若下游依赖 `ebit/ebitda`，需注意这里取的是最新版本。
5. **覆盖率矩阵口径。** 「标的数」含退市股与上市前历史，不等于当年可交易家数；按年做横截面因子时应先与 `stock_basic` 的 `list_date/delist_date` 求交。

## 七、后续如何用它修 PE 前视

数据已具备时点对齐条件，建议按下述口径重建本地推导 PE（`source=local:shares_x_close+fin_ttm`，2011–2017 段）：

1. **TTM 净利润**：`income.n_income_attr_p`（归母）为**累计值**，先按 `end_date` 做单季差分：
   - Q1 = 本期；Q2 = 半年报 − Q1；Q3 = 三季报 − 半年报；Q4 = 年报 − 三季报；
   - TTM(t) = 最近四个**已公告**单季之和。
2. **可见时点**：每一期的可见日取该期 `ann_date`（而非 `end_date + 固定滞后`），在 `ann_date` 之后的**第一个交易日**才允许进入计算；`f_ann_date` 与 `ann_date` 在本数据集中完全一致，可作为二次校验。
3. **股本**：用 `balancesheet.total_share`（同一 `ann_date` 对齐），或 `daily_basic` 的 `total_mv / close`；两者差异可作为交叉校验。
4. **PE(t)** = `close(t) × total_share(最近已公告)` / `TTM(最近四个已公告季度)`。
5. **回归验证**：把新口径结果与现有 2011–2017 `source=local:shares_x_close+fin_ttm` 段逐日比对，重点看**年报/半年报公告日前后 5 个交易日**的跳变——旧口径在报告期末即切换、新口径在公告日后切换，差异应集中在这几个窗口；若差异出现在窗口之外，说明旧口径还混入了其他前视来源，需继续排查。
6. **2007–2009 因子**：此前完全无法计算的盈利/成长/质量/应计类因子，现在可用 `income` / `balancesheet` / `cashflow` 重建；建议先与 2010 年之后同一因子实现做连续性检查（同一代码、相邻年度），确认口径一致后再向前延伸。
