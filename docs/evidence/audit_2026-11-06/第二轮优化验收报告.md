## 3. 性能门禁：诊断、修正与三环境实测

### 3.1 起点的真实缺陷

原 `_trace_factor()` 只看 `sys.gettrace()`。Python 3.14 下 coverage 7.17.0 使用 `sys.monitoring`（SysMonitor），不安装 trace 钩子，导致全量 `--cov` 回归中系数恒为 1.0，`b=16.87~18.38 µs/bar > 15` 被误判为代码退化【测试直接证据：`pytest_round2.log` / `pytest_round3.log`】。

探针实测【测试直接证据：`probe_trace.py` / `test_probe_trace_factor.py`】：

```text
PROBE sys.gettrace= None
PROBE coverage.current= active
PROBE coverage.repr= <Coverage ... core=SysMonitor ...>
PROBE trace_factor= 2.0  (修正后)
```

修正：`_trace_factor()` 改为先查 `sys.gettrace()`，再用 coverage 官方 API `coverage.Coverage.current()` 判断当前线程活跃实例，兼容 CTracer / PyTracer / SysMonitor 三种内核，未安装 coverage 时返回 1.0【代码直接证据】。

### 3.2 放大来源不是插桩本身

| 运行环境 | 每 bar `b` | 校准循环 | 比值 `b/calib` |
|---|---:|---:|---:|
| 独立脚本，无插桩 | 4.24 µs | 0.0236 µs/iter | 179.9 |
| 独立 pytest，`--cov` 单文件 | 4.67 µs | 0.0223 µs/iter | 209.7 |
| **全量 2004 用例 + `--cov`** | **17.35 µs** | **0.257 µs/iter** | **67.4** |

【测试直接证据：`probe_perf_numbers.py` / `test_probe_perf_numbers_under_cov.py` / `pytest_diag.log` 中 `DIAG` 行】

单独 `--cov` 只放大 1.1 倍，全量会话却放大 3.7 倍（校准循环放大 11.5 倍），说明**主因是长会话累积的进程状态（GC / 缓存 / 内存），coverage 只是叠加因素**【工程推论：基于上表三组实测】。因此不能简单地把全部阈值乘 4——那会让门禁在插桩模式下几乎失去拦截能力。

### 3.3 收紧方案

- 系数 **4.0 → 2.0**（收紧，不是放宽）：仅对 `MAX_US_PER_BAR`（15→30 µs/bar）与 `MAX_FIXED_OVERHEAD_S`（0.05→0.10 s）生效；
- `MAX_WALL_SECONDS`（3.0 s）与 `MAX_BAR_TO_CALIBRATION_RATIO`（300）**不乘系数**，保持严格；
- 两类绝对阈值与相对判据互补：全量会话靠 30 µs/bar 兜底，单独会话靠比值 300 兜底【代码直接证据：`tests/performance_test.py`】。

### 3.4 注入退化验证（关键验收）

| 环境 | 基线 | +150ms 固定开销 | +20 µs/bar |
|---|---|---|---|
| 无 `--cov`（系数 1.0） | PASS | **BLOCKED** `0.1531s > 0.05` | **BLOCKED** `25.10 µs/bar > 15.0` |
| 单独 `--cov`（系数 2.0） | PASS | **BLOCKED** `0.1542s > 0.1` | **BLOCKED** `比值 1070.6 > 300.0` |
| 全量 `--cov` 会话（系数 2.0） | PASS（17.35 < 30） | 预期 BLOCKED `0.1566s > 0.1` | 预期 BLOCKED `37.35 > 30` |

前两行是实测【测试直接证据：`verify_perf_gate.py` / `test_probe_injection_under_cov.py`】；第三行由全量会话实测基线 `per_bar=17.35 µs`、`fixed_s=0.0066s` 与注入量直接推算，未单独重跑 2004 用例做注入【工程推论】。

> 修系数前的对照：系数 4.0 时，`--cov` 下两类注入**均未被拦**（阈值 60 µs/bar / 0.2 s）【测试直接证据：同探针的首次运行输出】。这也是本轮坚持收紧而非"让测试通过就收工"的原因。
