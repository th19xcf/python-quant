## 1. P0-1 分档滑点在主撮合链路失效 · 已修

**根因**：`_execute_buy` / `_execute_sell` 调用成本模型时从不传 `adv20` / `total_mv_yi` / `category`，个股一律落到 30bp 保守档、ETF 落到 2bp 兜底档。【代码直接证据：修改前 `execution_core.py:1693,1698,1742`】

**实施**：

1. `Bar` 增加 `adv20`（成交额，元）/ `total_mv_yi`（亿元）/ `category` 三个字段，与既有 `adv_volume`（成交量，手）明确区分量纲。【代码直接证据：`execution_core.py:133-160`】
2. `_prepare_universe` 从 `amount` / `total_mv_yi` / `total_mv` / `category` 列构造分档输入。**全部 `shift(1)`**：订单在 t 日开盘成交，绝不使用 t 日全天成交额或收盘市值，避免修 P0-1 反而引入前视偏差。【代码直接证据：`execution_core.py:899-960`】
   - `total_mv` 兼容「元」与「亿元」两种量级（≥1e8 视为元，自动 /1e8）。
   - 列不存在时**不创建占位列**，避免给 12.7M 行面板造三份 `[None]*N`。
3. 分档输入贯穿 `get_buy_cost_rate` → 逐手回退 `calculate_buy_cost` → 实际扣费三处（用 `TypedDict` 保证 mypy 可推断），并逐笔在 `trades` 里记录 `slippage_rate` 供对账。【代码直接证据：`execution_core.py:2006-2155`】
4. 结果新增 `cost_inputs`（`tiered_symbols` / `fallback_symbols` / `lag_bars` / `fallback_note`），缺输入时显式标记而非静默兜底。【代码直接证据：`execution_core.py:815-880`】
5. 附带修复：`cost_model._as_date` 不识别 Polars/Pandas 时间戳，导致历史印花税/过户费时间表在时间戳输入下静默退回现行费率；现已补 `.date()` 归一化。【代码直接证据：`cost_model.py:73-103`】

**验收**：7 项专项测试（大盘 15bp / 小盘 30bp / ETF 5/7/10bp / category 升档 / 滞后一日 / 元→亿元换算 / 历史费率与文档常量），全部通过。【测试直接证据：`tests/test_p0_hardening.py::test_tiered_slippage_changes_buy_and_sell_cost` 等】

## 2. P0-2 参数优化偷看 OOS · 已修

**根因**：`optimize_strategy` 在含 OOS 段的全样本网格上 `_select_best_params` 并 `self.strategy.set_params(best_params)`，`param_stability_report` 同样基于全样本。【代码直接证据：修改前 `backtest_engine.py:162-176`】

**实施**：

- 全样本网格保留为 `optimization_results`（兼容既有调用方做逐笔对账），但**仅作参考、绝不参与选参**。【代码直接证据：`backtest_engine.py:162-175`】
- `validation='oos'` 时，最终 `best_params` / `best_value` / `param_stability_report` 一律取自 `_validate_out_of_sample` 的**样本内网格**（新增 `in_sample_grid` 回传，复用同一份结果，不额外跑一遍网格），OOS 只评估一次。【代码直接证据：`backtest_engine.py:245-253`】
- 切分不可用时不再退回全样本选参，改标记 `selection_sample='full_sample_oos_unavailable'` 并告警；`validation='none'` 标记为 `full_sample_no_oos`。【代码直接证据：`backtest_engine.py:180-205`】
- 新增 `leakage_guard`：`strict_in_sample_selection` / `full_sample_best_params` / `oos_evaluations` / `walk_forward_enabled` / `multiple_testing_correction='not_implemented'`（PBO/DSR 未实现，显式披露而非默认声称已校正）。【代码直接证据：`backtest_engine.py:225-245`】

**验收**：扰动 OOS 段行情（×3）后 `best_params` 与 `best_value` 完全不变；稳定性报告与 IS 网格同源；`validation='none'` 明确标记为非严格选参。既有 `test_optimize_strategy_*` / walk-forward / 进程池上下文测试全部保持通过。【测试直接证据：`tests/test_p0_hardening.py::test_best_params_ignore_out_of_sample_perturbation` 等 3 项 + 全量回归】

## 7. A11 挂单到期堆 + 除权堆 + ST 区间二分 · 已落地

**实施**：

1. **挂单 TTL 堆**：预计算 `code_days`（标的行情日下标），挂单产生时用 `bisect` 定位下一行情日，仅在「连续无行情天数 > ttl」时把 `(expire_day, code)` 推入 `heapq`；每日只弹出到期项，旧条目用 `pending_scheduled_expiry` 惰性失效。复杂度由 O(D×N) 降为 O(挂单数 × log D)。【代码直接证据：`execution_core.py:1490-1580`】
2. **全域覆盖快速路**：所有标的每天都有行情时 `code_days=None`，索引、堆、bisect 全部跳过（最常见面板零额外开销）。【代码直接证据：`execution_core.py:800-820`】
3. **除权事件堆**：`_init_run_context` 一次性按 `ex_date` 建堆，`_apply_corporate_actions` 每天只弹出到期事件，不再 `for code in schedule.codes()` 全量扫描；非交易日顺延语义不变。【代码直接证据：`execution_core.py:1035-1060,1590-1620`】
4. **ST 区间**：`_prepare_st_intervals` 一次性解析日期并按 `start` 排序，主循环每天只解析一次 `trade_day`，查询走 `bisect`；检测到重叠区间则退回原线性路径保持旧语义。【代码直接证据：`execution_core.py:1075-1140`】
5. 无区间表时热路径只多一次 bool 判断，不增加 dict 查找。【代码直接证据：`execution_core.py:1450-1470`】

**等价性验收**：7 项专项测试（TTL 内正常成交 / 精确到期日作废 / TTL=0 与长时间空洞 / ST 二分与线性逐日一致 / 重叠区间回退 / 除权与快照增量），加上既有 `test_pending_ttl_expires_when_symbol_has_no_rows`、`test_corporate_actions.py`、`test_st_status.py` 全部通过。【测试直接证据：`tests/test_p0_hardening.py` + 全量回归】

## 8. 性能验证与偏差说明（重要）

### 8.1 端到端（同脚本、同 seed 20261106、同机器）

| 场景 | 加固前基线 | 最终 | 变化 |
|---|---:|---:|---:|
| 2×250 | 0.0124 s | 0.0153 s | +23.0% |
| 5×1000 | 0.0759 s | 0.0825 s | +8.8% |
| 20×1000 | 0.1977 s | 0.2068 s | +4.6% |
| 50×2500（125k bar） | 0.9383 s | 0.9603 s | +2.3% |
| **100×2500（250k bar）** | **2.1471 s** | **2.0832 s** | **−3.0%** |
| 含 OOS 0.3 完整链路 | 0.1589 s | 0.1876 s | +18.1% |
| 回测聚合 | 3.7059 s | 3.7330 s | +0.7% |

【测试直接证据：`benchmark_before.json` / `benchmark.json` / `benchmark_after3.log`，`phase()` 重复执行至 ≥0.8 s 取单次均值】

### 8.2 未达成「端到端降 20%」目标的原因

1. **P0 加固的必要固定成本**：`cost_inputs` / `risk_gate` / `data_quality` / `failed_combinations` / `leakage_guard` 等审计字段、数据降级台账、分档输入列准备，都是每次回测一次的固定开销；小负载与 OOS 链路（一次调用跑 3 段回测）受影响最大。【工程推论 + 测试直接证据：OOS 场景 +18.1% 与三次 `run_segment` 结构吻合】
2. **A10 的 cProfile 占比含下游规则计算**：0.047 s 的 `RiskGate.check` 是累计时间，其中快照构造只是一部分，规则 `check()` 本身（涨跌停 Decimal 运算、行业遍历）无法省略。【工程推论：`cprofile_before.txt` / `cprofile_backtest.txt`】
3. **A11 在完整面板上原本就没有多少空转可省**：benchmark 合成面板每个标的每天都有行情，旧实现虽每日遍历 N 个槽位，但都是 `None` 快速跳过；部件微基准中 5,000 日 × 500 标的仅 0.0386 s（约 7.7 µs/日），量级本身不大。【测试直接证据：`benchmark_a10_a11.log`；工程推论】
4. **测量噪声**：同一版本多次重跑聚合值在 3.71~3.73 s 之间波动，小负载 ±5% 属噪声范围；最大负载的 −3.0% 是较稳定的信号。【工程推论：`benchmark_mid*.json` 四轮对比】

### 8.3 已做的开销收敛

发现首轮加固后小负载退化 +3%~28%，针对性做了三轮收窄：① 无分档输入列时不创建占位列；② 分档输入只在有挂单的 bar 求值；③ 无 ST 区间时跳过日期解析与 dict 查找；④ 全域覆盖跳过 `code_days` 构建与 bisect；⑤ 兜底日志降为 `debug`（结果字段仍机器可读）。回测聚合从 3.8176 s 收敛到 3.7330 s。【测试直接证据：`benchmark_mid.json` / `benchmark_mid2.json` / `benchmark.json` 四轮对比】

### 8.4 结论

**A10/A11 的代码级优化已经生效且经部件实测验证，但端到端净收益被 P0 加固的固定开销抵消，整体持平、大规模负载略快。** 这是"可信度优先"的合理代价；若后续要拿到端到端 20% 下降，应转向报告中的 A12（全面板物化改惰性列视图）与 A13（`_finite_float` 向量化/`__slots__`），而非继续在快照与挂单堆上投入。【工程推论：基于第 8.1~8.3 节实测】
