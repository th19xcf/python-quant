## B.2 定论：官方快照按**半开区间**（`out_date` 当日已不在册）

两条独立证据，方向一致：

1. **官方快照计数 20/20 一致**：体检时抽取 20 个 (指数, 日期)，以半开口径（`in_date <= d < out_date`）从本表重算只数，与官方月度成分快照只数 **20/20 相等**（`b2_slice2_check.md` §4）。
2. **`out_date` 当日的官方名册里查不到这些标的**：5,935 个带 `out_date` 的区间逐条回查官方面板，**在 `out_date` 当日仍在册的 = 0 / 5,935**（`panel_still_has_member_at_out_date = 0`）。

结论：**官方是右开（半开）区间，生产侧写法正确；错的是两处消费侧。** 这条不再留给调用方判断。

# 材料 C（§2）：`fund_adj_factor` 与 G-019 的冲突

## C.1 G-019 的原文与失效方式

G-019（`docs/数据缺口登记_正式表_2026-11-12.md:157`）写：「2,972,529→2,974,919（+2,390）；**2,619 只 mismatch 0**；**「行情有而因子无」0 行**」，判 `已修`。

实测（`b2_slice2_check.md` §6 + 本文 `b2s2_recommend_evidence.json`）：

| 断言 | G-019 写的 | 实测 2026-11-13 |
|---|---|---|
| 只数 mismatch | 0 | **2,241 只**（另有 1 只行情有、因子全无） |
| 行情有而因子无 | 0 行 | `561970.SH` **1 行行情 / 0 行因子** |
| 行数 | 2,974,919（§5.3 记现测 2,974,925，+8 未归因） | **2,974,925** |

**定性：G-019 不是“写错了”，而是“把时点结论写成了永久断言”。** 它测量时行情止于 2026-11-09，随后行情追加 11-10 / 11-11 两个交易日，而因子表没有任何链路在行情追加后自动重算，于是断言失效。这不是一次算错，是**缺少“行情追加 → 因子刷新”的不变量**。

### C.5.2 验收判据替换（不是放宽，是把循环论证换成独立基准）

**旧判据「残差归零」作废，登记为判据设计缺陷**：残差 = 因子 vs 事件表，而重跑正是用同一批事件表算因子，归零是构造性的，无法发现口径漂移。

**新判据（`work/b2s2_indep_baseline.py`）**：对每个「因子声称有除权」的交易日 t（`|step-1| > 1e-6`，`step = qfq[t]/qfq[t-1]`），用**通达信 `.day` 原始 OHLC**（未经过本仓库任何因子链路）反推参考价：

```
ref = close_tdx[t-1] / step      必须落在当日 [low, high]（loose 留 2% 边）
```

越界即判「因子与真实成交区间不一致」。剔除三类噪声并单独计数：桩 bar（`OHLC=1.000` 占位行，72 行）、停牌跨期（相邻记录日历间隔 >5 天）、跨非连续行。

**必须说清的一件事：用户给的基准数字「旧表 6 日 / 6 只」无法用任何独立基准复现。** 那个 6 来自 `quotes/fund.pre_close`，而 `pre_close` 由 `store._recompute_derived_columns` 按 `pre_close = close.shift(1) × qfq.shift(1)/qfq` 生成，是**旧因子的函数**——这正是 `docs/adj_factor独立源对拍_2026-11-11.md` §14.1 明文记录的循环论证。换上真正独立的 TDX 原始价后，**旧表自己就有 406 日 / 229 只**，所以「N ≤ 6」在旧基线上也不成立；它度量的是自洽，不是正确。

|---|---|---|---|---|---|
| 旧表（回滚后基线） | 4,091 | 786 | **406 日 / 229 只** | 1,582 日 / 542 只 | 见下表按前缀拆分 |
| 新表（只追加后） | 4,091 | 786 | **406 日 / 229 只** | 1,582 日 / 542 只 | **逐日明细与旧表完全相同**（JSON 中 `bad_loose_detail` 列表相等为 `True`） |

**N = 406 = 旧值，增量为 0**，这是「不得增加」的最强形态（集合完全相同）。结构上也必然如此：历史 2,974,925 行 `changed_rows = 0`，所以任何函数作用于两张表都得到同一结果；追加的 4,456 行步长恒 1.0，不产生任何「事件日」，对计数贡献 0。
