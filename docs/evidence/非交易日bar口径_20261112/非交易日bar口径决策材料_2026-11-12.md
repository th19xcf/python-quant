## 0. 结论先行

1. 非交易日 bar 的规模是**常数级**的：`stock_adj_factor` 220 行、`stock_turnover` 219 行，全部落在 **1991-01-05..1993-08-21**，涉及 16 只标的（全库 5,832 只）。
2. 它们对**现有回测结论的影响是 0**：最大日期 1993-08-21，与 2019 年之后的所有回测窗口零交集；且按交易日逐日对拍，删行与留行的因子覆盖差异 **0 / 0**。
3. 三条路对**六层行数与 `adv20` 阈值翻转都不产生任何变化**——因为两者都取自 `quotes` 的成交额，不取自因子表。真正需要重建层表的原因是**层表映射 bug**（周末 bar 被 `searchsorted(side='left')` 顶到下一交易日），那是独立的一件事，选 A / B / C 哪条都要单独处理。
4. 三条路里只有 **C（分层）** 能真正切断污染路径：`src/quant/factor_lib/data.py::load_panel` 以 **quotes 行**为面板轴、**不按交易日历过滤**，A 与 B 都不改变这一点（B 只动因子表，不动 quotes）。C 用「读取时按日历过滤」实现，不落第二个 parquet，DG-1 不受影响、数据零改动、回滚就是一个开关。
5. **推荐 C。**

- `quotes` 侧非交易日 bar 也是 **220** 条、16 只，与 `stock_adj_factor` 的 220 行**逐键完全一致**。
- `stock_turnover` 比 adj 少 1 行：`000004.SZ 1991-08-10`（该日有行情 bar 与因子行，但无换手行）。
- 星期分布已实测：**周六 181 行 / 周日 39 行**，无一条落在工作日的非节假日缺口上——这批 bar 就是 1990 年代深市早期「周末也记一条」的历史产物，不是采集错误、也不是缺节假日表造成。

### 1.2 因子值性质

- 220 行的 `qfq/hfq` **全部等于其下一行**（即周末 bar 没有引入新因子值）。
- 219 / 220 也等于其前一行；**唯一例外** `000002.SZ 1991-06-08`（周六）：该行 `qfq 0.008404 / hfq 1.422758`，前一行 `0.005907 / 1.0`。即一次除权事件被记录在周六，因子切换点比交易日历早一格。
- 结论：这些行**不携带独立信息**，但会作为「多一个观测点」进入任何按行处理的下游。

### 1.3 与历史快照的行差（回滚点是否可用）

`s_20261112_2046`（`_backup/factors_adj_turnover_20261112/`，mtime 2026-11-12 20:46:34，18,129,870 行）与现行（22:25:29，18,129,892 行）逐键对比：

| 方向 | 行数 | 分布 |
|---|---|---|
| 现行多出 | **+23** | `000001.SZ` 22 行（= G-107 的 22 个交易日缺口，1991-05-06..1996-02-09）+ `000002.SZ` 1 行 |
| 现行缺少 | **−1** | `000002.SZ 1992-04-18`（周六，非交易日行） |

因此该快照**不是现行表的准确改前镜像**（非交易日行 221 vs 220）。走 B 路线时不能直接拿它当回滚点，必须按 DG-11 在改前重新拍快照。

### 1.4 asof 中性验证（删行 vs 留行）

对 16 只标的的全部 quote 日期（126,862 个）逐日比对「因子表含 220 行」与「剔除后」两种口径经 `join_asof(strategy='backward')` 得到的因子值：

| 表 | 覆盖日期 | 差异行 | 差异所在日期 |
|---|---|---|---|
| `stock_adj_factor` | 126,862 | **2** | 全部落在非交易日 bar 上 |
| `stock_turnover` | 126,858 | **211** | 全部落在非交易日 bar 上 |
| **限定在交易日历内的日期** | — | **0 / 0** | — |

即：删行只影响「非交易日那几行自己」，对任何一个真实交易日的因子取值**零影响**。

### 1.5 `adv20` 阈值传播

口径：`adv20 = amount.rolling_mean(20, min_samples=1)`，`l4 = l3 & adv20 >= 2e7`。层表构建脚本 `tools/build_universe_layers.py` 存在旧映射 bug——`np.searchsorted(cal, day)` 默认 `side='left'` 把周末 bar 顶到下一交易日，随后 `unique(keep='first')` 取到错误那天的成交额。现行代码（mtime 2026-11-12 22:19:34，提交 `57900ba`）已修为「只保留日期精确落在日历上的 bar」。

全 16 只、8,424 个日历格逐日模拟，跨 `2e7` 阈值的**只有 `000009.SZ` 两处**：

| 日期 | 旧映射 adv20 | 新映射 adv20 | 跨阈值方向 | 层表当前值 | 重建后应为 |
|---|---|---|---|---|---|
| 1992-10-12 | 20,167,550 | 19,995,600 | `>=2e7` → `<2e7` | L4/L5 = **true** | false |
| 1993-01-18 | 19,882,550 | 20,257,450 | `<2e7` → `>=2e7` | L4/L5 = **false** | true |

其余 15 只 0 处；替代发生（周末 bar 顶替）的日历格共 **207** 个，但都不足以跨阈值。

**关键**：这 2 处翻转来自**层表映射修复**，与「因子表保留 / 清洗 / 分层」三条路**完全正交**——`adv20` 取自 `quotes.amount`，不取自因子表。

## 3. 为什么 3 条路的回测影响都是 0

三层证据，逐条可复算：

1. **日期不重叠**：非交易日行的最大日期 1993-08-21；现有回测面板 `PanelRequest` 默认区间 2021-01-01..2026-10-31；`pick_liquid_universe` 的窗口是「每个标的最末 250 个交易日」。1993 年之后无任何一条非交易日行。
2. **asof 在交易日上中性**：§1.4 已实测，删除 220/219 行后，126,862 个 quote 日期里只有 2 / 211 行差异，且全部落在非交易日 bar 自身；限定交易日历内为 0 / 0。
3. **层表不读因子表**：§1.6，六层行数与 `in_layer` 计数在 A/B/C 下完全相同。

因此「保留 / 清洗 / 分层」在本项目当前的回测范围内**不分胜负**；选择依据只能是「数据语义是否能自证」与「未来是否会踩坑」，不是「哪条更赚钱」。

## 4. 推荐与理由

**推荐 C（分层）**，实现方式钉死为「原始层不动 + 读取时按日历过滤」，不落第二个 parquet。

理由，按权重排序：

1. **只有 C 解决了真实污染路径**。`src/quant/factor_lib/data.py::load_panel` 以 `store.read_file('stock', code, with_factors=True)` 的**行情行**为面板轴，只按日期区间切片，**不按交易日历过滤**。周末 bar 会作为一行进入 1991-1993 面板，进而影响 `ret`（`close/close.shift(1)-1`）、`seq`、`next_tradable` 等按行计算的派生列。B 只删因子表行，`quotes` 里那 220 条 bar 仍在，面板照样把它们读进来——**B 花钱改了 2 个千万行文件，却没修到出问题的那条路径**。
2. **C 的代价比 B 低一个量级**。B 要重写 2 个 parquet（18.1M + 18.1M 行）、重算全库 SHA256、按 DG-11 新拍改前快照、按 DG-13 登记被取代路径；C 是 1 处读取过滤 + 1 次层表重建，**数据文件一个字节不动**，回滚就是把过滤条件去掉。
3. **A 不成立的原因是「语义不可自证」**：220 行 weekend bar 的因子值全部等于下一行，它们不携带信息却会改变行数守恒断言与按行号的任何对齐；保留它等于让「因子表行数」和「交易日数」永久对不上，后续每做一次缺口检测都要重新解释一遍。
4. **C 不违 DG-1**：过滤发生在读取时，磁盘上仍只有一个 `factors/stock_adj_factor.parquet`，不存在「同语义两套路径」。若改成落第二个 parquet 才会触发 DG-1，本方案明确不做。
5. **与「层表映射修复」解耦**：无论选哪条，`tools/build_universe_layers.py` 的精确日期映射都需要一次全量重建才能把那 2 处 `adv20` 翻转（`000009.SZ` 1992-10-12 / 1993-01-18）落到层表上——现行层表仍是旧映射值（已实测 L4/L5 = true / false，与修好后的 false / true 相反）。这件事建议与 C 一起做，但它是独立的缺陷修复，不构成选 C 的理由，也不该被 C 拖延。

**若最终选 B**，前置条件必须同时满足三条，缺一不可：① 改前按 DG-11 重新拍快照（不能复用 `_backup/factors_adj_turnover_20261112/`，它差 +23/−1 行）；② 在 `docs/数据权威路径清单.md` 登记被取代路径与 SHA256；③ 接受「下一次按 TDX 原始日期重建会把这 220 行重新长回来」，即需要同时改构建侧的口径，否则 B 是一次性的。

## 5. 回滚方式

| 路线 | 回滚动作 | 回滚证据 |
|---|---|---|
| A | 无需回滚 | — |
| B | `copy2` 改前快照覆盖回 `data/local_store/factors/stock_adj_factor.parquet` 与 `stock_turnover.parquet`，比对改前 SHA256 | 改前快照必须**在改前新拍**；现行 SHA256：adj `be29372d…`、turnover `7f90eda1…` |
| C | 移除 `load_panel` 里的日历过滤条件（1 处），层表按原口径重建一次 | 数据文件 SHA256 不变，回滚后可逐值比对到改前 |

C 的额外好处：因为不动数据，回滚不涉及 DG-11 备份链路，也不需要「改前快照」这一环。

### 9.5 `000002.SZ 1991-06-08` 单列判断

**不影响除权处理，但影响该标的 1991-06-10 的日收益。**

- 该行 `qfq 0.008404 / hfq 1.422758`，与其下一行 `1991-06-10` **完全相同**；`1991-06-08` 之前的那条 bar 为 `0.005907 / 1.0`。即除权切换点落在 `1991-06-08` 这一格，但**切换后的因子值在下一个交易日原样存在**。
- 因此删掉 `1991-06-08` 后，任何交易日的因子取值都不变（§1.4 的 asof 验证：交易日差异 0 / 0），除权处理不受影响。
- 受影响的是 `ret`：`1991-06-10` 的日收益由「7.50 / 7.95 − 1 = −5.66%」变成「7.50 / 前一交易日收盘 − 1」。这是 C 的预期效果，不构成需要改数据的理由。
- 建议：不单独为这只标的开例外；若 1991-1993 横截面研究要保留连续收益，按 §9.4 的建议 2 整体处理（扩日历或整窗关闭开关），不要逐只打补丁。
