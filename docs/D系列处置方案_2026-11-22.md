## 1. `industry_pit` 核实：确实是快照，不是 PIT 序列

**实测**（`data/local_store/meta/industry_pit/industry_snapshot_recent.parquet`）

| 项 | 实测 |
|---|---|
| 行数 / 列 | 11,162 / `ts_code, effective_date, end_date, industry_code, industry_name, level, source` |
| `effective_date` | 仅 5 个取值：2026-11-03 / 11-04 / 11-05 / 11-09 / 11-12 |
| `end_date` | 全表唯一值 2026-11-12 |

**产出方**：`src/data/quality/extended_builders.py::build_industry_pit`（[extended_builders.py](file:///e:/code/python/quant/src/data/quality/extended_builders.py#L283-L358)）。它读 `meta/industry/industry_history.parquet`（通达信口径），按变更点切段写 `industry_snapshot_recent.parquet` + `coverage.json`，并在 coverage 里已经写明 `authority=recent_snapshot_view（禁止 as-of 回溯）`、`complete=false`。

**消费方（实际读取扫描结论）**

- `src/` 内**没有任何业务代码读这张表**：唯一出现是上述写入器本身，以及 `src/data/industry.py` manifest 文本里的一句说明。属 write-only 产物。
- 契约 `industry_pit` 已改挂申万区间表 `industry_pit_sw.parquet`（[extended_contracts.py](file:///e:/code/python/quant/src/data/quality/extended_contracts.py#L79-L96)）。
- 行业中性化 / 行业敞口 / 选股剔除实际读的都是申万区间表：`attribution_local.py:191,418`、`portfolio_risk_local.py:117`、`industry_heat_local.py:45`、`industry_universe.py:40`、`strategy_lab/panels.py:51`、`strategy_lab/fields.py:166`。
- 另一条独立链路 `src/data/industry.py::load_snapshot` 读的是 `meta/industry/industry_history.parquet`（按 `as_of <= 目标日` 取最近一层），同样不读 `industry_snapshot_recent.parquet`。

**前视结论**：当前**无实际前视**（0 处生产读取）；风险是潜在的——任何按「PIT 区间表」语义 as-of 读它，2026-11-03 之前取不到、之后会把 11-12 的单一断面当成区间事实，等价于用未来快照回溯。文件名与 `dataset='industry_pit'` 的命名是主要误导源。

**修法（只出方案，本轮不实施）**

- 方案 A（推荐，改动 1 个写入器 + 2 处登记）：产物改名 `industry_snapshot_recent.parquet`，`dataset` 改为 `industry_snapshot_recent`，同步 `coverage.json`、manifest 与数据清单。
- 方案 B（可与 A 并行）：在读取侧加运行时断言——若 `end_date` 全空或唯一、且 `effective_date` 跨度 < 30 日，则 `raise` 拒绝当 PIT 使用。
- 方案 C（不建议近期做）：补 PIT 历史序列；通达信历史行业归属源端无完整历史，工期与源风险都最大。

**影响面**：生产读取 0 处 → A/B 属低风险改名 + 防呆；无需回改任何因子或回测代码。

## 2. manifest 滞后（D-01）：已按磁盘实测重算

**差异定位**（差异全部集中在 `quotes/manifest.json` 这份目录级总账，其余数据集不涉及）

| 数据集 | 差异 | 原因 |
|---|---|---|
| index | +31 文件 / +147,077 行 | 新增 801xxx 申万行业指数（全历史整段） |
| fund | +3 文件 / +4,491 行 | 新增份额/ETF 标的 |
| stock | +11,145 行（文件数不变 5,839） | 尾部追加 2 个交易日 |
| futures | 0 | 源端仍停在 2026-11-10 |

**修复后登记值**

- 顶层：`files 10,794 → 10,828`、`rows 25,963,228 → 26,125,941`、`bytes 900,203,853 → 907,156,232`、`date_range 1990-12-19 ~ 2026-11-18 → 1990-12-19 ~ 2026-11-20`。
- `universe.index` 4,656,286 → 4,803,363 行；`universe.stock` 18,163,246 → 18,174,391 行；`universe.fund` 2,990,520 → 2,995,011 行；`universe.futures` 153,176 不变。
- 顺带修掉原登记内部不自洽：`universe.stock.markets` 原为 358/2420/3055，与 `markets_detail` 361/2422/3056 不符（合计都是 5,839），现两者一致。

**方法**：一次性脚本逐文件读 parquet 元数据（行数取行组元数据，日期取 row-group min/max 统计；stock/fund/index 日期列名为 `date`，futures 为 `trade_date`，统一归一 ISO），重算 `universe.<kind>` 的 `files/rows/bytes/markets/markets_detail/date_min/date_max` 与顶层 `files/rows/bytes/date_range/counting`，同目录临时文件 + `os.replace` 原子替换。幂等：实测字段未变时不写盘、不动 `generated_at`，连跑两次第二次输出 `UNCHANGED`。人工字段（`semantics`/`produced_by`/`upstream`/`status`/`version`）原样保留。

**未动项与理由**

- `counting.codes_hash` 保留原值：原算法不可复现（`\n` / `,` / `|` 三种拼接与排序/原序共 5 种组合均不匹配），且全库无消费方校验该字段，属守卫字段。
- `upstream.latest_day_mtime=2026-11-11` 是上游源端 mtime，与本地落盘无关，保留。

**根因与建议**：`quotes/manifest.json` 在仓库内**无产者**（[daily_update.py](file:///e:/code/python/quant/tools/daily_update.py#L76-L78) 明确「人工维护、只读对账」），行情增量写盘不回写总账，所以每次增量后必然滞后。建议把本脚本的重算逻辑并入 `src/data/local_store/build.py` 收尾（或 daily_update 最后一步），本轮按范围约束未改代码。
