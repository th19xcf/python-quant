# 模型侧操作清单（2026-11-16）

## 1 定位与边界

本页回答「按模型现在该做什么」：把目标持仓台账的变动、市场趋势、行业热度与风格
轮动合成一张**模型侧**动作清单。它不是投资建议，也**不读用户实际持仓、不接账户、
不下单**；所有股数都是按给定资金折算的模型建议值，不代表任何真实委托。

## 2 输入

| 输入 | 用途 |
|---|---|
| `reports/target_holdings/目标持仓台账.csv` | 最新交易日的逐标的变动类型、目标权重、参考价与变动金额 |
| 市场趋势状态 | 结论卡的趋势档位，写入每行依据与失效条件 |
| 行业热度状态 | 按申万一级映射到标的，写入依据摘要 |
| 风格轮动状态 | 结论卡的风格方向，写入依据摘要 |
| 本地行情 | 交易日历与执行时点；不参与撮合 |

## 3 输出列含义

| 列 | 含义 |
|---|---|
| 序号 | 当前显示顺序（排序后重编） |
| 代码 / 名称 | 标的代码与简称 |
| 方向 | 买入 / 加仓 / 减持 / 清仓 / 持有 |
| 建议股数 | 按资金规模折算后的整手股数（100 股整数倍） |
| 参考价 | 台账参考价；清仓缺价时为 0 |
| 目标权重 | 台账目标权重（0~1） |
| 执行时点 | T+1 开盘（见 §5） |
| 触发/失效条件 | 该方向对应的执行与失效条件（见 §5） |
| 依据摘要 | 信号日、趋势、行业热度、风格四层来源 |

## 4 方向与股数

方向按台账「变动类型」一一映射：新建 → 买入、加仓 → 加仓、减仓 → 减持、
清仓 → 清仓、不变 → 持有。方向排序默认先卖后买、持有沉底。

股数 = `floor(缩放后变动金额 / (参考价 × 100)) × 100`：

- 买入 / 加仓用正向变动金额；
- 减持 / 清仓用变动金额绝对值；
- 持有或参考价缺失记 0。

缩放系数 = 参数资金 ÷ 台账「资金规模」，缺省资金 10 亿元；台账基准为 10 亿元时
系数为 1，股数与台账目标股数一致。

## 5 买卖时点与失效条件

时点口径完整复用回测执行内核，不新造规则、不在本页跑回测：

- **T 日收盘信号 → T+1 开盘执行**；执行日由交易日历给出，非人为指定；
- **涨停 / 跌停不可成交**：顺延至下一可成交日；
- **停牌阻断**：停牌期间不成交，复牌后按同一规则顺延；
- 成本按现有执行口径（佣金 / 印花税 / 滑点），本页不做撮合，只标注时点。

失效与触发条件按方向生成：

| 方向 | 触发与失效 |
|---|---|
| 买入 / 加仓 | 执行日开盘未涨停、未停牌即执行；趋势降档或下次再平衡时重核 |
| 减持 | 执行日开盘执行；趋势升档则暂停减持 |
| 清仓 | 执行日开盘执行；跌停或停牌则顺延至可成交日 |
| 持有 | 持有至下次再平衡执行日或信号翻档 |

下次再平衡执行日 = 下一个月末交易日的下一交易日，由交易日历推导。

## 6 缓存与刷新

沿用五个分析页的版本缓存：键 = `sha1(页面 + asof + dv + 输入指纹)`，输入指纹为
台账文件的 `mtime+size` 与资金规模，落盘 `logs/analysis_cache/action_list/`。
命中缓存直接渲染并在状态栏显示数据版本与原计算时间；「重新计算」强制绕过缓存、
重算后按原键原子覆盖。`dv` 缺失时不写缓存，按原逻辑现算。

## 7 实跑与验收

```
.venv\Scripts\python.exe -m src.quant.analysis.action_list_local --top 3
```

输出标的数、方向分布与前 3 行样例。当前台账只有一个交易日，故方向分布为全「买入」，
这是台账历史长度决定的事实，不是清单逻辑问题。
