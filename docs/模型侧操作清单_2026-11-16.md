# 模型侧操作清单（2026-11-16）

## 1 定位与边界

本页回答「按模型现在该做什么」：把目标持仓台账的变动、市场趋势、行业热度与风格
轮动合成一张**模型侧**动作清单。它不是投资建议，也**不读用户实际持仓、不接账户、
不下单**；所有股数都是按给定资金折算的模型建议值，不代表任何真实委托。

## 2 输入

| 输入 | 用途 |
|---|---|
| `reports/target_holdings/目标持仓台账.csv` | 最新交易日的逐标的变动类型、目标权重、参考价与变动金额 |
| 市场趋势状态 | 结论卡的趋势档位，写入每行依据与失效条件 |
| 行业热度状态 | 按申万一级映射到标的，写入依据摘要 |
| 风格轮动状态 | 结论卡的风格方向，写入依据摘要 |
| 本地行情 | 交易日历与执行时点；不参与撮合 |

## 3 输出列含义

| 列 | 含义 |
|---|---|
| 序号 | 当前显示顺序（排序后重编） |
| 代码 / 名称 | 标的代码与简称 |
| 方向 | 买入 / 加仓 / 减持 / 清仓 / 持有 |
| 建议股数 | 按资金规模折算后的整手股数（100 股整数倍） |
| 参考价 | 台账参考价；清仓缺价时为 0 |
| 目标权重 | 台账目标权重（0~1） |
| 执行时点 | 信号日的下一交易日开盘（见 §5）；已过窗口会标「已过执行窗口」 |
| 触发/失效条件 | 该方向对应的执行与失效条件（见 §5） |
| 依据摘要 | 信号日、趋势、行业热度、风格四层来源 |

## 4 方向与股数

方向按台账「变动类型」一一映射：新建 → 买入、加仓 → 加仓、减仓 → 减持、
清仓 → 清仓、不变 → 持有。方向排序默认先卖后买、持有沉底。

「变动类型」不由本页计算，来源是 `tools/target_holdings.py`：
`previous_targets()`（第 140-152 行）取严格早于本交易日的上一份清单，
`classify()`（第 155-162 行）按新旧目标权重比较得出 新建 / 加仓 / 减仓 / 清仓 / 不变；
上一日持有、本日目标权重为 0 的标的还会补一行「清仓」。台账只有首个交易日时
没有上一日可比，全部记为「新建」，因此方向分布全为「买入」——这是台账历史长度
决定的必然结果，不是方向判定未实现。

股数 = `floor(缩放后变动金额 / (参考价 × 100)) × 100`：

- 买入 / 加仓用正向变动金额；
- 减持 / 清仓用变动金额绝对值；
- 持有或参考价缺失记 0。

缩放系数 = 参数资金 ÷ 台账「资金规模」，缺省资金 10 亿元；台账基准为 10 亿元时
系数为 1，股数与台账目标股数一致。

## 5 买卖时点与失效条件

时点口径完整复用回测执行内核，不新造规则、不在本页跑回测：

- **信号日 T 收盘 → T+1 开盘执行**；信号日取台账「信号日」列（月末交易日），
  **不用台账「交易日」列推导**（后者只是清单生成/参考价快照日）；
- 执行日 = `next_trading_day(信号日)`，由交易日历给出，非人为指定；
- **涨停 / 跌停不可成交**：顺延至下一可成交日；
- **停牌阻断**：停牌期间不成交，复牌后按同一规则顺延；
- 成本按现有执行口径（佣金 / 印花税 / 滑点），本页不做撮合，只标注时点。

执行状态与 advice 侧 `resolve_exec_status` 同口径：

- `pending`：执行日尚未到（信号日 + 1 交易日不早于台账交易日）；
- `expired`：T+1 开盘已过。本页台账的信号日总是上一月末，因此执行窗口已过，
  买入/加仓/减持/清仓都**不得按「当前可买/可卖」使用**，只作为模型已执行动作与
  当前目标持仓的记录；页面结论卡与条件列都会标注「已过执行窗口」。

失效与触发条件按方向生成：

| 方向 | 触发与失效 |
|---|---|
| 买入 / 加仓 | 执行日开盘未涨停、未停牌即执行；趋势降档或下次再平衡时重核 |
| 减持 | 执行日开盘执行；趋势升档则暂停减持 |
| 清仓 | 执行日开盘执行；跌停或停牌则顺延至可成交日 |
| 持有 | 持有至下次再平衡执行日或信号翻档 |

执行窗口已过时，各行条件统一改为「已于 <执行日> 开盘执行，当前不追单；下一次
<信号日> 收盘信号 → <执行日> 开盘重核」，不把过期动作写成可追单。

下一次再平衡信号日 = 信号日所在月份之后那个月的月末交易日；执行日 = 其次一交易日。
以本台账为例：信号日 2026-10-30 → 执行日 2026-11-02（已过）；下一次信号日
2026-11-30 → 执行日 2026-12-01。

## 6 缓存与刷新

沿用五个分析页的版本缓存：键 = `sha1(页面 + asof + dv + 输入指纹)`，输入指纹为
台账文件的 `mtime+size` 与资金规模，落盘 `logs/analysis_cache/action_list/`。
命中缓存直接渲染并在状态栏显示数据版本与原计算时间；「重新计算」强制绕过缓存、
重算后按原键原子覆盖。`dv` 缺失时不写缓存，按原逻辑现算。


执行日按信号日推导为 2026-11-02（已过执行窗口），下一次再平衡 2026-11-30 信号 →
2026-12-01 开盘。方向分布为全「买入」，原因是台账只有一个交易日、没有前一日持仓
可比，判定规则本身已在 `tools/target_holdings.py` 实现并经单测覆盖。
