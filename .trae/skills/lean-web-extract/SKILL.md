# Lean Web Extract：省 token 的网页正文抓取

浏览器抓取的 token 大头不是页面本身，而是把正文拉进上下文。核心原则：**正文只走文件，模型只看路径、字节数与检索片段**。本技能源自 2026-11-06 ChatHub 全文抓取实测（54,239 字符正文若读入上下文约 30k–40k token）。

## 成本地图（实测教训）

- DOM 快照只返回可交互元素，正文拿不到；每次数千 token，反复尝试按倍数累加
- 截图约 1k–1.5k token/张；只用于确认版面与控件位置，禁止用来转录正文
- 正文全文进上下文：5 万字符约 30k–40k token，且留在上下文中后续每轮重复计费
- browser_id 每次会话轮换：任务开始只获取一次浏览器列表，禁止沿用旧 id

## 默认管线（文件优先四步）

1. **快照一次**：只为定位页面自带的「复制全部 / 导出 / 下载」按钮（如 ChatHub 的「复制所有消息」）
2. **备份剪贴板**：`powershell -NoProfile -ExecutionPolicy Bypass -File <本技能目录>/scripts/clip.ps1 -Action backup`
3. **点击复制 → 直落文件**：`scripts/clip.ps1 -Action save -OutFile reports/<主题>_<日期>.md`；产物只有字节数与字符数，正文不回显
4. **恢复剪贴板**：`scripts/clip.ps1 -Action restore`（自动删除备份文件）
- 本仓库归档位置固定为 `reports/<主题>_<日期>.md`；先例：`reports/chathub_quant_audit_full_2026-11-06.md`

## 事后读取（禁止重复吃全文）

- 关键词定位用 Grep，片段阅读用 Read 带 offset/limit
- 汇报 = computer:// 文件链接 + 脚本给出的 chars 数 + Grep 摘出的关键行
- 后续会话需要该内容时一律走文件检索，禁止「再读一遍全文」

## 升级阶梯

- **L0** 页面自带复制 / 导出 / 下载按钮 → 永远优先
- **L1** Ctrl+S 保存页面或打印为 PDF → 离线解析文件
- **L2** 截图：仅回答版面 / 视觉问题，拼最少张数
- **L3** 最后手段才让正文进上下文，且必须用 offset/limit 只取所需切片；文件路由存在时禁止整页进上下文

## 预算红线

- 任何上下文摄取之前，至少先完成一次文件优先尝试
- 同一目的的 DOM 快照最多 3 次，失败即换策略，禁止同方式重试
- 委托 browser 子代理：query 不超过 600 字符、一次只求一个可见结果、连续不超过 3 次、不粘贴代码块（JS 逻辑改用 Exec 工具执行）
- 完成判定 = 文件路径 + 字节 / 字符数 + 关键行摘录，不是全文复述
