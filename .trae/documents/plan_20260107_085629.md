# 核心数据源插件化迁移计划

## 迁移目标

将现有核心数据源处理器（TDX、Baostock、Macro、News）迁移到插件方式，同时保持向后兼容。

## 迁移原则

1. **渐进式迁移**：逐个数据源迁移，确保系统稳定性
2. **向后兼容**：迁移后不影响现有功能
3. **插件优先**：迁移后系统优先使用插件数据源
4. **代码复用**：保留现有处理器代码，通过插件封装调用

## 迁移步骤

### 1. 封装核心数据源为插件

#### TDX数据源插件

* 创建文件：`plugins/tdx_datasource.py`

* 类名：`TdxDataSourcePlugin`

* 继承：`DataSourcePlugin`

* 实现：封装 `src/data/tdx_handler.py` 功能

#### Baostock数据源插件

* 创建文件：`plugins/baostock_datasource.py`

* 类名：`BaostockDataSourcePlugin`

* 继承：`DataSourcePlugin`

* 实现：封装 `src/data/baostock_handler.py` 功能

#### Macro数据源插件

* 创建文件：`plugins/macro_datasource.py`

* 类名：`MacroDataSourcePlugin`

* 继承：`DataSourcePlugin`

* 实现：封装 `src/data/macro_handler.py` 功能

#### News数据源插件

* 创建文件：`plugins/news_datasource.py`

* 类名：`NewsDataSourcePlugin`

* 继承：`DataSourcePlugin`

* 实现：封装 `src/data/news_handler.py` 功能

### 2. 修改DataManager

* **修改初始化逻辑**：优先使用插件数据源， fallback到原有处理器

* **保留兼容性**：保留原有处理器初始化代码，确保插件加载失败时系统仍能运行

* **插件优先级**：插件数据源优先级高于原有处理器

### 3. 迁移后的使用流程

```python
# 迁移前
data_manager.tdx_handler.get_stock_data()

# 迁移后
data_manager.plugin_datasources['tdx'].get_stock_data()
```

## 4. 测试方案

* **单元测试**：每个插件单独测试

* **集成测试**：验证插件与DataManager集成

* **功能测试**：验证原有功能正常工作

* **兼容性测试**：确保向后兼容

* **性能测试**：插件方式性能对比

## 5. 部署方式

* 将插件文件放入plugins目录

* 系统自动加载并使用插件数据源

## 预期效果

1. **解耦核心代码**：降低系统耦合度
2. **增强扩展性**：轻松添加新数据源
3. **提高可维护性**：数据源代码独立管理
4. **支持热插拔**：无需重启即可加载新数据源

## 迁移文件清单

| 现有文件                          | 插件文件                            | 插件类名                     |
| ----------------------------- | ------------------------------- | ------------------------ |
| src/data/tdx\_handler.py      | plugins/tdx\_datasource.py      | TdxDataSourcePlugin      |
| src/data/baostock\_handler.py | plugins/baostock\_datasource.py | BaostockDataSourcePlugin |
| src/data/macro\_handler.py    | plugins/macro\_datasource.py    | MacroDataSourcePlugin    |
| src/data/news\_handler.py     | plugins/news\_datasource.py     | NewsDataSourcePlugin     |

## 风险评估

1. **兼容性风险**：低，保留原有处理器作为fallback
2. **性能影响**：低，插件调用开销极小
3. **测试覆盖**：需要全面测试各数据源功能

## 收益

1. **模块化设计**：数据源代码独立管理
2. **易于扩展**：新数据源只需开发插件
3. **降低耦合**：核心系统与数据源解耦
4. **便于维护**：每个数据源单独维护
5. **支持热更新**：未来可实现插件热加载
